# 课程用词约定

2026-10-01。读者的裁定：**课文改用平实的专业中文。**

起因是第 26 课「差距出在哪里」那张表，机制那一列写的是
「捕获把输家救了回来」与「聋掉的迟到起跑」。读者的话：这些词
「原本用来帮助理解但是实际上反而更让我混淆概念」。

这份文件是全课程（Wi-Fi 48 课 + UWB 25 课 + AMP 4 课）改写的唯一依据。
并行改写时它是裁判，不是建议。

## 1. 规则

**一、术语的位置只许放术语名。** 标题、小标题、`outcomes`、`terms[].plain`、
表格里命名机制的单元格、`limits` 的首句——这些位置上不许出现形象化说法，
要写机制本身的名字。

**二、正文用直述，不用形象化替代。** 原来靠一个画面代替机制描述的句子，
改成直接说那个机制。

**三、类比只允许出现在明确标为类比的说明句里。** 也就是说，可以写
「这相当于……」「可以类比为……」，但不许让类比**代替**机制出现，
更不许把它放进标题或术语位置。

**四、`捕获` 这个词保留，但它在这门课里指三件不同的事。**

**更正（2026-10-02，UWB 那一批实改时发现）。** 本条原文只写了 Wi-Fi 那一种，
并要求每课照抄那句解释。**照抄会在 UWB 课里写出一句关于本引擎的假话。**
三种都核过代码：

| 哪里 | 指什么 | 机理 | 代码 |
| --- | --- | --- | --- |
| **Wi-Fi** | 捕获效应（**capture effect**） | 守住**先锁定**的那个前导码，只在遇到强 5 dB 以上的前导码时才改去同步。**不对称，取决于谁先开始。** | `engine/channel.ts#canCapture`：`p >= l.rxDbm + CAPTURE_MARGIN_DB` |
| **UWB** | 捕获（**acquisition**） | 接收机第一次找到这个包、由此拿到时基的那一步。 | `@uwb-acquisition` 整课；`@uwb-uwbd` 的术语表 |
| **UWB** | 两路重叠时谁被解出来 | **纯按到达电平**，差 6 dB 以上强的那个被解出来。**对称，与先后完全无关。** | `uwb/channel.ts:631`：`strong = rx.rssiDbm >= other.rssiDbm ? rx : other` |

**所以：**

- 每一课用到这个词，都要**点明自己指哪一种**，用英文名区分
  （`capture effect` 或 `acquisition`）。`tests/course/wording.test.ts` 查这一条。
- **第三种不要写成 Wi-Fi 那句解释。** 它看着像捕获效应，而机理不同：
  没有「先锁定」这回事，谁先开始也不影响结果。UWB 课里写
  「到达电平明显高于」，不写「守住先锁定的那个前导码」。
- 顺带一个容易误会的细节：UWB 侧日志里的 `failReason: 'capture'` **只用于
  MMS 片段**，其余情形记为 `collision`。所以「UWB 里有 capture」这句话，
  在日志的层面上比在物理的层面上窄。

这是全课程术语撞车最厉害的一处：**一个读者在 Wi-Fi 学了第一种，
到 UWB 会连着碰上另外两种。** 三者都是本领域正确的中文，所以不是换词的问题，
是每次都要说清是哪一种。

## 2. 已知要换的词，以及换成什么

下表是扫描全课程得到的。遇到表里没有的同类说法，按 §1 的规则自行判断，
**并在报告里列出你自己决定的每一处**，以便补进这张表。

| 原来的说法 | 改成 | 为什么 |
| --- | --- | --- |
| 聋掉 / 聋 | 前导码未检出；收不到；接收机未能同步 | 生造的形象，不是机制名 |
| 输家 / 赢家 | 较弱的那一帧 / 较强的那一帧；竞争成功的站点 | 把"两帧的相对强弱"换成了胜负 |
| 把……救了回来 | 仍被正确接收；仍然解得出来 | 机制是"仍可解调"，不是"获救" |
| 门口（挡回、丢帧） | 入队失败；队列溢出丢弃 | `queueFull` 的机制名 |
| 钟上（把损失挪到钟上） | 生存期超时；因超时被丢弃 | `lifetime` 的机制名 |
| 老死在队列里 | 在队列中等到超过生存期而被丢弃 | 同上 |
| 耳朵（耳朵盖不住的部分） | 物理载波侦听（physical carrier sense） | 它指的是一个确切的机制 |
| 偷走（的米数） | 被缩短的距离；距离缩短量 | 攻击的效果是距离变小 |
| 偷（没有消息可偷） | 窃取 | 只是语体问题，换正式说法 |
| 发言权 | 信道占用；发送机会 | TXOP 给的是占用时间，不是"说话的权利" |
| 开口 / 说话 / 喊（指发送） | 发送；开始发送 | 同上 |
| 买单 / 账单 / 买卖（指代价） | 代价；开销；成本 | 直述即可 |
| 崩掉（指速率降档） | 降档；回退到更低的等级 | 机制名是速率回退 |
| 撑得住 / 撑不住 | 可支持 / 无法支持（的最高调制编码等级） | 读者选了平实一路 |
| 挤进（空当） | 利用……之间的空闲间隔 | 同上 |
| 白花（空口时间） | 浪费（空口时间） | 同上 |
| 烧掉（空口时间） | 占用；消耗 | 同上 |
| 低声细语 | 以较低的发射功率；发得较轻 | 同上 |
| 乖 / 笨 / 聪明 / 脾气 | 直接说那个行为 | 把机制拟人化了 |
| 失手 / 命中（指预测） | 预测错了 / 预测对了 | 同上 |
| 辩过去 | 解释掉 | 同上 |
| 干坐着 | 保持沉默；不发送 | 同上 |

### 2.1 Batch C 补充（2026-10-01，tier2 九课实改时发现）

这一批把范围从「比喻」扩到了**整个口语化语体**。原表只列了形象化的画面，
而真正让读者出戏的还有一大类：拿买卖、比赛、人情世故当机制说。

| 原来的说法 | 改成 |
| --- | --- |
| 排场／价钱／这笔钱／贵事／买下／买到／标价／定价／账（一笔账、结账）／一口价 | 固定开销；开销；代价；收益 |
| 抢跑／抢跑量 | 提前量；提前接入 |
| 参赛／分出胜负 | 参与竞争；决定谁先发送（`赢下一轮` 可留） |
| 玩……游戏 | 用同一套规则 |
| 兑现 | 每一轮都在起作用 |
| 认命 | 受……约束 |
| 喂（喂帧） | 从同一组待发的帧里取帧 |
| 一堆帧 | 一组待发的帧 |
| 活儿 | 帧；发送 |
| 独苗 | 唯一那台 |
| 家伙 | 设备 |
| 驮 | 承载 |
| 片子 | 视频数据 |
| 包装 | 固定开销 |
| 嫌疑人／无辜／怪罪 | 最显眼的那台；并不是原因；认定……是原因 |
| 惨／最惨 | 数字最差；等待最长 |
| 塌 | 降到 |
| 解脱 | 等待并没有因此改善 |
| 占便宜 | 多拿什么 |
| 摸到空口 | 取得发送机会 |
| 熬 | 等 |
| 起价 | 那段必等的静默 |
| 惩罚（指 EIFS） | 这段更长的等待 |
| 难看／难堪 | 明显偏长；更差 |
| 老老实实 | 如实 |
| 压着……说了话 | 的发送与它相撞 |
| 盖住 | 覆盖；长度正好容下 |
| 够得着 | 能够使用 |
| 挤过去 | 不会真的重叠 |
| 回执 | 确认帧（acknowledgement, ACK）／块确认 |
| 底噪 | 噪声地板 |

最后两行是裁定，不是扫描结果：

- **`回执`** 不是形象化说法，但它是 ACK 的非标准译法（像公文而不像协议）。
  换成 `确认帧`。这会让那个官方术语的首次带括号出现位置移动，**要跟着调整**，
  不是理由不换。
- **`底噪`** 是 `噪声地板` 的别名，而 `ZH_TERMS` 明确禁止它。
  它躲过了测试，原因见 §5 的更正。

### 2.2 Batch D 补充（2026-10-01，tier2 其余九课 + AMP 四课）

又一整批漏网的词族。原表每次只列了一个族里的一个词，而实改时整族都在：
列了 `买单／账单／买卖`，漏了 `买／卖／买到／买回来／省钱／更贵／值钱／票价／这笔钱`；
列了 `白花`，漏了 `白送／白白付出／白费`；列了 `嘴／说话`，漏了
`闭嘴／出声／说了算`；列了 `乖`，漏了 `乖乖／友善／吃亏／愿望`。

| 原来的说法 | 改成 |
| --- | --- |
| 钟／一只钟（指 TXOP 限值或时隙边界） | 期限；剩余时间；定时基准 |
| 帽子／盖子 | 能力上限 |
| 一团糊 | 解不出这一帧 |
| 撞车 | 碰撞 |
| 起跑／同时起跑 | 开始发送 |
| 大声／嗓门 | 用全屋都解得开的速率 |
| 醒来／醒了（指 NAV 到期） | 预约到期；恢复竞争 |
| 裸奔 | 完全没有保护 |
| 可乘之机 | 可能撞进来的时间 |
| 打死／死掉／报废 | 失败 |
| 赌注／运气 | 风险 |
| 指挥 | 调度 |
| 定死 | 规定 |
| 压根 | 根本（错别字） |
| 围墙／陷阱／清场／挤成一团／挖出来／掐不准 | 按上下文直述 |
| 节拍 | 比特定时 |

**裁定：以下几个留下。** 它们不是生造的形象，是技术读者本来就会用的中文：

- **`听不见／听得见`** —— 全课程通用，而且「两台听不见彼此的站点」正是隐藏节点的
  标准讲法。只有 `聋` 被换掉。
- **`死亡螺旋`** —— 它是 `rate-fallback` 要**推翻**的那个假说的既有名字。
  换掉它，那一课就没有可反驳的对象了。
- **`倒挂`、`预告／公告`、`罩住`** —— 直述，且 `罩住` 是一张图里被钉住的标签。
- **代码注释里的四处历史引文**（`txop.ts`、`rate.ts`、`rate-cost.ts`、
  `rate-fallback.ts`）—— 它们是英文设计注释，读者看不到，而 `txod.ts:15` 那一处
  还把 2024 年语料的原标题与新措辞并列着，是有用的记录。

### 2.3 一条比用词更要紧的发现

Batch D 报告：**被标出来的词有时在替一个真正的错误打掩护。**

`streams.ts` 有一个小标题写作「两端都有发言权」。换掉 `发言权` 的时候才看清，
这句话**不只是比喻，它是错的**——发言权（信道占用）属于 TXOP，而那一节讲的是
两端各有几根天线。一个形象化的说法把一句事实错误藏了三个月。

`txop.ts` 也有两层：被点名的是 `发言权`，而 `钟` 才是承重的那一个——
它在五处命名 TXOP 限值，包括一个图标题和一个表格行。

**所以这次清扫要当成一次复核来做，不是一次替换。** 每改一处形象化说法，
都要问一句它原来在替什么说话，以及那件事是不是真的。

## 3. 一律不许改的东西

- **任何数值。** 课文里的每个数都被测试钉在一次真实运行上。
- **`scenario()`、`variants`，以及 `jumps` 的跳转目标**与任何场景代码。
  两份 fixture 必须零 diff，**绝不运行 `UPDATE_HASHES=1`**。
  **更正（Batch D 发现）：`jumps[].label` 不在保护范围内。** 原文把整个 `jumps`
  划进禁区，但标签是**读者在按钮上看得见的文字**，而且只改标签对哈希是中性的
  （`amp-intro.ts` 的「两个标签挤进同一时隙」就卡在这里）。受保护的是跳转的
  目标与时刻，不是标签的措辞——而且那条强制测试也要走 `jumps[].label`。
- **`sources`** 的出处内容。措辞可以更平实，**引用的条号、文稿号、模型取值标记
  一个都不许动**。
- **`limits` 的主张本身。** 措辞可以改，**每条断言的内容不许变**——那些主张是
  逐条对着引擎核过的，改掉主张就等于重新撒谎。
- **已有的官方术语**与它们的英文名（`src/course/readability.ts` 的 `ZH_TERMS`
  管这件事：官方术语首次出现要带标准英文名与缩写）。

## 4. 三处会被测试抓到的连带影响

1. **很多测试钉着课文的原话。** 改了措辞就要改那些断言。
   **改断言时不许弱化它**：原来断言一个事实，改完还要断言同一个事实。
2. **`lessonMinutes` 是按汉字数算的**（`readability.ts` 的 `mainPathChars`），
   课程的唯一长度控制是 30 分钟上限。平实的写法通常更长，
   **改完要确认没有哪一课越过上限**。

   **量它的时候要 import 常数，不要重打。** 三个常数是
   `CHARS_PER_MINUTE = 220`、`OBSERVE_MINUTES = 2`、`TRY_MINUTES = 4`
   （`curriculum.ts`）。控制者凭记忆打成 150 / 0.5 / 1.5，于是把
   `uwb-reply-time` 实际只剩 **4 个汉字** 的余量读成了 484 个。

   四门课现在带着 CAUTION 头注，因为它们贴着跳档线：
   `rate`（1 个汉字跳 20→25）、`uwb-reply-time`（4 个，25→30）、
   `uwb-m2m`（5 个）、`ofdma-ul`（9 个）。没有任何一门越过 30 分钟上限。
3. **`ZH_TERMS` 的首次出现规则**：如果改写让某个官方术语更早出现，
   那一课就要在新的首次出现处带上英文名。跑全量测试，不要靠读。

## 5. 新增的强制测试

`tests/course/wording.test.ts`：§2 与 §2.1 左列的每个词，在任何一课的课文里
都不许出现（`捕获` 除外，它在白名单里）。

**更正（Batch C 发现）：`lessonStrings` 不走 `limits`。** 按原来的写法，
这条测试police不到 `limits` 的正文——而 `底噪` 正是藏在 `mlo.ts` 的 `limits` 里
躲过检查的。所以这条测试要走**课文加 `limits` 的全部文本**，
`limits` 是课文里最该用准确词的地方之一。

这条测试的意义是**让它不能回来**，而不是只修一次。仓库里已经有同形的先例：
`limits` 的测试断言课文里不出现「本仿真器有简化」。

**例外要写在测试里并注明理由**，不许靠注释赦免。

### 5.1 写这条测试时的陷阱（Batch D 实测）

**禁用词做子串匹配会误伤。** `钟上` 出现在 `时钟上` 里面——`amp-slots` 就有一处，
而 Batch D 为了绕开它改写了一个本来没问题的句子。同一个坑也咬过另一条测试：
`允许发送`（CTS 的中文名）是 `被允许发送` 的子串。

所以这条测试要按词边界判，或者给每个禁用词配一份合法的例外串，
**并且在测试里写明每一条例外为什么合法**。写成裸的 `toContain` 会让课程
为了迁就测试而放弃正确的词。

## 6. 两处由实改纠正的事实错误

**一、我给批次的简报把捕获的方向写反了。** 简报里写的是「两帧重叠中**较弱**的那一帧
仍被解出」。错的。`engine/channel.ts` 的 `canCapture` 要求
`p >= l.rxDbm + CAPTURE_MARGIN_DB`——后到的信号必须**强 5 dB 以上**才会换锁，
所以存活的是**较强**那一帧。

而这让读者的抱怨有了更硬的根据：`输家` 在最自然的读法下就是「较弱的那一帧」，
**而那是错的**；它真正指的是「起跑晚的那一帧」。一个本该帮理解的词，
在最自然的读法下编码了一个错误事实——这正是读者说的「反而更让我混淆概念」。

四个批次都没有把这个错写进课文，因为它们去读了引擎和测试，没有信简报。
**提到捕获的五个文件全用 `较强／更强`。**

**二、`queues` 的一条 `limits` 自相矛盾。** 它写着真实设备常丢「**队尾**最老的一批」，
而同一课通篇说的是新帧排到队尾、从队首取帧、重传放回队首——**最老的在队首**。
drop-oldest 丢的是队首那一端。Batch B 发现了但按 §3 不动 `limits` 的主张，
正确地上报给控制者改。**这是 §2.3「比喻替错误打掩护」的第三例。**

## 7. 这份契约还没覆盖的地方（2026-10-02）

**§5 那条测试只走课程对象。** 而读者看得见的文字远不止课文：

| 哪里 | 谁在管 |
| --- | --- |
| 79 门课的课文、`limits`、标题、跳转标签 | `tests/course/wording.test.ts` |
| `src/ui/Guide.tsx`（指南） | **没人管** |
| `src/ui/glossary.ts`（词汇表） | **没人管** |
| `src/editor/EditorGuide.tsx`（编辑器指南） | **没人管** |
| `src/ui/i18n.ts`（界面文字、提示、帧类型名） | **没人管** |
| `src/model/scenario.ts` 的校验消息 | **没人管** |
| `src/player/player.ts` 的四条错误横幅 | 用词**没人管**；编码由 §9 那条全仓判据管 |

这不是假设出来的问题：写 RCM 有效轮次那一刀时，**控制者自己在编辑器指南里写下了
两处 `开口`／`说话`**（都是被禁的「发送」那个意思），而 Task 2 的一条拒绝消息里也有一处。
三处都是在手工扫描时发现的，没有任何测试会报。

**而扩这条测试要先解决一个子串问题，比课文里的更棘手：** `开口` 在
`EditorGuide.tsx` 里出现七次，其中**五次是「门窗开口」**——墙上的洞，和「发送」毫无关系。
所以把测试扩到非课文文本，必须先给每个禁用词配好合法例外，
否则它会把正确的词也判成错的。

暂不扩，记在这里。扩的时候从 `开口 → allow: ['门窗开口', '开出 … 开口']` 起步。

## 8. 一个名字已经被别的东西占住了（2026-10-02，§10.36 实改时发现）

`readability.test.ts` 的 `ZH_TERMS` 把 **确认帧** 登记成 ACK 的中文名，而这条规则是
**位置性**的：首次出现处 40 字以内要带上英文名。于是 UWB 侧 §10.36 的那一帧
——界面在 `i18n.ts` 里叫它「收妥确认帧」——写进受检课文就会触发规则，
要求在一帧**不是 ACK** 的东西后面补「（ACK）」。

**这不是测试错了，是两个机制共用了一个中文名。** 处理办法是不去借那个名字：
课文写「收妥确认」或直接写 **MMRCM**（multiple message receipt confirmation message），
两者都不含 `确认帧` 这三个连着的字。

下一个写 UWB 课的人会再撞一次，所以记在这里：**检查一个中文名有没有被 `ZH_TERMS`
登记给别的东西，比想一个好名字更靠前。**

## 9. 写完含中文的文件，提交后要从 git 里读回来（2026-10-10，W14）

**规矩一句话：任何一刀只要写过含中文的文件，提交之后要把那些文件从 git 里读回来
（`git show <sha>:<path>`，或 `git diff` 看字符而不是看行数），确认中文完好。**
这条规矩在 2026-10-10 之前只活在控制者给每一刀的 brief 里——那是最容易丢的地方，
换一个控制者、换一次会话它就不存在了。所以写进这里。

### 事故（`0732f01` 种下，`055e734` 修掉）

`0732f01` 之后，`src/player/player.ts` **整个文件**被按 cp1252 读了一遍再按 UTF-8 写回：
文件里原有的每一个非 ASCII 字符都变成了它自己那几个字节的 Latin-1 读法。
**17 处**，其中**四处是读者真会看到的字符串**——worker 起不来时的错误横幅。
「仿真进程没有启动，时间无法推进。请刷新页面重试」那一条，发出去的是十一行乱码。
剩下的落在注释里：`7½`、`1 000×`、`0…3 s`、「尚未出现」、「第一个触发帧」、`▶ 载入并观察`。

**当时没有任何东西在看。** 没有判据测一条只在 worker 启动失败时才出现的横幅的文本，
而注释里的损坏对仓库里其它每一条判据都是不可见的。
发现它靠的是人去读那个文件——而不是任何一次全量测试。

### 现在有一条全仓判据，位置要记住

`tests/smoke.test.ts` › `source encoding` ›
**`has no double-encoded UTF-8 anywhere under src/ or tests/`**。它不需要例外名单，因为乱码有定义——一段非 ASCII 字符，
它自己的 cp1252 字节是另一些非 ASCII 字符的合法 UTF-8；`µs`、`−3 dB`、`▶`、「载入」
都不符合。那条判据的 docblock 反过来指着本节。

**但它不能替代上面那条规矩，有三个理由：**

1. **它只在跑全量（或至少跑到 `tests/smoke.test.ts`）时才发现。** 一刀只跑自己那几个
   文件的测试就看不到它——而只跑自己那几个文件，恰恰是改一个 UI 字符串时最自然的做法。
2. **它只走 `src/` 与 `tests/`。** `docs/`（包括这份文件）、`README.md`、
   `.superpowers/` 下的规格与报告，一个字都不在它的覆盖里——而这些文件几乎全是中文。
3. **它只认双重编码这一种损坏。** 截断、BOM、把中文整段写成 `?`、
   把 CRLF 文件整体换成 LF 再把中文写坏——这些它都不认。

所以：**判据是网，读回来是手检；两样都要。**

### 怎么读回来

提交之后，对这一刀碰过的每一个含中文的文件：

```
git show <sha>:<path> | head -40      # 看中文是不是中文
git diff <sha>^ <sha> -- <path>       # 看改动是不是只有你打算改的那几行
```

**关键是看字符，不是看行数。** 一次整文件重编码的 diff 行数可以和一次正常编辑一模一样
（那次事故的 diff 是 26 行），所以 `--stat` 不解决问题；要看出来必须让那些中文显示出来。
写文件的工具也值得怀疑一次：那次事故是「整文件读进来再整文件写回去」这个动作干的，
而不是某一处编辑干的——**凡是整文件重写，就要把这一步做足。**

### 为什么写在这份文件里，而不是 `docs/inert-config-contract.md`

`inert-config-contract.md` 管的是**另一族失效**：一个 schema 收得下、打开它之后记录流
一个字节都不变的配置，口径是「拒绝，还是钉住现状」。
一条乱码的横幅既不合法、也不空转——它是读者当场看得见的垃圾，没有东西可拒、也没有现状可钉，
那条六步判据的第一步（「有没有一门课正在演示这个配置」）在这里根本问不出来。

本文件管的是**读者看得见的中文**：§1–§6 管课文怎么写，§7 已经在数
「读者看得见的中文里，哪些没人管」，并点名了 `i18n.ts`、`Guide.tsx`、校验消息。
播放器那四条横幅就是同一族里的一员，而「写完中文要读回来」是这一族唯一的通用防线。
所以它是本文件的第九节。

### 10.5 判据：什么算这一类缺陷，什么不算

**算**，四个条件同时成立：

1. 这个词在 `ZH_TERMS_EXCLUDED` 里（所以术语规则对它是关着的）；**并且**
2. 它出现在**主路径**的某一处（`why`／`outcomes`／`terms`／`body`／`picture`／`numbers`／
   `observe`／`tryThis`／`quiz`；`deeper`、`sources`、`limits` 不算——那三处不是读者的必经之路）；**并且**
3. 这一课在**这处之前**没有解释过它：没有命名框（`就是……`／`叫作……`／`所谓……`／
   `……指的是`／`词：`／`（词）`／`词（English`），也没有把一个更长的同族复合词写全；**并且**
4. 它的 `needs` 闭包里也没有哪一课解释过它，**而闭包里的解释必须按词形核**。

**不算：**

- **同一课内的回指。** `@decode-thresholds` 自己定义了 `速率余量`，后文写 `含余量` 指的就是它。
  不豁免这一类，凡是自己定义了更长复合词的课都会变成假阳。
- **词表不计出场顺序。** `terms` 是读者随时可查的表，
  2026-09-23 修正案的原文也只要求「出现在本课或更早一课的 `terms` 里」，没有顺序要求。
- **句子自己兜住了。** `@uwb-ancillary` 的 `why` 写「一帧的载荷（payload）有上限」——
  是什么的上限，这句话自己说了。这是判据的**假阳**，不是债。
- **普通中文和仿真器的计数单位同形。** 这是最大的一类假阳，见下。
- **`deeper` 与 `sources` 里的裸用。** 那两处是深度与出处，读者不走。

**判据不能只看词形，这是量出来的，不是担心出来的：**

- **53 对里有 31 对落在 `尝试` 与 `上限` 两个词上**（前段 14 对里有 9 对），
  而这两个词绝大多数用法是**普通中文**——「第一次尝试」里的尝试是动词，
  「一帧的载荷有上限」里的上限是普通名词。
  它们进豁免表的理由恰恰是**仿真器另有**一个同名的计数单位与同名的上界。
- 上一刀（2026-10-11 的读者审计，`.superpowers/sdd/learner-audit-report.md` §7）
  **逐条读过修之前的 20 条前段命中：9 条真、11 条假，约 45 %**。
  这是一次人读的记录，钉在那一刀的语料上（基线 `95b0898` 加 `ed4c6dc`／`f64b0ac`），
  **它不会漂，因为它是关于那一次快照的事实**；今天可复算的同向代用量是上面那两个数（31／53、9／14），
  它们有断言看着。
- **所以这类缺陷只能当分诊清单用，不能当绿灯。** 一处要算成债，必须有人读过那一句，
  确认「读者在这里会停下来问是什么」。

**台账自己的边界，也量过：它只走那 25 个词。** 2026-09-23 修正案点名的四个量里，
`门限` 既不在 `ZH_TERMS`（那里只有 `RTS 门限` 与 `能量检测门限` 两条复合行），
也不在豁免表里——**22 门课在主路径上裸用它，而本节的台账看不见这 22 门课**。
这不是漏记，是台账的口径；要不要把它收进来，是 §10.6 重新考虑条件的一部分。

### 10.6 这笔债什么时候该重新考虑建规则 —— **立案，建议不批**

**这不是一条新立的案。** 它就是 2026-10-11 读者审计 §8 那一条
（仓库里「立案并建议不批」的第九条，先例十条：`docs/wifi-course-backlog.md` 的
W2／W4／W6／W7／W8b／W10 六条、`docs/superpowers/specs/2026-10-10-tier4-design.md` 的
W14／W15 两条、这一条，以及 `docs/superpowers/specs/2026-10-11-no-room-design.md` §6.3），
**第一次写进 `docs/`**——在此之前它只活在一份 `.superpowers/` 下的报告里。

**要建什么：** 一条全仓规则，对 `ZH_TERMS_EXCLUDED` 的 25 个词执行 §10.5 的判据，
逐课报出「这门课用了这个词，而没有谁解释过它」。

**为什么建议不批，三条理由，每条都独立成立：**

1. **它正是 2026-09-25 裁定点名要删的那一种。** 失败信息讲的是**一句话怎么写**
   （「这里要点名这个量」），不是仿真器做了什么。要让它绿还得给 `尝试`、`上限` 开豁免——
   **一条带着两条豁免、顶着 53 对存量债、失败信息讲行文的规则**，
   就是「绿着却证明不了它名字说的那件事」。
2. **它今天的前段精度约 45 %**（§10.5），而噪声集中在两个词上。
   按一条量出 45 % 精度的规则去改课文，是拿噪声当工单。
3. **已经有一个产出更高的办法在用，而它不是仪器。** 这笔债的四处已还，
   起因是**真实读者问的五个问题里有四个正中真缺陷**。本节的台账是给那个办法配的账本：
   第 54 处报上来的时候，有地方落、有判据判、有先例照。

**什么时候该重新考虑，三个可检验的条件，任一成立即重开：**

1. **判据的前段精度量到 80 % 以上**——做法是先把 `尝试` 与 `上限` 从判据的词表里拿掉
   （它们今天占 53 对里的 31 对），对剩下的 22 对逐条读过并记下真假。
   **这个条件可以今天就验，不需要等任何别的东西。**
2. **这一族的缺陷再被真实读者报上来一次。** 已经有一次：2026-10-11，读者在
   `@selectivity` 上的原话是「这里余量是啥」。第二次意味着「靠人读」这个办法的漏检率
   不再可接受，而那时该批的**不是**本节这条全仓措辞规则，而是把判据覆盖的词收窄到
   「读者问过的那几个」，并照 §10.4 那四对的形状逐课钉住。
3. **台账的口径被判为太窄**——也就是决定把 `门限` 这类「两张表都不在」的词收进来（§10.5 末）。
   那是一个口径决定，要人批；批之前本节的 53 对不许改口径，否则这一节自己就成了漂移源。

### 10.7 为什么写在这份文件里，以及那条断言落在哪

**为什么是本文件的第十节，而不是新开一份：**

1. **§3 最后一条就是被关掉的那条要求。** 它把「官方术语首次出现要带标准英文名」
   交给 `ZH_TERMS` 管，而这笔债是那次委托留下的洞——**记录该紧挨着产生它的那次委托**。
2. **§7 已经是「读者看得见的中文里，谁在管／没人管」的账本。** 本节是那张账本的一行，
   连细目一起写开：`ZH_TERMS_EXCLUDED` 的 25 个词 → **没人管**。
3. **§9 立下的形状是「一条没有判据的规矩住在契约里，而判据在测试里指回这一节」。**
   本节照同一个形状，连互指的断言一起（见下）。
4. `docs/inert-config-contract.md` 管的是另一族：schema 收得下、打开之后记录流不变的配置，
   口径是「拒绝还是钉住现状」。这里没有配置可拒，也没有记录流可比，
   它那条六步判据的第一步在这里问不出来。

**那条断言：`tests/course/glossing-debt.test.ts`**，四条：

- `§10 of the wording contract and this file point at each other`
- `§10.2 lists exactly the 25 words ZH_TERMS_EXCLUDED holds, with each word's own debt`

- `§10.7 states the figures the criterion measures`

**为什么它落在 Keep 一栏，而不是被 2026-09-25 的裁定删掉：**

1. **它的失败信息讲的是一个数或一个名单对不上，不是一句话该怎么写。**
   修法永远是**改这一节**（重新量，更新台账），而不是改课文。
   它对课文的任何一次改动都不设方向：债多了、债少了都合法，**只要台账跟着走**。

4. **它不会空转**：台账里有 53 行非空的数据，判据要是哪天量不到东西（正则失配、
