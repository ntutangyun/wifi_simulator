# 频谱感知延后 SSBD 实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建 P802.15.4ab 草案 §10.45 的频谱感知延后，把本引擎「一次忙、整块封口」
的后果换成草案要的「每个发射时隙、每端各自一次信道接入」，
并把「给延迟定上界就是决定不再等」这件事量出来。

**Architecture:** SSBD 是纯时序加一次带种子的随机抽取，引擎已有逐设备 RNG、
逐设备 CCA（`UwbChannel#lbtBusy`）与按时隙推进的时钟，所以算法本身托得住。
托不住的是 MAC PIB、向上层报的那个失败、以及持久化位
（它的定义是「本次是不是重传」，而本引擎的窄带控制面没有重传，这一位取不到真）。

**Spec:** `docs/superpowers/specs/2026-10-03-ssbd-design.md`

### Task 4: 规格 §5 那五条，每条一个测试

**Files:** Test `tests/uwb/ssbd-inert.test.ts`（新）；按需 Modify `src/model/scenario.ts`

**这一整个任务只做一件事：证明每一个被允许的组合都不是空的。**
本分支已经发出过三个「被允许却可证明无效果」的配置，而这一刀的规格提前把五条点了名：

1. **场景里没有 6 GHz Wi-Fi 链路** —— 没有中介，CCA 永远空闲，SSBD 一次也不跑。
   schema 拒不掉（场景本来就可以没有 Wi-Fi）。**断言记录逐字节相同且 `UWB_SSBD` 为空**，
   把它钉成**明示的**断言，而不是让它看起来生效了。
2. **`maxBackoffs: 0` + `txOnEnd: true`** —— 不做任何 CCA 却名义上满足 §10.39.8.3。
   这是草案自己的洞（评审 I-169 要求禁止，CRG Rejected）。
   **允许，并钉住它与 `nbLbt: 'off'` 逐字节相等。**
3. **`txOnEnd: false` + 持续忙的信道** —— 可观测结果与今天的整块封口**看起来一样**。
   **测试必须把两者分开**：封口是一次检测、一条记录、随后整块静音；
   FailOnEnd 是每个时隙 `maxBackoffs + 1` 次 CCA、每个时隙一条记录，
   且锚点的 `UWB_TIMEOUT` 落点不同。**这条测试分不开，这个开关就是空的，不许发。**
4. **`oneToMany: true` 且响应方够多** —— 余量是负数，一次退避也塞不进。
   断言有记录、收尾是 `clamped`、实际退避 ns **恒为 0**：有感知、无退避。
5. **`ssbd` + `schedule: 'contention'`** —— 两者作用在不同的电台与不同的相位上。
   断言一次运行里 `UWB_CONTEND` 与 `UWB_SSBD` 都出现，
   且竞争抽签结果与 `ssbd` 关着时相同。

- [ ] 五步同上 + fixture 零 diff

**`uwb-ssbd`《有界的延后，和它界不住的那个帧》** —— 规格 §8 是骨架。

**一句话结论**：给信道接入的延迟定上界，就是提前决定不再等——缺省那 74 µs 的上界
等不过一个 238–470 µs 的 Wi-Fi 数据帧，于是它照发；而能塞进自己那一格的最大上界
424 µs，仍然短于场景里最长的那一帧。**这三个数全部由测试跑出来，一个都不许抄。**

课文还要说清两件：**先听后发在这份草案里是可选的**（13 条要改成 shall 的评审全部
Rejected），**而「必须先听」是管制说的**；以及**时间域里没有赢法，所以后来有人
把延后提到了频率域**（§10.47），指向切片 5b。

`basis` 是 **P802.15.4ab 草案**，不是已发布标准——`basis.test.ts` 对草案有自己的要求，
照既有草案课（`uwb-mms`、`uwb-nba`）的写法，**并给出文稿编号**。
