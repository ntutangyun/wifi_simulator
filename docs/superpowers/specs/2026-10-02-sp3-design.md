# SP3 分组测距：最短的测距帧，不构成最短的轮

2026-10-02。已发布标准 §10.32.8 与它的 SRRR IE（§10.32.9.9）。
`docs/uwb-modellable-backlog.md` 的切片 3.5。

## 1. 机理（正文读出来的，不是从标题猜的）

§10.32.8.1：SP3 测距分**三个相位**——RCM、SP3 测距、数据报告。

§10.32.8.2 讲清了三件要紧的事：

- **身份来自时隙，不来自载荷。** 调度由控制器的上层决定，每个时隙指派给一台确定的
  设备，而 RCM 里的 **RDM IE** 就是承载"哪个时隙归谁、角色是什么"的那个单元。
- **ARC IE 指定测距过程与 SP3 包格式**，于是两端都知道 SP3 相位何时开始、何时结束，
  并在前后各调一次 MLME-STS 原语启停这个包配置。
- **RCM 可以携带 RSSD IE** 交换 STS 种子的一部分；而参与设备的 **STS 计数器必须为
  SP3 包的收发各自推进并设对**。

而 **SRRR IE**（§10.32.9.9，SP3 Ranging Request Reports IE）是**响应方请求要报什么**：
正文的例子里 `SRRR IE (I,R1)` 表示响应方 1 向发起方请求到达角与往返时间，
把该单元的 **RAOA** 与 **RRTT** 两个字段都置 1。

## 2. 这一刀真正要教的东西

一个 SP3 包是 `SYNC + SFD + STS`：**没有 PHR，没有载荷**。所以它是一个纯粹的
时间标记——而正因为它带不了载荷，**它量到的时间必须在别的地方回来**。

于是它和切片 1 直接咬合：那一刀建的 **SS-TWR 回复时间延后**（§10.29.6.3）正是
"先发，时间随后由另一条消息补上"那条路。**SP3 把这条路上的测距帧压到物理上最短。**

而账是这样的（本仿真器的既有常量，Task 1 要跑出来而不是抄）：

| 帧 | 码片 | 约 |
| --- | --- | --- |
| SP3 测距标记 = `UWB_SHR_CHIPS + UWB_STS_CHIPS` | 70 368 | **141 µs** |
| 最短的 SP1 帧（14 字节响应，含 PHR） | — | **181 µs** |

每个测距帧省约 **40 µs**。但：

- SS-TWR 嵌入式（SP1）：A+1 帧，**没有报告相位**。
- SP3 分组：A+1 个标记，**外加 A 个报告**。

**所以 SP3 是否划算取决于 A 与报告的大小，而不是取决于哪一帧更短。**
这就是那一课的题目：**最短的测距帧不构成最短的轮。**
Task 1 要把这个交叉点算出来——A 等于几时 SP3 开始划算。

### 2.1 更正（2026-10-02，Task 1 实现之后查正文）：没有交叉点

**上面那句「A 大的时候更便宜」是我写错的，正文不支持它。**

Task 1 先按逐个响应方一帧报告去算，得到的结果是 SP3 随 A 单调变贵、任何 A 都不划算；
它把这个反常当成模型错了（这条纪律是对的），改成把一轮的报告批成一帧，于是算出
A = 9 的交叉点。**而正文说的是前者。**

§10.32.8.2 对 Figure 10-242 的测量报告相位写得很明确：发起方把方位角与往返时间发给
请求了它的那个响应方，而**响应方 1 与响应方 N 各自单独**把被请求的回复时间装在一个
RMI 信息单元里发回发起方。**是各自一帧，不是批成一帧。**

于是本仿真器的账是这样的，而它比原来那句更干脆：

| | 帧数 | 每帧 |
| --- | --- | --- |
| SP1 嵌入式 | A 帧响应 | 约 187 µs（回复时间在帧里） |
| SP3 分组 | A+1 个标记 **外加** 每个报告方一帧 | 标记约 141 µs，报告帧约 184 µs |

**一帧只要带载荷，就要先付 SHR + STS + PHR 那约 160 µs**，第一个载荷比特才开始。
所以标记省下的 40 µs 永远还不上多出来的那一帧。**空口时间上 SP3 没有交叉点，
它一直更贵。**

而这让那一课的题目从一个条件句变成一句断言：**最短的测距帧不构成最短的轮——
在本仿真器量得到的这个维度上，它构成的是更长的轮。**

那么 SP3 为什么存在？正文自己给了一句，而这一课要引它：§10.32.8.2 说
**在某些应用里，要不要报告可以由一种带外机制事先知道**。报告相位一旦走带外，
它占的空口时间就整个离开了这个信道——而那正是本仿真器量不到的那一半。
另一半同样量不到：SP3 包整个是 STS，而本引擎没有一处密码学。

**Task 1 的两个数因此改成：**每帧省下的 µs（跑出来），
以及**一轮里这笔节省被报告相位吃掉多少倍**（同样跑出来）。
不再有「A 等于几」这个数，因为它不存在。

### 2.2 再更正（2026-10-02，Task 3 跑完真实的轮）：贵是相对谁贵

**§2.1 写的「它一直更贵」漏了一个限定，而补上这个限定之后这一课才立得住。**

Task 3 按相位量了真实的轮（1 到 6 个锚点），测距相位每个响应方便宜 46.410 µs，
报告相位每个响应方 184.295 µs，RCM 每个响应方多一个 SRRR IE 约 3.08 µs。
对着**嵌入式**的 SP1，SP3 每个 A 都更长，差距随 A 变大——§2.1 的结论成立。

**但它同时量出了 §2.1 没说的那一半：对着「延后」的 SP1，SP3 每个 A 都更短**
（A = 1 到 6 时短 37 到 223 µs）。

这不是一处矛盾，是这一课真正的题目：

| 比较对象 | 它有没有报告相位 | SP3 的结果 |
| --- | --- | --- |
| SP1 嵌入式（回复时间在测距帧里） | 没有 | **一直更长** |
| SP1 延后（回复时间另发一帧） | 有 | **一直更短** |

**所以报告相位才是全部的开销，而最短的测距帧只在已经付过这笔开销的那条路上才赢。**

而那条路正是切片 1 建的——§10.29.6.3 的回复时间延后。**SP3 是那条路的终点**：
既然时间反正要另发一帧回来，测距帧就没有理由还带着 PHR 和载荷。

课文的三句话因此是：嵌入式不需要报告相位，所以它不需要 SP3；
一旦你为了别的理由走了延后那条路，报告相位的开销已经付了，这时 SP3 把测距帧
压到物理上最短就是纯赚；**而那个「别的理由」是什么，本仿真器量不到**
（正文 §10.32.8.2 给的那个带外机制，以及 SP3 包整个是 STS 这件事）。

**倍数有两个，课文要说清用的是哪一个：** 对着最短的 SP1 帧（14 字节响应）
是 4.578 倍，对着**嵌入式**那一种（20 字节响应）是 3.971 倍。
§2.1 比的是嵌入式，所以课文用 **3.971**。

## 3. 建什么

### 3.1 SP3 包

`uwbSp3Chips()` / `uwbSp3Ns()` = `UWB_SHR_CHIPS + UWB_STS_CHIPS`，**不含 PHR**。
引擎的 `UwbInfo` 已经有 `sp` 字段（目前恒为 1，4ab 的控制面用 0），SP3 就是 `sp: 3`。
自己的 `FrameKind`：`'uwbSp3'`。

**不建 STS 本身**，照旧——引擎没有一处密码学，`UWB_STS_CHIPS` 建的只是"它占多少
空口时间"。`sts` 相关的 `limits` 已有先例，照抄那条理由。

### 3.2 身份来自时隙

这一条**引擎已经有了**：`slotAction` 就是"哪个时隙归谁"。SP3 不需要新机制，
它需要的是**不要给那一帧加任何能装身份的东西**——这是这一刀最容易被"顺手修好"
的地方，和切片 3 的 Ruling 3 同一个形状。

### 3.3 SRRR IE：请求要报什么

内容按正文：**RAOA** 与 **RRTT** 两个请求位。两者都对上了引擎已有的东西——
`aoa` 会话开关算出的方位角，以及 DS-TWR 的往返时间。

于是它建成**响应方在 RCM 之前声明自己要什么**，而报告相位只报被请求的那几项：
`RAOA` 关着就不报方位角，报告帧因此更短。**这是一个能量出来的数。**

`SRRR_IE_BYTES` = 头 2 + 控制 1（两个请求位 + 保留）= 3 字节，每个响应方一个。
RCM 因此长 `3A` 字节——**请求不是免费的**，与 §10.36 的 MMRCR 恰好相反
（那一位在既有的控制字里）。两者放在一起是一对好对比，课程要写。

## 4. 不做

- **MLME-STS 原语**与 **RSSD IE**：照旧，没有一个 MAC 原语，也不持密钥。
  STS 计数器的推进因此也不建——引擎的 STS 只是一段空口时间。
- **多发起方多响应方**（§10.32.8.1 说过程可推广到此）：本刀只建一对多，
  与 §10.32.8.2 的图一致。多对多已有自己的模式，两者的合并是另一刀。

### 4.1 补建（2026-10-02，Task 3 的复核结论）：发起方自己的那两帧

Figure 10-242 里**发起方自己也发一个 SP3 包**（图上标作测距启动），
而在测量报告相位里**发起方也发一帧**，把方位角与往返时间送给请求了它的那个响应方。
Task 3 两件都没建：测距相位只有 A 个标记（时隙 0 是 RCM，它必须带载荷），
报告相位只有 A 帧（`uwbSlotsPerTag` 的 `2A+1` 没有给发起方留位置）。

**第二件必须补**，理由不是忠实度，是 SRRR 的 **RRTT** 请求位现在**可证明地什么也不做**：
它确实上了空口（RCM 里那 3 个字节），而整个报告相位在它置位与不置位时逐字节相同。
**一个被允许却可证明无效果的配置，正是一个特性看起来做完了的方式**——
切片 3 的 `contention` + `rmnr` 是同一个形状，这是本分支第二例。

**第一件一并补**，因为它是同一个 `uwbSlotsPerTag` 的问题，而且它只会让 SP3 看起来
更便宜（现在少算了一个标记），所以 §2.2 的结论在补建之后依然成立——方向对我们不利地安全。

补建之后：测距相位 A+1 个标记，报告相位 A+1 帧，`uwbSlotsPerTag` 在 `sp3` 下是
`2A+2`。**只在 `sp3` 打开时改变**，既有场景逐字节不变。
- **SP2**：标准还有 SP2（STS 在载荷之后）。不建，范围决定：引擎不建调制与波形，
  SP2 与 SP1 在"占多少空口时间"这个粒度上没有差别。

## 5. 验收

1. **SP3 帧比最短的 SP1 帧短约 40 µs**，而且这个数是**跑出来的**
   （`uwbSp3Ns()` 与 `uwbPpduNs(uwbRespBytes('ds'))` 之差）。
2. **没有交叉点，而这件事要被量出来，并且要量两个对照（§2.2）。**
   同一场景，SP3 分组分别对着 SP1 **嵌入式**与 SP1 **延后**各跑一轮，
   读整轮的空口时间总和并按相位分开：对嵌入式每个 A 都更长，对延后每个 A 都更短。
   两边都按 A 扫一遍钉住，而不是钉一个不存在的交叉点。
   **要写进课的是 3.971 这个倍数**（对着嵌入式的 20 字节响应），
   以及「报告相位才是全部开销」这个结论。
3. **SP3 帧一个字节的载荷都没有**：`ies` 为空，帧长 = `uwbSp3Ns()` 对应的字节等价物
   不存在（它不是以字节计的），所以测试要直接比 ns。
4. **测距结果仍然正确**：SP3 轮测出的距离与 SP1 轮在噪声之内一致。
5. **SRRR 的请求位真的省东西**：`RAOA` 关掉时报告帧更短，差值等于方位角那一项。
6. **既有场景逐字节不变**，两份 fixture 零 diff。
