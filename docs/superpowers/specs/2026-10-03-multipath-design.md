# 多径：一条接不上的线，和一个量不到的回波

2026-10-03。`docs/uwb-modellable-backlog.md` 的切片 4（「Wi-Fi 侧多径（接
`engine/scatter.ts`）+ UWB 单站回波」）。已发布标准 IEEE Std 802.11-2024
（§19.3.2/§19.3.3、§27.3.23、§19.3.12.1）、IEEE Std 802.11be-2024（§36.1.1、Table 36-18）、
IEEE Std 802.15.4-2024（§11.2.2、§11.2.3、Table 12-1）、IEEE Std 802.11bf-2025
（§9.4.1.81、§11.55.1、§11.55.3），以及 P802.15.4ab 草案材料（§10.39.1/§10.39.2）。

**这份规格的结论是：切片 4 按 backlog 写的那个样子做不出来，而且不是因为工作量。**
两半各有各的原因，而两个原因不是一种：Wi-Fi 那一半**算得出来它改不了任何判决**，
UWB 单站那一半**要么落在本引擎的粒度之下，要么要发明两个标准和语料库都没给的常数**。
所以 §1 到 §4 是查证，§5 是缩小之后真正要建的那一点，§6 把不做的分成两类。

## 1. 机理（正文读出来的，不是从标题猜的）

### 1.1 Wi-Fi：时延扩展进入「解不解得出」这件事，只有一条路，叫保护间隔

802.11-2024 把这句话在**三处**原样写了三遍（§19.3.2/§19.3.3 的 HT 发送过程、
§27.3.23 的 HE 发送过程、以及第三处 §32.3 引 §21.3.10.5.4）：保护间隔（GI）要插在
**每一个** OFDM 符号前，而它的用途正文直接点明——**对抗时延扩展**。HE 那一处还多说
一句：插多长由 TXVECTOR 的 `GI_TYPE` 指定。

802.11be-2024 §36.1.1 给出 EHT 的取值：GI 为 **0.8 / 1.6 / 3.2 µs**；EHT-LTF 符号
3.2 / 6.4 / 12.8 µs；数据字段的 DFT 周期 12.8 µs。Table 36-18 把同一组数放在一张表里，
并给出子载波间隔：EHT 字段 **78.125 kHz**，pre-EHT 字段 **312.5 kHz**。

**于是判决门槛是一个长度，而且只有一个：** 回波比直射多走的路超过 c × GI 之后，
它才落到下一个符号里去，才有符号间干扰，才可能改变「解不解得出」。算出来是

| GI | c × GI |
| --- | --- |
| 0.8 µs | **239.83 m** |
| 1.6 µs | 479.67 m |
| 3.2 µs | 959.34 m |

**本编辑器画得出的任何房间都给不出 240 米的额外路程。** 这不是近似，这是这一刀
全部结论的来处：在本仿真器的几何里，回波**永远**落在保护间隔之内，于是它**永远**
不产生符号间干扰，于是它**永远**不改变这个引擎的解调判决。

### 1.2 正文里没有的那两个词

在 802.11-2024 全文（5956 页、1699 万字符）里搜过：

- `frequency selectiv*`——**0 处**。
- `coherence bandwidth`——**0 处**。
- `delay spread`——只有 3 页，全是上面那同一句 GI 的话。
- `channel model`——4 页；其中唯一写成模型的那一处是 §19.3.12.1 的波束成形信道，
  式 (19-62)：接收向量是**逐子载波 k** 给出的。

**所以：已发布正文给了「门槛是 GI」这个机理，却没有给任何一个时延扩展的数值，
也没有把频率选择性写成一个可照着建的模型。** 一个 σ_τ 要是写进本仓库，它只能是发明的。
而逐子载波这件事，正文唯一写下的形式（式 19-62）正是本引擎没有的那个维度。

### 1.3 UWB 单站：已发布标准里没有这件事，草案里有，而草案给的机理恰好否掉它

802.15.4-2024 全文（967 页、219.8 万字符）搜过：`monostatic` **0 处**、`bistatic`
**0 处**、`radar` **0 处**、`sensing` 2 处且都与感知条款无关。**已发布标准没有单站，
也没有双站——它连「感知」这一节都没有。**

它有的是反面：§11.2.2 与 §11.2.3 定义 TX-to-RX 与 RX-to-TX 的**转换时间**，
Table 12-1 把 `aTurnaroundTime` 定成符号周期数（HRP UWB PHY 落在「其余 PHY 一律 12」
这一档）。正文对转换时间的定义是：从所发 PPDU 最后一个码片的后沿，到物理层
**准备好接收**第一个码片的前沿。**一台要转换的收发机，在自己发的时候不在收。**

单站的机理在 **P802.15.4ab 草案**里，而且查得很实：
- 草案的感知条款是 **§10.39**，§10.39.2 列的模式有单站、双站、多站与代理感知四种
  （15-24/0010r36 对草案 C 的意见汇总第 553 条，正是在要求这四个模式的说法前后一致）。
- 15-22/0308r0（Novelda）第 7 张：全双工收发机可以**一边发强脉冲一边收弱反射**，
  但难实现；半双工收发机的**接收会被自己的发送掩蔽**，方向切换要快到约 1 ns；
  收发分用两根天线也不行，天线靠得太近，掩蔽照旧。同一份第 39 张给了一个算过的数：
  **32 ns 的静默换来 4.8 m 的感知距离**。
- 15-22/0335r0 第 8 张：所以必须有**长静默**。
- 15-23/0044r1 第 18 张：单站感知要看「贴着墙呼吸的人」，所以需要**很高的动态范围**。

**4.8 m 对 32 ns，就是 c·T/2。** 这条关系本身是物理，而草案材料给了它一个算过的例子，
所以它不是我推的。

## 2. 更正：backlog 这一条有三处不对

### 2.1 「Wi-Fi 侧留着接口没接」——没有接口

`src/engine/channel.ts` 的 `Channel` 构造函数收七个参数：事件队列、取时钟、
**`linkTable: Map<string, Map<string, number>>`**、`emit`，以及三个可选的
`spectrum` / `bsGeometry` / `fading`。

- **没有 `scatterers` 参数**，`src/engine/simulation.ts:383` 把 `scatterers` 只交给
  `UwbNetwork`，一个字节都没给 `Channel`。
- **没有 `onEcho`**：`PhyListener` 五个方法全是直射那一路（`onCcaBusy` / `onCcaIdle` /
  `onRxStart` / `onRxOk` / `onRxCorrupt`）。UWB 侧的 `UwbRadio.onEcho?` 是那一刀建的。
- **连节点位置都没有**。Wi-Fi 的电平来自 `buildLinkTable`（`src/engine/propagation.ts`）
  一次算定的一张表，`Channel.linkDbm` 读的就是表里那个数。几何只从两个可选口子进来：
  `ChannelSpectrum.posOf`（6 GHz 与 UWB 的跨技术耦合）和 `BsGeometry.posOf`
  （AMP 反向散射）。两个都是为别的切片开的，都不覆盖全部节点。

所谓「接口留好了」指的只有一件事：`echoLossDb` 把路径损耗律写成参数
`(dM: number) => number`，把波长写成参数 `lambdaM`。**那是一个参数化，不是一根线。**
`src/course/uwb/uwb-sensing.ts:231` 和 `uwb-sensing-resolution.ts:189` 写的
「接口也留好了」，准确说法是「这个模块不依赖任何一种电台，所以它**可以**被另一侧调用」。

**所以这一刀不是「接一下线」，是给 Wi-Fi 信道一套它现在没有的几何。** 工作量上
那是 `linkTable` 这个结构的改动——而 §4 会说明，改完之后没有任何一个判决会变。

### 2.2 `scatter.ts` 算的不是 Wi-Fi 解调判决需要的那个量

读完全文 183 行，它算的是：双站距离（`echoPathM`）、多走的路（`echoExcessM`，钉住非负，
三角不等式）、两段时延（`directDelayNs` / `echoDelayNs`）、电平（`echoLossDb`，
两段损耗减去被重复计费的接收孔径 `apertureCorrectionDb`，加物体自己的反射强度），
以及**一个判决**：`isResolvable`，把多走的时间跟传入的 `resolutionNs` 比。

这五件事里，前四件对 Wi-Fi 一样成立——几何不认载波。**第五件不成立。**
`isResolvable` 问的是「这台接收机**分不分得开**两个到达」，这是**感知**的判决：
分得开才有第二个目标。Wi-Fi 要的判决是「这一帧**解不解得出**」，而 §1.1 已经说清，
那个门槛不是 1/B 而是 GI。两个门槛折成长度差了两个数量级：

| 带宽 | 1/B | c × 1/B（感知门槛） |
| --- | --- | --- |
| 20 MHz | 50.000 ns | **14.99 m** |
| 40 MHz | 25.000 ns | 7.49 m |
| 80 MHz | 12.500 ns | 3.75 m |
| 160 MHz | 6.250 ns | 1.87 m |
| 320 MHz | 3.125 ns | 0.94 m |

对照：GI 0.8 µs 折成 **239.83 m**（§1.1）。而 UWB 那一侧的 1/B 是一个码片，
0.60 m——所以同一套几何、同一条判决式，在 UWB 上落在一间屋子的尺度里，
在 Wi-Fi 上要么落在半间屋子（320 MHz），要么落在整栋楼之外（20 MHz）。

**结论一句话：`scatter.ts` 是一个感知原语，不是一个多径原语。** 它对 Wi-Fi
**可以**算出一个 `resolvable`，而那个布尔值在 Wi-Fi 侧**什么也不决定**。

### 2.3 「十几课的 limits 解除」——该点名，而且多数解除不了

见 §3。十五条，分布在十四课里，`十几课` 这个数是对的；**能收紧的只有一条，
而且是收紧，不是解除。**

## 3. 那十五条，逐条点名，以及每一条之后该说什么

### 3.1 Wi-Fi 侧九条（八课）

| 课 id | 这一条说的是 | 接上几何之后 |
| --- | --- | --- |
| `decode-thresholds` | 衰落对整条信道带宽同值；不建模时延扩展，因此无频率选择性 | **一字不改**。几何回波给不出逐子载波的差异（§2.2）。 |
| `mcs-ladder` | 同上，且「不会只有一部分子载波坏掉」 | **一字不改**。同上。 |
| `noise-floor` | 同上，外加无多普勒 | **一字不改**。同上。 |
| `radio-primer`（第一条） | 多径只以它对幅度的净效果出现，所有子载波同起同落 | **一字不改**。同上。 |
| `width` | 带宽只是一个倍数，整条信道只有一个电平；明说打开衰落也补不上 | **一字不改**，而且这一条点出了真正的那一刀（§6.3）。 |

**八条里有七条不动，第八条只动半句。** 这不是保守——是 §4 的数。

## 4. 读者会看到什么（这一节决定这一刀值不值）

### 4.1 Wi-Fi 的记录流里没有电平这一栏

`src/model/records.ts` 的全部记录类型过了一遍：`RX_OK`、`RX_FAIL`、`RX_MISS`、
`CCA_BUSY`、`TX_START`/`TX_END`——**一个 dBm 字段都没有**。整个引擎里带电平的记录
只有 AMP 反向散射那两条（`AMP_BS_REPLY.rxDbmAtAp`、`AMP_BS_BOOT.incidentDbm`）。
UWB 那一侧之所以看得见回波，是因为那一刀新建了 `UWB_ECHO` 这条记录，
把双站距离、多走的路、门槛与电平全写进了一行。

**所以 Wi-Fi 的电平变化本身不可观测。** 它只能通过三个后果被看见：
解调翻转（`RX_OK` ↔ `RX_FAIL`/`RX_MISS`）、载波侦听翻转（`CCA_BUSY`）、
或者选中的 MCS 变了（`frame` 里）。下面两小节把这三件事逐个算掉。

### 4.2 回波与直射的比值是一个闭式，而 Wi-Fi 的指数把它压死

`echoLossDb` 减去 `apertureCorrectionDb` 这件事有一个恰好的后果：
自由空间的第一米 `PL0 = 20·log10(4π/λ)`，孔径项 `10·log10(4π/λ²)`，两者之差
**恒等于 `10·log10(4π) = 10.992 dB`，与载波无关**。于是

> 回波比直射高出 = **10·log10(4π) + 10·n·log10(d₁·d₂ / d) + extraLossDb**

`n` 是路径损耗指数，`d₁`、`d₂` 是两段腿，`d` 是直线。**这条式子不含波长，
也不含 PL0**——它只认指数和几何。两侧的指数不一样，而这就是全部的差别：

- UWB（`UWB_PL_EXP = 2.0`）：2 m 连线、中点、0 dB 物体 → 回波比直射 **低 5.03 dB**
  （也就是更响），这正是感知课里「贴线的那个最响」的来处。
- Wi-Fi（`PL_EXP = 3.0`）：同样的中点物体，**4 m 连线就已经低 10.99 dB**，
  10 m 连线低 **22.93 dB**，15 m 连线低 **28.21 dB**。

一条低 X dB 的射线，与直射同相叠加最多抬高 `20·log10(1+10^(−X/20))` dB：
X = 11 时 **±3.3 dB**，X = 23 时 **±0.9 dB**，X = 29 时 **±0.3 dB**。
对着 `PHY_MODES.eht.sensDbm` 的阶梯（最小一级 **1 dB**）与 `RATE_MARGIN_DB = 3`，
**一个完美的一平方米反射体在任何 Wi-Fi 尺度的链路上，最多也只能在一级边界上来回抖一下。**
而编辑器的 🪞 工具默认写 −10 dB，那就再低十个分贝，连一级都碰不到。

### 4.3 `hidden` 那一课的走廊反射，建不出来——而理由是结构性的

`hiddenScenario()`：AP 在走廊 (5, 4)，两台 STA 在 (0.8, 7.2) 与 (9.2, 7.2)，
砖墙在 x = 4 与 x = 6 两处**整段贯通**（`brick(4,0,4,8)`、`brick(6,0,6,8)`，无门窗开口）。
`buildLinkTable` 给 sta-1 → sta-2 的电平是 **−83.43 dBm**，`CCA_PD_DBM` 是 −82，
所以它们确实听不见。

**两堵墙把平面整个分开了。** 从 sta-1 到 sta-2 的任何路线——直射也好，经任何一点的
两段也好——都必须穿过 x = 4 和 x = 6，一共 24 dB。墙费完全一样，于是回波只能
**额外**付两段扩散。在整间房子里以 0.1 m 为步长扫一遍，用**完美的一平方米**反射体：

| 最短腿长下限 | 全房最好的那个回波 | 对比直射 −83.43 dBm |
| --- | --- | --- |
| 1.0 m | −92.70 dBm | 低 9.3 dB |
| 0.5 m | −84.52 dBm | 低 1.1 dB |
| 0.1 m | −64.20 dBm | **高 19.2 dB** ← 见下 |

**最好的情形仍然比那条已经听不见的直射更弱。** 走廊里一次反射让两个房间互相听见，
在本引擎的损耗律与「墙整段贯通」的几何里**不可能发生**。真要演它，需要把墙本身
变成反射面（镜像法 + 可见性判断）加上开口处的绕射——而 `scatter.ts` 自己的文件头
（设计 §9）已经把这件事划出去了。

**0.1 m 那一行是一个必须记下的陷阱。** `pathLossDb` 里有 `Math.max(dM, 0.1)`，
于是一个贴在节点上的物体会让那一段腿的损耗停在 0.1 m 不再增长，回波比直射**高 19 dB**。
这纯粹是钳位的产物。编辑器的 🪞 工具允许把物体放在任何地方，**所以任何 Wi-Fi 侧的
接线都必须先有一个最短腿长，而且那个长度要从钳位点算出来，不能写字面量。**
（UWB 侧侥幸没事：n = 2 加上两米的连线，钳位虽然也会命中，量级温和得多。）

### 4.4 所以这一刀的可观测性

**零。** 没有新记录（Wi-Fi 侧没有感知消费者），没有翻转的解调（§4.2），
没有翻转的载波侦听（§4.3），没有换挡的 MCS（§4.2 的 ±0.9 dB 对 1 dB 的阶梯加 3 dB 余量）。
回波也不会变成干扰：它不上 `Spectrum`（反射不辐射新东西，`scheduleEchoes` 的注释
已经把这件事定下来了），而作为同一条链路上的额外功率它比直射低 11 dB 以上，
加进 `interferenceMw` 同样是零点几分贝。

**这就是 backlog 高估这一刀的地方。** 它假定「接上线」会解除十几条 limits；
算下来接上线之后那十五条里**十四条一个字不能改**，而唯一能改的半句
（`radio-primer` 的家具反射）靠的是「场景里现在可以摆一个物体」这件事，
而不是靠任何一个跑出来的数。

## 5. 建什么

切片 4 缩成三件小事，一件引擎、两件课程。**三件都默认关或零行为变化。**

### 5.1 `echoRatioDb()`：把 §4.2 那条闭式写进 `scatter.ts` · `physics`

```
echoRatioDb(tx, s, rx, plExp, extraLossDb) = 10·log10(4π) + 10·plExp·log10(d₁·d₂/d) + extraLossDb
```

- **为什么建**：§3 和 §4 的每一句话都靠它，而现在它只存在于这份文档里。
  它是 `echoLossDb` 的一个恒等变形（`PL0 − apertureCorrection ≡ 10·log10(4π)`），
  所以测试可以**用 `echoLossDb` 自己来钉它**：在两种指数、三种几何、两个载波下
  两条路算出来的差应当逐位相等。一个由代码做的恒等式，强于一句注释里的断言——
  `apertureCorrectionDb` 的文件头已经是这个先例。
- **它不改变任何行为**：没有调用方，没有记录，两份 fixture 零 diff。
- **它顺带给出一个上界**：`plExp = PL_EXP` 代进去，`d₁·d₂/d ≥ d/4`（中点取最小），
  于是 Wi-Fi 的回波**最多**比直射高 `10.992 + 30·log10(d/4) + extraLossDb` dB。
  这个式子算出来的东西，是 §6.1 不做 Wi-Fi 回波的那个理由本身。

### 5.2 两个门槛长度，算出来不写字面量 · `standard §36.1.1` / `standard §19.3.2` / `physics`

- `wifiEchoResolutionM(widthMhz)` = `C_M_PER_NS × 1000 / widthMhz`——感知门槛，
  §2.2 那张表的五行由它生成。
- `wifiIsiThresholdM(giNs)` = `C_M_PER_NS × giNs`——解调门槛，GI 的三个取值来自
  802.11be-2024 §36.1.1 / Table 36-18（0.8 / 1.6 / 3.2 µs），**写成常量而不是 239.83**。
- 两者都是纯函数，归到 `src/engine/phy.ts`（GI 是 PHY 的常数）或 `scatter.ts` 旁边；
  **调用方只有课程文本的派生模块**，照 `src/ui/echoFacts.ts` 已经立的规矩：
  课文里出现的数由引擎算，不由人打。

### 5.3 课程：改四处过期的说法，收紧半句，并把两个长度写进既有的两课 · `model`

1. **`uwb-intro`、`uwb-geometry`、`uwb-capstone`、`uwb-aoa`** 四条 `limits` 按 §3.2 改。
   前三条现在是**假的**；第四条结论对、理由错。这四处与切片 4 的题目无关，
   是感知那一刀留下的债，应当**先改、单独改**。
2. **`radio-primer` 第二条**收紧半句（家具反射现在摆得出来；绕射与波导仍然没有）。
3. **`uwb-sensing-resolution` 的 `deeper`** 里那句「只接了 UWB 这一侧」改写成
   §2.2 的那个理由，并把两个长度摆在一起：UWB 0.60 m、Wi-Fi 20 MHz 14.99 m、
   而 Wi-Fi 真正的解调门槛 239.83 m。**三个数由 §5.1 / §5.2 的函数算出来。**
4. **`uwb-sensing` 的单站那一条**补上 §1.3 的那个算出来的数：
   半双工单站的可测距离是 c·T/2，而本引擎最短的一次发送是 32 821 ns（`rsfNs(32, 0)`），
   折成 **4 920 m 的盲区**；草案材料算过的那个例子是 32 ns 换 4.8 m。
   **这一句把「不做单站」从一句范围声明变成一个量出来的事实。**

## 6. 明确不做

### 6.1 Wi-Fi 侧的回波到达路径 —— **不是举证不足，不是工作量，是算出来它什么也不改**

这一条必须与下面两类分开写，因为它的理由是第三种：机理读通了（§1.1），
工作量也不大（给 `Channel` 一套几何），**但 §4 把三条可观测路径逐条算成了零**。
按 backlog 自己的两条判据，它**卡在第一条**：做完之后没有一轮仿真跑得出它改变的量。

要是有一天要重新考虑，触发条件是可以写下来的，而且不是「感觉值得了」：

- 引擎有了**逐子载波**的信号质量（那时回波有地方落，见 §6.3），或者
- `RX_OK` 这一类记录**带上电平**（那时 ±0.9 dB 至少看得见），或者
- 路径损耗指数降到接近 2（那时 §4.2 的闭式才让回波有机会追上直射）——
  而 `PL_EXP = 3.0` 是室内的取值，降它是另一件事。

**顺带记下：真要建，`pathLossDb` 的 0.1 m 钳位必须先处理**（§4.3），
否则 🪞 工具会变成一个 19 dB 的信号放大器。

### 6.2 UWB 单站回波 —— 两个不同的理由，各否掉一条路

**路一：半双工 + 脉冲串（草案自己给的那条路）。不做，理由是粒度（scope）。**
单站的可测距离是 c·T_静默/2，草案材料算过的例子是 32 ns 换 4.8 m。
本引擎最短的一次发送是一个 MMS 片段：

| 发送 | 时长 | 盲区半径 c·T/2 |
| --- | --- | --- |
| RSF（N_MSR = 32，gap = 0） | 32 821 ns | **4 920 m** |
| RSF（N_MSR = 40，gap = 0） | 41 026 ns | 6 150 m |
| RSF（N_MSR = 64，gap = 25） | 91 282 ns | 13 683 m |
| RIF（STS 32 单位） | 32 821 ns | 4 920 m |
| MMS SP0 控制 PPDU | 117 600 ns | 17 628 m |

**每一行的盲区都把整栋楼装进去了。** 要让单站落进一间屋子，必须建**片段内部的
脉冲串结构**——32 ns 量级的静默，比本引擎的最小发射单位小三个数量级。
而 backlog 自己的排除理由就是这一条：这个仿真器建的是「谁在什么时候发了多长的包」，
不是比特、不是波形。**这是一刀的工作量落在了另一个粒度上，不是一刀的工作量太大。**

**路二：全双工收发机（草案列为可选的那条路）。不做，理由是举证（evidence）。**
这条路的模型本仓库已经有先例，而且是个好先例：AMP 反向散射的单站读写器
（`src/engine/ampBs.ts`）就是「一边发一边收」，它的噪声地板由
`monoLeakDbm`（发射功率减 `AMP_BS_ISOLATION_DB = 20`）与
`readerFloorDbm`（再减 `AMP_BS_READER_DR_DB = 50`）两步算出来，
`monoReachM` 还是一个发射功率会约掉的闭式——那一课的结论正是「单站把读写器开大
买不到任何距离」。**UWB 单站要照这个样子建，就需要同样的两个数。**

搜过了，而且搜的是全文而不是目录：
- IEEE Std 802.15.4-2024 全文 967 页——没有感知条款，`monostatic` 0 处。
- P802.15.4ab 本地语料 1133 份文档——`monostatic` 31 份 94 处，`multistatic` 54 份、
  `bistatic` 16 份；草案条号 §10.39.1/§10.39.2 与四个模式查得到（15-24/0010r36）；
  掩蔽机理查得到（15-22/0308r0 第 7、39 张；15-22/0335r0 第 8 张）。
- **但 TX-RX 隔离度与接收机动态范围，一个 dB 数都没有。** 15-23/0044r1 第 18 张
  只说「需要很高的动态范围」，并给了「每多一位 ADC 把地板降 6 dB」这样的定性话，
  没有给一台 UWB 单站收发机的隔离度或动态范围取值。

AMP 的 20 dB / 50 dB 出自 TGbp 的 2.4 GHz 窄带读写器提案，搬到一台 500 MHz 带宽的
UWB 接收机上就是**发明两个数字**——backlog 的第二条判据正是为这种情况写的。

**这两个理由必须分开记，因为把它们混成一句是我上次犯的错。** 路一是粒度，
机理齐全；路二是举证，模型齐全。

### 6.3 频率选择性与逐子载波的信号质量 —— 范围决定（scope），而且它才是那九条 limits 真正指的那一刀

§3.1 的九条里有六条说的是同一件事：整条信道带宽共用一个电平，所以不会出现
「信道的一部分废了、另一部分还好」。`width` 那一条还明说了打开衰落也补不上。
**这六条要的不是回波，是一个逐子载波的信道。** 802.11-2024 唯一写下的那种形式
是 §19.3.12.1 式 (19-62)，逐子载波 k；802.11be-2024 Table 36-18 给了子载波间隔
（EHT 78.125 kHz），所以「一个子载波有多宽」是查得到的。

**不做，理由是范围：** 它要动 `resolveLock` 这个所有 Wi-Fi 判决共用的函数
（现在是整帧期间最差的那一个信噪比一次判定），而且要给 `linkTable` 加一个
频率维度。这是独立的一刀，而且比切片 4 大。**它该在 backlog 里单独有一行，
而不是被「接 scatter.ts」这句话代表。** 同一刀里顺带能做的是 `frame-anatomy-bytes`
那一条：GI 按时延扩展在 0.8/1.6/3.2 µs 之间切换，取值已经查到（§1.1）。

**举证上还缺一个数，这要说清**：正文给了 GI 的取值和「GI 对抗时延扩展」这个机理，
**却没有给任何一个时延扩展的数值**（§1.2，搜过，0 处）。所以那一刀要么把 σ_τ 标成
`model` 并说清它不出自标准，要么从别处取证。**这不是「举证不足所以做不出来」——
机理是完整的，缺的只是一个可以标成模型取值的常数。**

### 6.4 Wi-Fi 感知（IEEE Std 802.11bf-2025） —— 举证（evidence），但不是「没有」，是「有而落在别的维度」

查过了，因为它看起来是这一刀的更好版本：802.11bf-2025 是**已发布**的修正案，
语料库里有全文（228 页），`monostatic` 37 页 139 处、`bistatic` 21 页 81 处，
还有代理感知（sensing by proxy）。但读进去之后它分成两半，两半都接不上：

- **sub-7 GHz 那一半的测量结果是 CSI**：`Sensing Measurement Report` 帧
  （§9.4.1.81 的容器，§11.55.1 的 TB / 非 TB 测量交换）送回的是感知测量结果
  或 CSI 变化反馈值。**本引擎没有 CSI**——没有逐子载波的信道，这正是 §6.3 那一刀。
- **带单站/双站/多站这几个模式名的那一半是 DMG/EDMG（60 GHz）**：§11.55.3 的
  DMG 感知，建在 TDD 波束成形上（`Sensing Type` 字段取值 0 = Coordinated Monostatic、
  1 = Coordinated Bistatic、2 = Multistatic，Table 9-59a），交换里是 TRN 单元与波束序号。
  **本引擎没有 60 GHz PHY，也没有波束。**

能建的只剩那个**交换**本身（NDP 公告、NDP、报告帧占多少空口时间），
而那是一刀 MAC/空口时间的活，**里面一个回波都没有，也用不到 `scatter.ts`**。
记在这里，是为了下一个人不要把它当成切片 4 的替身。

## 9. 这一刀最后落在哪一课

**落不到新的一课，而这件事本身是关于这一刀的发现。**

能写出来的那句结论是有的，而且值得知道：

> **「没有建模多径」在这个仿真器里不是一句道歉，是一个算出来的结果：**
> 同一套回波几何，超宽带接收机分得开的门槛是 0.60 m，Wi-Fi 20 MHz 是 14.99 m；
> 而真正决定一帧 Wi-Fi 解不解得出的那个门槛根本不是它，是保护间隔——折成 239.83 m，
> 比任何一间屋子都长。**所以室内多径改不了本引擎的判决，
> 而真会改判决的那一半不叫多径，叫频率选择性，它不在这套几何里。**

工作标题：**「两个长度：回波分得开，和回波改得了」**。

**但它不该成为一课，理由是 backlog 自己的第一条判据。** 这句结论的证据是读者自己
验的一道算术（三个长度，三个来源），**没有一轮仿真跑得出它改变的量**——
按这个计划的规矩，那是讲解课，不是仿真。所以它的归宿是
`uwb-sensing-resolution` 的 `deeper` 与那九条 Wi-Fi `limits` 的措辞
（§5.3），也就是**把一句「没有建模」升级成一个带数的说法**，
而不是在课程里新开一节。

**而真正会生出一课的是 §6.3。** 那一课的题目已经摆在 `width` 那一条 `limits` 里了：
信道越宽，踩到「一部分深衰、另一部分完好」的机会越多，而本仿真器现在演不出来。
**那一刀该进 backlog 单独一行，排在切片 4 原来的位置上。**
