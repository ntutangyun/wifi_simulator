# UWB 课程的标准依据:核对与重组

2026-09-26。两件事:把 UWB 课程用的每个数核对到目前能拿到的最新草案材料,
以及把"依据哪份文件"从各课 `sources` 里的散句变成课程结构上的数据。

## 1. 依据分成两半,性质不同

UWB 课程 19 课,依据分得很干净:

| 分组 | 课数 | 依据 | 状态 |
| --- | --- | --- | --- |
| UWB 一、二阶段 | 14 | IEEE Std 802.15.4-2024 | 已发布,802.15.4z 已并入正文 |
| UWB 三阶段 | 4 | P802.15.4ab 公开提案 | 草案,SA 投票复审中 |
| uwb-capstone | 1 | 两者 | — |

4z 那一半没有待追的修正案:4z 已折进 2024 版正文,引用的 §10.29.1、§10.29.8、
§10.32、§16.2.x 都是现行条款,标准留给厂商的参数用 FiRa UCI 默认值。

4ab 那一半不同。P802.15.4ab 尚未批准,草案正文是会员限定的,**仓库里没有抄过
一个字**;模型是照工作组的公开提案改写的:

- **15-22/0381r5**(94 处引用)成对测距周期、阶段划分、时隙/轮/块默认值、LBT、窄带信道表
- **15-23/0100r2**(53 处)RSF/RIF/MMRS 定义、N_MSR 取值、窄带物理层配置
- **15-23/0502r3**(14 处)必选操作参数集
- **15-22/0205r0**(13 处)每毫秒能量预算

## 2. 核对:方法与结果

草案正文拿不到,但语料库
(`D:\ai_patent_experiments\.claude\skills\wifi_patent_skill\references\uwb_tg4ab`,
1127 份文稿、约 1160 万字符,覆盖 2021–2026)里有 2025–2026 年的**意见决议文件**,
它们逐条引用草案的页/行/条号。这是目前能拿到的最接近草案正文的东西,核对就用它。

标准状态(据 15-26/0391r4,2026 年 9 月会议闭幕报告):第一次 SA 投票复审的意见
正在处理,236 名投票人、77% 回应率、80% 赞成率,316 条意见(108 技术 / 204 编辑 /
4 一般),3 个技术议题未决(compact frame 优化、发射功率控制等)。语料库里草案版本
最高只提到 D4.0(D5.1 出现一次),**"D5.0"这个版本号并未被语料库证实**。

### 2.1 过时:条号

`src/uwb/mms.ts` 写 `P802.15.4ab §10.38.5`。条号演化是
10.35.5 → 10.36.5 → 10.38.5 → **10.39.5**;按年份统计命中数:

| 年份 | 10.38.5 | 10.39.5 |
| --- | --- | --- |
| 2024 | 89 | 20 |
| 2025 | 2 | 29 |
| 2026 | 0 | 2 |

现行是 **10.39.5**。`16.2.11`(MMS 包)四年未动,那个引用是对的。

### 2.2 字段改名

经 15-24/0506 与 15-25/0066r1,*Ranging PHY Configuration* 字段里:

| 仓库常量 | 草案现用名 |
| --- | --- |
| `N_MSR_SET` | RSF Fragment Length |
| `STS_LEN_SET` | RIF Fragment Length |

取值集合本身没有被推翻。

### 2.3 数值站得住

`RSF_COUNT_SET = [0,1,2,4,8,16]`、`RIF_COUNT_SET = [0,1,2,4,8]`——草案把它们放进
*MMS Number of Fragments* 字段各占 3 bit,15-25/0261r0 明确列出 16/8/4/2/1。**一致。**

### 2.4 `MMS_RP_MIN_SLOTS = 20` 的性质变了

引用的是 15-22/0381r5 Table 1.2.3.3 的默认值。草案(15-25/0282r1 引述)现在说
`macMmsRpDuration` **下界由所有 RSF/RIF 片段的实际时长推出**,不是一个固定的 20。
代码里 `Math.max(20, …)` 的形状对,但那个 20 的地板草案没有。

### 2.5 片段间隔:不是两个取值,是三个

既有记录说"提案写 1 ms,引擎用 `(responders+1) × slot`(一对多 2 ms)"。核对后要
补一条:草案另有**交织模式,偏移 500 µs**(15-25/0388r1)。所以引擎的取值是第三种,
既不是 1 ms 也不是 500 µs。课程里的说明该按这个更新。

### 2.6 草案有、仿真器没有(都是新增,不矛盾)

- 两种配置:**NBA-MMS (Config 2)** 与 **UWBD-MMS (Config 1, UWB 驱动)**,后者允许
  Poll/Response 长度为零(15-25/0194r0)
- **MMS Fixed Reply Time**(`macMmsFixedReplyTime`,应答方自收到第一个片段起偏移固定 RSTU)
- **Reversed MMS order**(15-25/0376r2)
- **RSF with SFD**(`phyUwbMmsRsfSfd`,15-25/0066r1)
- **非交织子轮**(10.39.7)
- MMRS 配置集现为草案 **Table 85**,至少到 Config #49;仓库的 `MMS_SETS` 是其中一个命名子集

4z / 4-2024 那一半,核对没查出问题。

## 3. 重组:依据变成数据

原先"这一课依据哪份文件"只存在于每课 `sources` 的散句里:读者要读到课文末尾才知道
手上的数是已发布标准还是草案提案,而在学习指南里查一个词时根本无从得知。

### 3.1 数据模型

`StandardBasis` 四个值,`BASES` 给每个值配 `label` / `status` / `draft`:

| 值 | label | status | draft |
| --- | --- | --- | --- |
| `ieee-802-11` | IEEE Std 802.11 | 已发布 | false |
| `ieee-802-15-4-2024` | IEEE Std 802.15.4-2024 | 已发布,含 802.15.4z | false |
| `p802-15-4ab` | P802.15.4ab | 草案,SA 投票复审中 | true |
| `p802-11bp` | P802.11bp | 草案 | true |

依据是**列表**,不是单值:综合实践课确实同时依据已发布标准和草案,说出来比
挑一个好听的更诚实。

`Tier.basis` 必填,`CourseModule.basis` 选填——只有偏离所属阶段的模块才声明,
两者因此不可能意外不一致。这正是 `track` 字段已有的形状。`basisOf(mi)` 取
模块的,取不到就取阶段的。

三个模块/阶段偏离默认,每一个都是真实的:

- **共存**(M16):唯一两种电台同时在场的模块,读一次 UWB 轮次对上一个 Wi-Fi
  发送端,因此依据两份标准。
- **UWB 三阶段**:MMS 课程建立在已发布物理层(§16.4.9 等)之上,再叠草案,
  所以阶段依据是两份,不只是草案。
- **环境能量物联网**:`track: 'amp'`,依据 P802.11bp。

### 3.2 面板

阶段标题下一行徽标印 `依据:<label>(<status>)`;偏离默认的模块在自己那行再印一次;
进入课文后,面包屑下再印一次(此时阶段标题已滚出视野),草案再追加"草案,内容可能变动"。
任一依据是草案时,徽标转琥珀色。

### 3.3 一致性规则(tests/course/basis.test.ts)

本仓库反复出现的缺陷类型是**声明与实际不符**,出处和课文一样会漂。四条规则,
全部是数据规则,**不对措辞下断言**:

1. **模块不得引用未声明的文件。** 抓的是把草案编号偷偷写进一门声称依据已发布标准
   的课里——静默、评审看不见、且误导读者一个数有多硬。
2. **模块声明的草案必须真的用到。** 只管草案:陈旧的草案声明是危害,而一份只按
   条号引用(§17.3.10.2)的已发布标准不是,要求它在课文里出现名字就成了措辞规则。
3. **阶段声明的每份文件必须在其下某处被引用。** 比模块规则弱,是故意的:抓完全
   凭空的声明,又不强迫每个模块在自己课文里点名。
4. **模块不得声明与其阶段完全相同的内容。** `track` 字段已挣得这条教训:与默认
   一致的覆盖,只是给同一个事实多开一个会过期的地方。

另加一条:**标题含"草案"的学习指南分组,每个条目都要说出处**——草案引用、模型取值、
标准条款、法规,四者之一即可,只有沉默算失败。读者在指南里查一个数时没有课文、
没有段落标题,一个不说出处的草案条目读起来和已发布标准的条目一模一样。

四条规则都逐条验证过:人为违反时各自命中对应测试,恢复后全绿。

### 3.4 这一步没做的事

**没有一课一提案。** 现有 4 门 4ab 课每一门都同时引用同一组 4 份提案,不是一课
一提案;要做成一课一提案必须重写课文,超出"先不创建新内容"的范围。能按主要依据
分组的,恰好就是现有那两个模块:

- 多毫秒片段 → 15-23/0100r2(物理层)、15-23/0502r3(配置集)
- 窄带控制面 → 15-22/0381r5(MAC)、15-22/0205r0(能量预算)

**没有搬课、没有改课文正文、没有动 fixture。** 19 课位置全部不变。

**没有修 §2 查出的漂移。** 那是改引用与注释,与结构无关,在下一刀里修——见 §4。

## 4. 第二刀:修漂移

只改引用、注释与说明,不改任何数值行为;fixture 未动。

- **条号** `§10.38.5` → `§10.39.5`,两处。并在 `rifStartMs` 的文档里写明这个条号一直在
  搬家(10.35.5 → 10.36.5 → 10.38.5 → 10.39.5),所以裸条号是有保质期的。
- **字段改名** 在 `N_MSR_SET` 与 `STS_LEN_SET` 的定义处记下草案现用名
  (RSF Fragment Length / RIF Fragment Length)。标识符本身不改:那是课程与编辑器的
  词汇,改名是纯粹的搅动,还要冒动 fixture 的风险;两个名字都写出来,读者两个都学到。
- **`MMS_RP_MIN_SLOTS`** 重新定性为 model:草案已把它从"默认 20"改成"由片段总时长推出"。
  `mmsRoundPlan` 里的 `Math.max` 本来就是草案那条规则,那个 20 只是本仿真器垫在下面的地板。
- **片段间隔** 模块头部改写成三种取值并列:成对轮次 1 ms(提案)、一对多
  `(responders+1) × slot`(本引擎)、交织模式 500 µs(草案,本引擎不建模)。
- **「D5.0」这个版本号全部删掉**,共 11 处(4 课 + 学习指南 + 编辑器说明 + 词汇表 + i18n +
  README ×2)。语料库只证实到「截至 2026 年 9 月处于 SA 投票复审阶段」;草案版本最高提到
  D4.0(D5.1 一次),D5.0 这个号从来没有被证实过。

顺带修掉一类测试缺陷:六处测试用 `toContain('D5.0')` 断言"本课声明了这是草案"。版本号每次
复审都会动,把它钉死正是陈旧声明得以通过评审的原因。改成钉稳定的东西——`'草案'`、
`'unratified draft'`,以及本来就在断言的提案编号。
