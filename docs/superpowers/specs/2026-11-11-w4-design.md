# W4：单向测距与到达角按 IEEE 802.15.4-2024 改正（2026-11-11）

工作计划 `docs/superpowers/plans/2026-11-10-uwb-standard-alignment.md` 的 W4：审计表 `docs/uwb-standard-audit.md` 的 #15、#16，以及硬规则表里四个自创元素中的三个（TXT/RXT 用于 DL-TDoA 的部分、COFF、BLINK、作为信息单元的 RAOA）。
在 W2b（提交 2a152e6）之上完成。每一处都对照了语料库原文（`ieee_standards/text/802154-2024.json`）。

## 2. 未实现

- 单向测距轮最后的测量报告（图 10-225 的 MR）：标准没有规定单向测距时报告什么。
- 锚点同步的方式与残余误差（DL-TDoA）：标准只说「synchronized in some way」；本仿真器假定完全同步。UL-TDoA 的 `syncErrorNs` 仍只用于 UL。
- SP3 单边测距的 RTOF 请求：发起方的报告在应答方的回复时间到达之前发出，在那一帧里报不出 TOF；要实现需改报告阶段的顺序。编辑器与 schema 拒绝 `ssTofRequest` 与 `sp3` 同开。
- 竞争调度下的 TOF 请求：报告没有应答方事先知道的时隙。
- RMI 的 AOA Azimuth FOM、AOA Elevation（及其 FOM）字段；RRMC 的 AOA 请求位（本课的场景里方位角留在测得它的锚点上，由锚点自己定位，不经空口）。
- UL-TDoA 的基础设施报告（§10.29.5 只说设备会为每一帧报告时间戳）：四个到达时刻经有线回程到达参考锚点，不在空口。

## 3. 本仿真器的取值与取法（标准留给实现的）

- DL-TDoA 的锚点完全同步（0 ppm，真实的时隙边界）。
- 测距消息不带信息单元（标准没有规定它的内容）。
- 标签只用锚点 0 那条测距消息上测得的时钟偏差修正自己的速率；基准是锚点 0。
- 时隙长度不在 RCM 里（ARC 的 Content Control 为 0），由会话事先约定（§10.32.3.3 允许由上层设定）。
- TOF 字段四舍五入到整数 RCTU。

## 4. 核查不了的

- 图 10-225 里 OWR 轮的 RCM 是否也是一帧 RFRAME：本仿真器不用 RCM 计时，基准取锚点 0 自己的测距消息（锚点 0 因此在第 0、1 号时隙各发一帧）。
- 多用途帧的 Sequence Number 与本仿真器每台设备的序列号计数器共用。
