# 零头：一项要建，一项要删

2026-10-03。已发布标准 §16.2.9.4、§16.2.9.1、§10.29.1.1、Table 16-17、Table 16-31；
P802.15.4ab 提案文稿 15-25/0066r1 与 15-25/0194r0。
`docs/uwb-modellable-backlog.md` 的切片 6。

## 0. 先写结论，因为它和这张表上写的不一样

**这两项不是一刀，而是一刀加一次删除。**

| 项 | 查完的结论 |
| --- | --- |
| 附加 STS RMARKER §16.2.9.4 | **删除。** 本引擎的 BPRF 参数集里只存在两个标记中的第二个，而它唯一能建的用途，课程已经用一把更长的尺子教过了。 |
| `rsfSfd` 的长度 | **建，自成一刀。** 机理清楚、数算得出、代价量得到——但它**必然改动一行既有 fixture**，这是那条笔记没有预见的，也是这一刀唯一要人点头的地方。 |

两项的题目毫无交集：前一项是 4z 的 STS 段内部的时标与时钟比值，后一项是
4ab 的 MMS 片段长度与毫秒能量预算。把它们捆成「零头」只是因为都短，
而其中一项短到了不该做的程度。

## 1. 第一项：附加 STS RMARKER（§16.2.9.4）

### 1.1 正文给的是什么

§16.2.9.4 定义 SRMARKER0 到 SRMARKER4 五个标记，每一个都落在 STS 的某个
512 码片静默间隔（§16.2.9.1 规定这个间隔恒为 512 码片）的第一个码片上：
0 在第一个有效段之前的那个间隔，1 到 4 依次在第一到第四个有效段结束处的那个间隔。
**正文自己加了一个括号——「若存在」**：段不存在，对应的标记就不存在。

同一节还写了两件对本引擎要紧的事：

- **在 PHR 与 PSDU 排在 STS 之后、或者整个不存在的那两种分组配置里，
  RMARKER 与 SRMARKER0 是同一个时刻。** 这两种配置就是 Table 16-1 的
  结构 #1 与 #3，也就是本引擎建的 `sp: 1` 与 `sp: 3`（§10.32 的 ARC IE 用
  Table 10-165 那个字段来选它）。
- 这五个标记的计数器读数与各自的品质因数，由 §8.3 的 MCPS-DATA 原语参数报出，
  而且**支持它们是可选的**。

§10.29.1.1（语料库第 435 页）给了标准正文里唯一一处「拿它们做什么」：
上层可以用一个或多个 STS 段的 SRMARKER 接收计数器读数去估**远端发射机与本地
参考时钟之间的相对时钟偏差**，公式是「该段的理想长度 ÷ (RxS1 − RxS0 的实测差)」；
举的动机是天线分集的设备里不同子系统收发不同的 STS 段，于是可以逐子系统地估。

### 1.2 本引擎的模式决定了只有两个标记，而第一个是旧的那一个

Table 16-17：**BPRF 模式的段数是「1，强制」，没有可选项**；多段（1、2 强制，
3、4 可选）只在 HPRF 模式下存在。Table 16-31 的 BPRF 强制参数集第 3 行
（SHR + STS + PHR + 数据，正是本引擎的 SP1）与第 4 行（SHR + STS，正是 SP3）
都写着段数 1、段长 64 个 512 码片单位——这恰好是 `uwb/phy.ts#STS_ACTIVE_CHIPS`
的 `64 * 512`。而 HPRF 在 `docs/uwb-feature-coverage.md` 里早就标着**范围决定**。

于是在本引擎建得出的每一个带 STS 的分组里：

| 标记 | 在本引擎里 |
| --- | --- |
| SRMARKER0 | **就是现有的 RMARKER**，由 §16.2.9.4 自己那句话保证（配置 #1 与 #3）。`uwb/phy.ts#UWB_RMARKER_CHIPS` 等于 `UWB_SHR_CHIPS`，而 SFD 之后的第一个码片正是第一个间隔的第一个码片。 |
| SRMARKER1 | 唯一新增的那个时刻：`STS_GAP_CHIPS + STS_ACTIVE_CHIPS` = **33 280 码片 = 66 667 ns**，跟在 RMARKER 之后。 |
| SRMARKER2–4 | **不存在。** 没有第二、三、四段。 |

所以这一项的全部内容是**一个新常量**，而且它是由两个既有常量加出来的。

### 1.3 唯一能建的那个用途，课程已经教过了，而且用的尺子长十五倍

§16.2.9.4 给的用途（MCPS-DATA 参数把五个读数与五个品质因数报给上层）本引擎
一条 MAC 原语都没有，这条按既有规矩直接出局。

剩下 §10.29.1.1 那个时钟偏差估计。而**那个算术本引擎已经有了**：
`uwb/mms.ts#ratioSigma` 与 `uwb/mms.ts#rmarkerFromFragment` 做的就是
「用两个时间戳量一段已知跨度，得到两块晶振的比值」，只不过量的是 MMS 片段列车，
跨度以毫秒计。把 SRMARKER0→1 那段跨度代进同一个函数（跑出来的数）：

| 跨度 | σ_ratio（100 ps 时间戳） |
| --- | --- |
| SRMARKER0 → SRMARKER1，66.667 µs | **2.121 ppm** |
| 一个片段间隔，1 ms | 0.141 ppm |
| `@uwb-mms-numbers` 那一串的 14 ms | 0.010 ppm |

对照两个数：会话握着的那个时钟偏差噪声是 `cfoNoisePpm` 缺省 **0.2 ppm**，
而标准 §16.4.9 允许的晶振偏差上限是 **±20 ppm**。所以包内这把尺子比引擎现在
直接交出来的那个数**差 10.6 倍**，只比「完全不知道时钟」好 9.4 倍。

**而这个结论课程里已经有了一字不差的一节。** `@uwb-mms-numbers` 的
「为什么比值量在整串上，而不是量在一帧上」写着：同样两个 100 ps 的时间戳，
取在 14 ms 两端是 0.0101 ppm，取在一个 82 µs 的片段两端约 1.7 ppm——
比它想测的那块晶振还差。**66.667 µs 的 2.121 ppm 就是同一句话的第二个例子。**

### 1.4 结论：删除，并改一行覆盖表

建出来能看见的东西只有：每个 UWB 帧多两个计数器读数（其中一个与既有的那个完全相等），
以及一个课程已经教过的 ppm 数。要让它影响到距离，就得拿 2.121 ppm 去顶替
0.2 ppm——**而没有任何条款要求这么做**：§10.29.1.1 说的是上层「可以」这么估，
它是若干条路里的一条，而引擎现在走的是载波那条。

于是：

- 这一项从 `docs/uwb-modellable-backlog.md` 的切片 6 里**删掉**。
- `docs/uwb-feature-coverage.md` 第 193 行从「**未偿的债**」改成「**范围决定**」，
  理由写三句：BPRF 强制参数集只有一段（Table 16-17、Table 16-31），
  配置 #1 与 #3 下 SRMARKER0 与 RMARKER 同时刻（§16.2.9.4 自己说的），
  §10.29.1.1 那个用途的算术引擎已有且跨度长 15 倍（`ratioSigma`）。
  **这不是举证不足**——§16.2.9.4、§10.29.1.1、Table 16-17、Table 16-31
  全文都在语料库里，第 662、435、661、681 页，我都读了。
- `@uwb-sts` 的 `limits` 加一条（见 §4.3），`@uwb-mms-numbers` 那一节加半句
  交叉引用。两处都是文字，不动引擎。

## 2. 第二项：`rsfSfd` 的长度

### 2.1 我那条笔记里的「因此」是错的

笔记写的是「`rsfSfd` 置 1 之后 RSF 不变长，码序号那条因此校验不了」。
**两个半句都对，中间那个「因此」是错的，而且这两件事早已分别判过。**

长度那一半，代码是这样的（`src/uwb/frames.ts:713`）：

```ts
export function makeRsf(
  src: string, dst: string, index: number, phy: MmsPhy, block: number, round: number, slot: number,
): FrameDesc {
  return mmsFrame('uwbRsf', src, dst, rsfNs(phy.nMsr, phy.gap), block, round, slot, {
```

`phy.rsfSfd` 没有进到长度里。它只进到一处（`src/uwb/mms.ts:249`）：

```ts
  const openers = phy.rsfSfd ? fragments : fragments.slice(0, 1)
```

**就这一行。** 置 1 之后能开场的片段从「包首那一个」变成「全部」，别的什么都不变。

码序号那一半是另一件事：`MmsPhy` 里没有序列码索引这个量，`src` 里也没有，
所以草案那两条置 1 条件（码序号 9–32、且 RSF 片段长度为 32 或 64）
只有后一条校验得了（`src/model/scenario.ts:793` 读 `MMS_RSF_SFD_N_MSR`）。
**把 RSF 加长一点也变不出一个码序号来**——两条缺口各有各的原因，没有因果关系。
而且 `docs/superpowers/specs/2026-09-26-mms-draft-features-design.md` §9
早就把 Sequence Code Index 判成了明确不做，`@uwb-acquisition` 的 `limits`
也已经把它写明。**所以笔记的后半句不是债，是一条已经做过的判决被重新报了一遍。**

还可以把这条判决写得更准一点：Table 16-8 是长度 127 的三元码（索引从 9 起），
Table 16-9 是长度 91 的那一组（索引到 32），所以草案那个「9–32」就是
「长 127 与长 91 这两族码」，也就是把长 31 的那几个老码排除在外。
而本引擎的 MMS 分组用的恰好是长 91 那一族（见 §2.2 的符号时长），
4z 侧用的是长 127 那一族（`PSYM_CHIPS = 508` = 127 × 4）。
**于是这条条件在本引擎里是构造上成立的，不是无从校验的。** 正确的处理是
在注释与 `limits` 里把这句话说出来，而不是加一个字段。

### 2.2 SFD 有多长：两条独立的路算出同一个数

这一刀能不建一个凭空的常数，全靠这里。

- **标准那条路**：Table 16-31 的 BPRF 强制参数集每一行的 SFD 长度都是 **8 个前导符号**
  （Table 16-11 的 SFD #2）。而 Table 16-10 给长 91 码的符号是 **364 码片、729.17 ns**。
  8 × 364 = **2 912 码片**，过 `chipsToNs` 是 **5 833 ns**。
- **草案那条路**：15-25/0194r0 那张捕获对照表的短分组列，SFD 一格是 **5.8 µs**，
  而它**已经在引擎里**：`uwb/mms.ts#MMS_SP0_SEGMENT_NS.sfd` = `5_800`。
  反过来除一下：5 800 ÷ 729.17 = **7.95 个符号**。

两条路差 0.57%，而且互相印证了同一件事：**这个 SFD 是 8 个前导符号，
长度与 `nMsr`、与 `gap` 都无关，是一个定值。** 于是实现取引擎里已有的那一个
（`MMS_SP0_SEGMENT_NS.sfd`），一个字面量都不新增。

顺带，这也让草案那两条条件的意思变得干净：**RSF 的重复次数必须等于包首 SYNC 的
前导符号重复数，而 32 与 64 恰好是长 91 码强制支持的那两个 PSR 值**
（Table 16-9 后面那段文字：HPRF 模式强制支持 PSR 32 与 64）。
`@uwb-acquisition` 的 `deeper` 已经把这层意思写对了，这一刀只是给它补上数字。

### 2.3 它改变的三个量，跑出来的

`mmsFragmentDbm(fragNs) = 10·log10(UWB_MS_BUDGET_NJ / (fragNs/1000))`
——每毫秒的能量预算是定额（37 nJ），片段变长，峰值功率就按比例降。
在会话缺省的 `gap: 64` 下（`MMS_RSF_SFD_N_MSR` 允许的两个长度各一行）：

| `nMsr` | 片段 | 加 SFD 之后 | 多出 | 峰值功率 |
| --- | --- | --- | --- | --- |
| 32 | 65 641 ns | 71 441 ns | **+8.84%** | −2.4897 → −2.8575 dBm（**−0.368 dB**） |
| 64 | 131 282 ns | 137 082 ns | **+4.42%** | −5.5000 → −5.6878 dBm（**−0.188 dB**） |

三个能读出来的后果：

1. **片段变长** 5 800 ns，时间线、帧详情与编辑器的「最长片段」都看得见。
2. **每个片段的峰值功率降低**，而且**草案允许的两个长度价码不同——短的那个
   贵一倍**。这是这一刀买到的那句话：SFD 加的开场机会不是免费的，
   而片段越短，它越贵。
3. **一轮的占用时间**多 8 × 5 800 = **46 400 ns**（八个 RSF 的列车），
   而**一轮的时长不变**——片段按 1 ms 的格子排，137 µs 还远在格子里。
   「占用变多但时长不变」本身是一句值得写进课的话。

而第 2 条让 `acquired()` 的判据第一次有了两个方向：它比的是片段自己的
`rssiDbm` 与 `UWB_RX_SENS_DBM`，所以在余量不到 0.188 dB 的链路上，
**置 1 会输掉一个不置 1 本来能赢的轮**。今天的课文把这个属性讲成单向的
（「加的是机会，不是灵敏度」），补上长度之后它变成一笔交易，
而这正是草案给出这个字段时自己的说法。

### 2.4 一个陷阱：时间戳一毫秒也不许跟着动

RSF 变长之后最容易被「顺手修好」的地方在这里，而修错的代价是 1.74 km。

`uwb/frameFields.ts#mmsPpduLayout` 现在把一个片段画成一段，`rmarkerNs: 0`
——「片段的第一个脉冲就是 RMARKER」。加了尾随 SFD 之后会有人想：
既然是靠 SFD 开场的，时间戳就该读在 SFD 之后。**不对。**

- 分组的 RMARKER 仍然是**片段 0 的第一个脉冲**。SFD 只是让后面的片段也能充当
  检测入口，它不改变时间戳读在哪里。
- `rmarkerFromFragment(firstCounter, index, ratio, gapRctu)` 走回去用的是
  **片段起点到片段起点**的间隔，而 SFD 加在片段尾部、格子仍是 1 ms，
  所以 `gapRctu` 一个 RCTU 都不变。
- 把时间戳挪到 SFD 之后，等于给每个读数加 5 800 ns 的偏置：
  乘光速是 **1 739 m**。这是本刀测试要钉死的那一条。

**所以这一刀改长度与功率，不改任何一个计数器。**

### 2.5 代价：它必然改动一行既有 fixture

`tests/fixtures/lesson-hashes.json` 今天写着：

```
  "uwb-acquisition": "1bfef8ca",
  "uwb-acquisition#0": "1bfef8ca",
```

`#0` 是 `rsfSfd: true` 那个变体（`uwbAcquisitionScenario('sfd')`），
而它的空口哈希与基准场景**逐字节相同**。
**这两行相等本身就是这处缺陷的证明**：这个属性今天在空口上什么也不做。
（`uwb-record-hashes.json` 里两者不同，因为接收侧的捕获判定确实分叉了。）

于是把长度建出来之后，**`uwb-acquisition#0` 在两份 fixture 里都必须改值**——
它是全仓库唯一一个把这个属性打开的既有场景。这不是「只增不改」，
而是「改一行，并且那一行的新值与基准行不再相等」。

本刀不打算绕开这一点，而且**不许用第二个开关去绕**：给长度再加一个缺省关的
场景字段，等于一个草案属性配两个开关，那是本分支反复警告的那种「看起来做完了」。
**这一行改动要在提交信息里单独点出来，并且要有人点头。**
除此之外两份 fixture 只增不改，`MMS_DRAFT_DEFAULTS.rsfSfd` 仍然是 `false`，
所以别的场景一个都不动。

## 3. 建什么

### 3.1 片段长度（`4ab draft 15-25/0066r1`）

`uwb/mms.ts` 加一个算出来的长度函数，`rsfNs` 保持原样不动（别处还按
「序列本身有多长」在用它）：

```ts
/** An RSF on the air: the sequence itself, plus the 8-preamble-symbol SFD the draft appends to
 * every fragment when `rsfSfd` is set — one and the same SFD the packet's own head carries, which
 * is why the draft only allows the attribute where N_MSR equals a supported SYNC PSR value.
 * 4ab draft 15-25/0066r1 (the attribute), 15-25/0194r0 (the SFD's duration) */
export function rsfAirNs(phy: MmsPhy): Ns {
  return rsfNs(phy.nMsr, phy.gap) + (phy.rsfSfd ? MMS_SP0_SEGMENT_NS.sfd : 0)
}
```

改到 `rsfAirNs` 的三处：

| 位置 | 为什么 |
| --- | --- |
| `uwb/frames.ts#makeRsf` | 帧的 `txTimeNs`，于是 `mmsFragmentDbm` 自动跟着降。 |
| `uwb/mms.ts#mmsLongestFragmentNs` | 它经 `uwb/phy.ts#uwbSlotFitNs` 加 `UWB_SLOT_GUARD_NS` 定时隙长度。**这是那个上限，必须算出来**；漏了它，时隙会按旧长度裁。 |
| `uwb/frameFields.ts#mmsPpduLayout` | 片段从一段画成两段（序列 + SFD），`rmarkerNs: 0` 留在第一段上（§2.4）。 |

`uwb/ui/UwbSessionFields.tsx:1103` 读的就是 `mmsLongestFragmentNs`，自己就对了。

### 3.2 不建什么

- **序列码索引**（`out-of-scope`，并且是一次**重申**）：引擎没有这个量，
  2026-09-26 的规格 §9 已经判过。本刀要做的是把 §2.1 那句话写进注释与 `limits`：
  长 127（Table 16-8，索引自 9 起）与长 91（Table 16-9，索引至 32）两族码
  就是草案那个 9–32，而本引擎的 MMS 分组用的是长 91 那一族，**条件构造上成立**。
  不加字段。
- **RIF 带 SFD**（`out-of-scope`）：草案这个属性说的是每个 **RSF** 之后，
  RIF 是 STS 段，不在其中。
- **长分组那一列**（`model`，照旧）：15-25/0194r0 那张表还有 PSR128 的一列，
  引擎一向取短分组那一列，`MMS_SP0_NS` 的注释写了理由。SFD 同样取短的那一个，
  **方向对我们不利地安全**：短 SFD 让这一刀算出的代价尽可能小。
- **把 SFD 建成一次真的相关检测**（`out-of-scope`）：引擎不建序列、不建相关器，
  `acquired()` 一向是一条门限判据，这一刀不碰它的形状，只让它的输入变低。
- **五个 SRMARKER**：见 §1.4，整项删除。

## 4. 验收：跑完整轮，读它的输出

1. **片段真的变长了，而且是算出来的。** 同一场景开关 `rsfSfd`，读记录里片段的
   `txTimeNs`：`nMsr` 64 时 131 282 → 137 082 ns，`nMsr` 32 时 65 641 → 71 441 ns，
   而断言里的数全部由 `rsfAirNs` 算出，不写字面量。
2. **峰值功率真的降了，而且两个允许的长度价码不同。** 同两轮读 `txDbm`：
   −0.188 dB（`nMsr` 64）与 −0.368 dB（`nMsr` 32），两个数都由 `mmsFragmentDbm`
   算出来。**「短片段付双倍」这一条要进课文。**
3. **一轮的占用变多、时长不变。** 跑 `@uwb-acquisition` 的 SFD 变体整七块，
   把列车的占用时间加起来：八个 RSF 多 46 400 ns；而轮的起止时刻与基准场景相同。
4. **计数器一个 RCTU 都没动。** 这是 §2.4 那个陷阱的看门测试：
   同一场景、同一种子，开关 `rsfSfd`，**所有 `UWB_TS` 的 `counter` 与
   `UWB_RANGE` 的距离逐字段相同**（在两边都捕获得上的链路上）。
   偏了就是把时间戳挪到 SFD 之后了，而那是 1 739 m。
5. **新增一个余量不到 0.188 dB 的场景，证明代价是真的。** 置 1 之后整轮失败，
   不置 1 时包首那一个片段开得了场——**一个新变体，fixture 只增**。
   这一条是这一刀买到的那句话的全部证据。
6. **时隙没有被按旧长度裁。** `mmsLongestFragmentNs` 改了之后，
   读 `uwb/phy.ts#uwbSlotFitNs` 算出的时隙长度，确认它跟着长了 5 800 ns。
7. **既有场景逐字节不变，除了那一行。** 两份 fixture 只有
   `uwb-acquisition#0` 改值，别的一行不动；`lesson-hashes.json` 里
   `uwb-acquisition` 与 `uwb-acquisition#0` 从此**不再相等**，
   而这个不相等就是验收本身。

## 5. 明确不做：范围与举证分开写

**范围决定**（机理读通了，这个仿真器的粒度不到那一层）：

- **MCPS-DATA 的 SRMARKER 参数与逐标记的品质因数**（§16.2.9.4）：
  一条 MAC 原语都没有，照旧。
- **多段 STS**（Table 16-17、Table 16-19）：段数 2–4 只在 HPRF 下存在，
  而 HPRF 整项是范围决定。所以 SRMARKER2–4 在本引擎里不是没建，是**不存在**。
- **逐子系统的时钟偏差**（§10.29.1.1 给的那个动机）：引擎没有天线子系统，
  AoA 是算出来的一个角，不是两路接收机。
- **序列码索引**：见 §3.2，2026-09-26 规格 §9 的重申。
- **把两个时间戳合起来降噪**：§16.2.9.4 只说每个标记各有一个品质因数，
  **没有给合并规则**。要建就得自己发明一条加权，那违反这张表的第二条判据。
  注意这一条属于范围还是举证要说准：**规则不存在于正文，不是正文找不到**。

**举证不足**（这一次一条都没有，而这句话是查过才写的）：

两项要用到的条款全文都在语料库里，我搜的是正文而不是标题：

## 6. 课：一条也不新增

**两项都不配一课，而第二项要改一课的结论。**

### 6.1 `@uwb-acquisition`：删两句、改一句、加一个变体

- `limits` 里那条「置 1 之后每个 RSF 应当变长，本引擎没有把 SFD 的码片加进去…
  这笔代价在本课的时间线上一微秒也看不见」——**整条删掉**，换成建出来之后的数：
  片段多 5 800 ns，峰值低 0.188 dB（`nMsr` 32 时 0.368 dB），一轮多占 46.4 µs
  而时长不变。
- `deeper` 的「本仿真器在这里的两处不完整」**第二处删掉**；第一处（码序号）
  按 §2.1 改写成「构造上成立、因此只校验得了另一条」，而不是「无从校验」。
- `limits` 里「草案给的两条置 1 条件，本引擎只校验得了一条」那一条保留，
  但把「码序范围保证 SYNC 与 RSF 本来就是同一段图案」这句**升级成构造性的**：
  本引擎的 MMS 分组用长 91 那一族码，落在 9–32 之内。
- `deeper` 的「它解决不了的那一种」要**加第二种**：余量不到 0.188 dB 时，
  置 1 反而输掉一个本来能赢的轮。新变体就是它的证据。
- **课文那句话因此从单向变成一笔交易**：
  今天写的是「这个属性加的是机会，不是灵敏度」；
  建完之后是「**它用每个片段 0.19 dB 的峰值功率，换来每个片段一次开场机会——
  而片段越短，这笔买卖越贵**」。这是这一刀改的那半句结论。
- 要注意的副作用，写进 `limits`：基准场景与 SFD 场景**不再是严格的受控对比**
  （今天它们的片段长度完全相同，而那正是旧课文说「这正是让那组对比干净的原因」
  的那个理由）。「把 Wi-Fi 挪出这条信道」那个变体仍然是干净的对照，
  而两列片段现在差一个 SFD，课文必须说出来。

### 6.2 `@uwb-sts`：加一条 `limits`

> 标准在 STS 段内部还定义了五个附加时标（§16.2.9.4），而本引擎的 BPRF
> 参数集只有一个 STS 段（Table 16-17、Table 16-31），所以其中只有两个存在：
> 第一个与 RMARKER 同时刻（正文自己说，PHR 排在 STS 之后或者根本没有的那两种
> 配置下如此，而本引擎只建这两种），第二个在段尾那个 512 码片间隔上，
> 落后 66 667 ns。它们唯一能落到本引擎的用途是 §10.29.1.1 的时钟比值，
> 而 66.667 µs 的跨度配 100 ps 的时间戳只给到 2.1 ppm——比会话直接交出来的
> 0.2 ppm 差十倍。所以引擎不读这两个标记，`limits` 把这件事记在这里。

### 6.3 `@uwb-mms-numbers`：半句交叉引用

「为什么比值量在整串上，而不是量在一帧上」那一节已经算过 82 µs 给约 1.7 ppm。
补半句：标准在一个分组**内部**也给了同一个算术（§10.29.1.1，用 STS 段两端的
附加时标），跨度 66.667 µs、落在 2.1 ppm——**同一条曲线上的另一个点，
而不是另一种方法**。
