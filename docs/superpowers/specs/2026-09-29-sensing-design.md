# UWB 感知:散射体与回波

2026-09-29。给引擎加上会反射的物体与它产生的回波路径,让 802.15.4ab 的
**感知**(sensing)有东西可教。默认关闭,按场景开启。

## 1. 为什么要做,以及它顺带买到什么

感知是 TGD 列的 4ab 五大类之一(窄带辅助 UWB、多毫秒测距、**感知**、共存、安全),
而课程 22 门 UWB 课里**零课**讲它。读完整条线的人去看一份讲感知的文稿会是白纸。

但不能只写讲解课。这门课程的纪律是**每个数都能在仿真里跑出来**,
四门 4ab 课都做到了;感知课做不到的话,它就是课程里唯一"只能读、不能试"的一块。

而要让感知跑得出来,缺的只有一件事:**信号能从直达路径之外的地方回来**。
补上它,**顺带就有了多径**——那正是十几课的 `limits` 里记着"没有建模"的东西。
所以这一刀买到的不只是感知。

## 1.5 放哪里：共享层，不是 UWB 的 channel

两个 channel 各自为政（`engine/channel.ts` 与 `uwb/channel.ts`），
**而物理就住在 channel 里**。本周已经为此付过三次代价：
衰落做成 Wi-Fi 侧独有而需要一段范围声明；`uwb-subrounds` 一句
“本仿真器没有时变信道”当场变假；本切片本来又要再写一遍同样的声明。

所以散射体与回波的几何放进 **`src/engine/scatter.ts`**，
和 `fading.ts` 同形：纯函数、与电台无关。

理由是实际的：回波的几何对两种电台是**同一个问题**——
`(|TX→S| + |S→RX|) / c`，与载波、调制、帧格式全无关。
差别只在两件事：用哪个路径损耗模型（**作为参数传进去**，不写死），
以及接收端拿这条额外路径做什么（UWB 拿去感知，Wi-Fi 那就是多径）。

结构上没有任何东西挡着：`uwb/channel.ts` 本来就在引用
`engine/propagation`，而 `fading.ts` 已经放在 `engine/` 里、只是目前只有
Wi-Fi 侧接线——同一个先例。

**本切片只接 UWB 侧。** Wi-Fi 侧不接，但接口留好，
并在课程的 `limits` 里写明“同一套几何，Wi-Fi 侧还没接”。
这样以后的 Wi-Fi 多径是接一下线的事，而不是重写一遍。

## 2. 建什么

**散射体(scatterer)**:场景里一个会反射的物体,有位置和一个反射强度。
它不发射、不接收、不进链路表,只是让信号多一条路可走。

**回波(echo)**:对每一对(发送端, 接收端),每个散射体产生**一条额外的到达**:

| 量 | 值 |
| --- | --- |
| 时延 | `(|TX→S| + |S→RX|) / c` —— 双站距离除以光速 |
| 电平 | 两段路径损耗之和,再减去一个反射损耗项 |

回波**永远晚于**直达路径(三角不等式),这是一条可以写成测试的不变量。

## 3. 最关键的一条:回波不能被当成直达路径

`src/uwb/channel.ts` 349–366 对每对设备排**一个** `Arrival`。Batch E 核过:
"每对设备只投递一次",整个接收侧是按这个前提写的。加了回波之后,
**接收端可能把回波当成直达路径去打时间戳**,那会毁掉测距。

所以每个 `Arrival` 要带一个标记(`echo: true` 或等价物),而且:

- **测距路径完全忽略带标记的到达。** 时间戳、`acquired`、片段累加,一个都不看回波。
- **只有感知的消费者读它们。**

这条的后果是:即使场景打开了散射体,**测距结果也逐字节不变**。这既是安全网,
也是物理上对的——4z/4ab 的测距接收机锁的是第一条路径,后面的多径是它要抑制的东西。

## 4. 分辨率:这一课真正的教学点

回波能不能从直达路径里分出来,取决于它晚多少。UWB 的码片是
`UWB_CHIP_NS = 2.003205 ns`(标准 §16.2.4 的 499.2 Mchip/s),对应约 **0.6 m** 的额外路程。

所以有一条可以算的条件:

```
(|TX→S| + |S→RX|) − |TX→RX|  >  c × UWB_CHIP_NS  ≈ 0.6 m
```

**贴着直线站的人是看不见的。** 这不是简化,这是真实设备同样要面对的物理,
而且它能在仿真里直接量出来:把散射体往连线上挪,回波就并进直达路径里消失了。

这是本切片最值得写成一课的东西——它把"分辨率"从一个词变成一个可以算的距离。

## 5. 电平:这里要小心不要发明数字

回波比直达路径**弱得多**,这正是感知难做的原因。但精确的雷达方程
(含 `(4π)³` 与雷达截面 σ)不是本引擎的粒度。

取法:两段路径各按既有的 `uwbPathLossDb` 算,**再减一个反射损耗常数**
`SCATTER_LOSS_DB`,由它一项承担雷达截面与几何因子。这个常数标 `model`,
并在注释与课程里写明它是一个**概括**而不是从雷达方程推出来的:
真实的回波强度随物体大小、材质、朝向变化,人体在 UWB 频段的雷达截面
常被引作 0.5–1 m² 量级,而本仿真器不建模其中任何一项。

**不要**在代码或课程里写一个具体的雷达截面数值然后假装它被用上了——
它没有被用上。

## 6. 配置

场景加一段,**整段可缺省**;缺省即今天的行为(`fading` 那一刀已验证过这个形状)。

```ts
export interface ScattererCfg {
  id: string
  /** 位置,米。 */
  pos: Vec3
  /** 这个物体比一面理想反射面弱多少,dB。model */
  extraLossDb: number
}
```

`Scenario.scatterers?: ScattererCfg[]`,缺省时**属性不存在**——
不是空数组,理由与 `fading` 相同:走不走回波分支由"这个属性在不在"决定。

## 7. 硬约束

- **既有场景逐字节不变。** 两份 fixture 零 diff,先于一切验证。
- **打开散射体之后,测距结果仍然不变**(§3 的后果)。这一条要单独测:
  同一个场景,有散射体与没散射体,`UWB_RANGE` 记录**逐字段相同**。
- 确定性不变:同一场景同一种子两次跑,时间线哈希相同。

## 8. 验收:跑完整轮,读它的输出

1. 回波**晚于**直达:随机取一百组几何,回波时延严格大于直达时延。
2. 回波**弱于**直达:同上,电平严格更低。
3. 分辨率条件:散射体贴着连线时,额外路程小于 0.6 m,回波不可分辨;
   挪开之后可分辨。两种情形各跑一轮,读记录。
4. **测距不受影响**:打开散射体,`UWB_RANGE` 与关闭时逐字段相同。
5. 散射体缺省时,fixture 零 diff。

## 9. 明确不做

- **墙不作为散射体。** 墙仍然只对直达路径加固定时延与损耗。把墙变成反射面会让
  路径数爆炸,而且需要镜像法与可见性判断,那是另一刀。
- **不建模多普勒与运动。** 散射体是静止的,所以这一刀给的是"对被动物体测距",
  不是靠帧间差分做的存在检测。运动是下一刀,而且它需要 §5 的电平模型先站住。
- **不改 4z/4ab 的测距行为。** §3 与 §7 已经把这条钉死。
- **Wi-Fi 侧不加散射体。** 与衰落那一刀相反的范围决定,理由相同:
  一次只动一种电台,两边都好验。
