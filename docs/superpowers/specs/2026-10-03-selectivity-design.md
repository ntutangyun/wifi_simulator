# 频率选择性：标准没给时延扩展，但它给了一张按资源单元分格的信噪比表

2026-10-03。`docs/uwb-modellable-backlog.md` 切片 4 那一行——它刚被
`docs/superpowers/specs/2026-10-03-multipath-design.md` 从「Wi-Fi 侧多径 + UWB 单站回波」
换成**频率选择性（逐子载波）**。已发布标准 IEEE Std 802.11-2024
（§9.4.1.49、§9.4.1.63、§9.4.1.65、Table 9-85、Table 9-108、Table 9-109、Table 9-122、
Table 9-128、Table 9-129、式 (9-4)、§10.33.3、§19.3.12.1 式 (19-62)、§19.3.12.2、
§19.3.2/§19.3.3、§27.3.23、§32.3）与 IEEE Std 802.11be-2024（§9.4.1.73、§9.4.1.74、
§9.4.1.75、§36.3.2.1、Table 36-18、Table 36-5/6/7）。

**这份规格的结论是：这一刀做得出来，而且它不需要那个发明出来的常数。**
多径那份规格把这一刀的拦路虎定成「σ_τ 在正文里查不到，只能标 `model`」。
那句话是对的——我自己又搜了一遍，比它搜得宽，命中数更惨——**但它问错了题目。**
已发布正文从来不用时延扩展去参数化频率选择性；它用的是**子载波分组 Ng** 与
**逐 26 音调资源单元的平均信噪比**，两者都是查得到的数、带条号、带量化范围。
σ_τ 在这一刀里一次也不需要出现。

而第二个结论是坏消息，它是跑出来的：**`width` 那条 limits 预告的那句话，方向是反的。**
见 §4。

§1 到 §3 是查证，§4 是那条预告被推翻的地方，§5 建什么，§6 拒绝计划，§7 不做，§8 验收。

## 1. 机理（正文读出来的，不是从标题猜的）

### 1.1 信道在正文里本来就是逐子载波的，而且正文自己说它逐子载波不一样

802.11-2024 §19.3.12.1 把等效复基带 MIMO 信道写成式 (19-62)：**在子载波 k 上**发送
向量 x_k，收到的是 y_k = H_k·x_k + n。下标 k 不是装饰——§19.3.12.2 紧接着说，
隐式反馈波束成形要算出**一组**发送导向矩阵，**每个子载波一个**，而探测的用途是
「为**所有子载波**估出 MIMO 信道」。

**所以「信道的一部分和另一部分不一样」这件事，正文是直接写下来的，
只是它不用「频率选择性」这个词。** 它用下标 k。

### 1.2 正文给了这件事的两个尺度，两个都是数

**尺度一：子载波分组 Ng——「并成一个的载波数」。**

| 代 | 字段 | Ng 取值 | 条号 |
| --- | --- | --- | --- |
| HT | MIMO Control 的 Grouping (Ng) | 1 / 2 / 4 | Table 9-85 |
| CMMG | CMMG MIMO Control 的 Grouping | 1 / 2 / 4 / 6 | Table 9-115 |
| HE | HE MIMO Control 的 Grouping | **4 / 16** | Table 9-122 |
| EHT | EHT MIMO Control 的 Grouping | 同 HE（§9.4.1.74 引同一式） | §9.4.1.73 |

Table 9-85 对这个字段的定义逐字是「并成一个的载波数」。配上 802.11be-2024
Table 36-18 的 EHT 子载波间隔 **78.125 kHz**，Ng 折成带宽就是算出来的：

| Ng | Ng × ΔF,EHT |
| --- | --- |
| 4 | 0.3125 MHz |
| 16 | **1.25 MHz** |

**这就是正文自己认定「一个数可以代表一段频率」的那个宽度。** 它不是相干带宽
——正文没有这个词——但它是同一件事在反馈设计里留下的痕迹：超过这个宽度，
标准就不再允许用一个值。

**尺度二：26 音调资源单元——正文自己选的那个分格。**

§9.4.1.65（HE CQI Report field）与 §9.4.1.75（EHT CQI Report field）写的是同一句话：
该字段携带**逐资源单元的平均信噪比**，而每一个值是「**该 26 音调资源单元内
逐子载波信噪比（分贝）的算术平均**」。§9.4.1.75 还给了数量：Partial BW Info 里
每置一位（即每 20 MHz）**9 个**。26 音调在 EHT 间隔下是 **2.03125 MHz**。

**这一句的重要性在于它给的不是「子载波」而是「一格，格内取分贝平均」——
那正好是本引擎能承载的粒度。** 引擎不建波形、不建调制，它建的是电平；
而标准这里要的也恰好是一个电平的平均值。

### 1.3 正文还给了这件事的幅度，而且给的是一个带范围的字段

§9.4.1.49（MU Exclusive Beamforming Report field）与 802.11be-2024 §9.4.1.74
（EHT MU Exclusive Beamforming Report field）定义的是**逐子载波信噪比相对本空时流
平均值的偏差**，式 (9-4)：

> ΔSNR(k,i) = min( max( Round( 10·log10(|H_k·V_(k,i)|² / N) − SNR_i ), −8 ), 7 )

Table 9-108 把每一个 ΔSNR 子字段定成 **4 比特二补码**，正文逐字写明取值
**−8 到 7 dB**。Table 9-109 给出每个带宽、每个 Ng 下要回报多少个子载波（Ns'）
与它们的序号。

**所以正文给了三样东西，一样不少：**

1. 这个量存在，而且是逐子载波的（式 19-62、式 9-4）。
2. 它的频率分格（Ng、26 音调资源单元，Table 36-18 折成 MHz）。
3. 它的幅度范围（4 比特，−8…+7 dB），以及绝对信噪比那一侧的范围
   （Table 9-129 的 6 比特编码：从 ≤ −10 dB 到 ≥ 53 dB，**步长 1 dB**）。

正文**没给**的只有一样：这个偏差的**分布**。而那一样本仓库已经有了，见 §2.3。

（§19.3.2/§19.3.3 的 HT 发送过程、§27.3.23 的 HE 发送过程、§32.3 的 NGV 发送过程；

不是相干带宽，而且是一条定性的 NOTE，没有数值。**

**所以多径那份规格的那句话成立，只是它拦不住这一刀：**
σ_τ 确实只能是发明的；**而这一刀用不到它。**

## 2. 更正：多径那份规格有三处要改，两处让这一刀变小

### 2.1 不是六条，是五条；而第六条说的是保护间隔，不是平坦

多径规格 §6.3 写「§3.1 的九条里有六条说的是同一件事」。逐条数过（搜
`频率选择`、`整个信道带宽`、`整条信道`、`平坦`、`同起同落`、`一部分深衰`、
`一部分子载波坏掉`、`一部分废了`）：**`频率选择` 这个词只出现在四个课程文件里**
（`decode-thresholds`、`mcs-ladder`、`noise-floor`、`radio-primer`），
第五条是 `width`，它不用这个词而是写「那两层对整个信道带宽是平坦的」。

**五条，不是六条。** 第六条若要算，只能算 `frame-anatomy-bytes` 那条
`model-value`（「保护间隔这个选择在引擎里不存在，`symNs` 是每一代一个常数」）——
**它说的不是平坦，是 GI 不可选**，而那是另一半（§7.1 的切片 4c）。
这个区别要紧：**五条由这一刀解除，第六条不由它解除。**

### 2.2 那份十五条的清查漏了至少一条

多径规格 §3.1 列了 Wi-Fi 侧九条（八课）。同一批关键词扫下来还有一条同族的，
它不在那张表里：`mumimo` 的 `kind: 'unmodelled'`——「引擎连可以拿来瞄准的东西都没有
——一对节点之间只有一个电平数，没有信道矩阵」。这与 `streams` 那条（已列）是
**同一个形状**，而 `streams` 在表里、`mumimo` 不在。所以「十五条」这个数偏小。
**这一刀不解除这两条（它们要的是天线维度，见 §7.1），记在这里只是因为
那份清查被当成了一次普查，而它不是。**

另有 `rate-fallback` 一条也在这一族的边上：「真实设备靠每帧回来的信噪比估计
**提前避开一段深衰**」。它同样不被这一刀解除（选级仍读静态表均值，见 §4.3），
但它是读者会联想到的那一条，课文要点一句。

### 2.3 「要动 `resolveLock` 并给 `linkTable` 加一个频率维度」——后半句不必，前半句被夸大了

**`linkTable` 一个字节都不用改。** 频率维度不是**存**出来的，是**抽**出来的——
与 `src/engine/fading.ts` 已经立的规矩一模一样：每一次抽取都是
`(seed, txId, rxId, key)` 的纯函数，哈希出来，不留状态。
把 key 从 `fast|${frameKey}` 扩成 `fast|${frameKey}|b${bin}`，**一个新的表都不需要。**
`linkTable` 仍然是「每一对一个均值 dBm」，而那正是 `mcsForPeer` 要的东西（§4.3）。

**`resolveLock` 不是「所有 Wi-Fi 判决共用的函数」。** 读完 `src/engine/channel.ts`
（892 行）与它的全部调用方，Wi-Fi 侧的判决有五个落点，`resolveLock` 是其中**一个**：

| 判决 | 在哪 | 读的是什么 | 这一刀动不动它 |
| --- | --- | --- | --- |
| 载波侦听忙闲 | `updateAllCca`（848 行起） | 标量功率和 | **不动** |
| 前导检测 | `detectOrMiss`（786 行） | 标量 `p` 对 `detectThreshDb` | **不动** |
| 捕获效应 | `canCapture`（693 行） | `p` 对 `lock.rxDbm + CAPTURE_MARGIN_DB` | **不动** |
| **解调** | **`resolveLock`（753 行）** | `lock.rxDbm − dbm(lock.maxInterfMw)` | **动** |
| 选级 | `simulation.ts#mcsForPeer`（261 行） | **直接读 `linkTable`**，不经过 `Channel` | **不动** |

`resolveLock` 自己只有 15 行，调用方两个（`endTx` 第 731 行、`endAmpData` 第 748 行）。
它用的两个量是 `lock.rxDbm`（`acquireLock` 时一次写定）与 `lock.maxInterfMw`
（随 `applyOneTx` / `onForeignChange` 取时间上的最大）。**要改的就是这两个量的类型，
以及它们怎么合成一个数。** 其余四个落点继续走均值那一路，于是：

- 载波侦听、前导检测、捕获效应的时间线**不会因为这一刀而改变**——
  这既是工作量上的好消息，也是一条要写进 `limits` 的简化
  （真实接收机的前导检测同样吃频率选择性）。
- **爆炸半径比那句话小。** 它是一个结构体字段加一个函数，不是一张表的维度。

**代价在别处，而且要说清：** `maxInterfMw` 一旦分格，
`interferenceMw`（819 行）与 `onForeignChange`（383 行）就从 O(在飞帧数) 变成
O(在飞帧数 × 格数)，而 320 MHz 的格数是 144（§3.1）。这一刀必须让这条路
**只在开关打开时才走**，理由与 `linkDbm` 那句注释一样（「fading 关着是常见情形，
必须逐位不变：把表里那个数原样交回去，而不是给它加一个零」）。

## 3. 建什么

一句话：**给解调判决一个按 26 音调资源单元分格的信噪比，格数由带宽算出来，
格内的偏差复用既有的小尺度衰落，合成用容量。** 默认关。

### 3.1 格数：由标准算出来，不写字面量 · `standard §9.4.1.75` / `standard be Table 36-18`

```
RU26_TONES         = 26                       // §36.3.2.1 / Table 27-8 的 26 音调资源单元
RU26_PER_20MHZ     = 9                        // §9.4.1.75：Partial BW Info 每置一位 9 个
selBinWidthMhz()   = RU26_TONES × DF_EHT_KHZ / 1000      // = 2.03125 MHz
selBins(widthMhz)  = RU26_PER_20MHZ × widthMhz / 20
```

`DF_EHT_KHZ = 78.125` 来自 802.11be-2024 Table 36-18，与那张表里的
GI（0.8 / 1.6 / 3.2 µs）、DFT 周期（12.8 µs）同出一处，**写成常量而不是写 2.03125**。
算出来是：

| 带宽 | 格数 | 一格多宽 |
| --- | --- | --- |
| 20 MHz | 9 | 2.03125 MHz |
| 40 MHz | 18 | 同上 |
| 80 MHz | 36 | 同上 |
| 160 MHz | 72 | 同上 |
| 320 MHz | **144** | 同上 |

**为什么取 26 音调而不是 Ng。** 两者都是标准给的，Ng = 16 折成 1.25 MHz、
20 MHz 上 16 格，比 26 音调那一档细。取 26 音调的理由有三条，都不是口味：
（一）§9.4.1.65/§9.4.1.75 把这一格的内容**明确定义成「格内逐子载波信噪比的分贝平均」**，
那正是本引擎唯一能承载的量，而 Ng 的那一格装的是 ΔSNR 与压缩波束成形角度；
（二）26 音调资源单元是 OFDMA 的**最小**资源单元，于是「一格」在本引擎里同时是
「一个最小 RU」，这让切片 4b（§7.1）不必换单位；
（三）格数少一点，§2.3 那笔算力账便宜一点。
**三条都要写进注释，因为这是一处有两个标准答案的选择。**

### 3.2 格内偏差：复用既有的小尺度衰落，一个新常数都不加 · `model`（既有）

`fading.ts` 的 `smallScaleDb(cfg, seed, txId, rxId, frameKey)` 原样用，
key 从 `fast|${frameKey}` 变成 `fast|${frameKey}|b${bin}`。于是：

- **分布仍然是 `FadingCfg.smallScale`**（`'none'` / `'rayleigh'` / `'rician'`），
  K 因子仍然是 `RICIAN_K_DEFAULT_DB = 6`。**没有新的 `model` 取值。**
- 幅度仍然按 `E[|h|²] = 1` 归一，于是**格间的均值仍然是链路的均值**，
  `linkTable` 与 `mcsForPeer` 的语义一个字不变。
- 慢的那一层（`shadowDb`）**不分格**，这是对的：阴影是整条信道一起的，
  它按相干区间走时间，不按频率走。课文要说这一句。

**而「格与格之间独立」这一条，有标准的旁证，不只是省事：**
正文之所以要为**每一个** Ng 组回报一个值，正是因为它不假定组与组相同；
而 Ng 组比 26 音调还细。所以把 2.03 MHz 的格当成独立抽取，
在标准自己的反馈粒度之内是**保守方向**（真实信道格间有相关，相关会减少分集，
见 §7.1 的切片 4b 与 §4.4 的那句诚实话）。

**一个由标准定出来的自检，必须进测试：** §1.3 的 ΔSNR 字段只有 4 比特、
范围 −8…+7 dB。跑出来（40 000 次、九格到一百四十四格）：

| 分布 | 落在 [−8, +7] dB 之外的格 |
| --- | --- |
| `rayleigh` | **15.3 %** |
| `rician`（K = 6 dB） | **3.3 %** |

**所以标准自己那个字段装不下一个纯瑞利的逐格信道，却装得下 K = 6 dB 的莱斯。**
这不是把瑞利判为非法——它是最悲观的那一档，留着有用——而是一条**算出来的
标定**：场景若选莱斯 K = 6（引擎既有缺省），逐格偏差有 96.7 % 落在标准自己
的反馈字段表达得了的范围里。**这一行是本规格「caps are computed」最硬的一处，
它把一个分布的选择从口味变成了一个对着条号的百分比。**

### 3.3 合成：容量，而不是最差格，也不是 EESM · `physics`

```
selEffSinrDb(meanSinrDb, devsDb) =
  10·log10( 2 ^ ( mean_b log2(1 + 10^((meanSinrDb + devsDb[b]) / 10)) ) − 1 )
```

**为什么不能取最差格。** 今天的 `resolveLock` 取的是**时间**上最差的那一瞬间，
很容易顺手把频率也照这么办。跑出来那是灾难性的错（瑞利，深度是均值之下）：

| 带宽 | 格数 | 最深那一格的平均深度 |
| --- | --- | --- |
| 20 MHz | 9 | 12.05 dB |
| 40 MHz | 18 | 15.12 dB |
| 80 MHz | 36 | 18.03 dB |
| 160 MHz | 72 | 21.09 dB |
| 320 MHz | 144 | **24.09 dB** |

**每翻一倍带宽，最深的坑深约 3 dB。** 取最差格就等于宣布 320 MHz 的链路
比 20 MHz 的差 12 dB——那是把「OFDM 跨整条信道编码」这件事整个删掉。
**而这正是 `width` 那条 limits 预告的那个方向，所以这个取法必须被点名拒绝。**

**为什么不是 EESM。** 工业界的链路映射是 EESM，它每个 MCS 要一个 β。
那个 β 在上面搜过的四份文件里一个都没有——**它是真正需要发明的那个数。**
容量不需要任何常数，它是一条不等式的紧化（Jensen 在 log2(1+x) 上），
**所以它标 `physics`，而 EESM 标 `out-of-scope`，理由是举证。**

**容量的代价要写清，这是本规格最大的一处乐观：** 真实接收机达不到容量，
它与容量之间差一个与星座、码率、交织都有关的量。于是本模型给出的
是频率选择性**最小**的那份损失。**这句话要进 `limits`，而且要说明
那个差值就是我们拒绝发明的那个数。**

### 3.4 开关与拒绝 · `model`

`Scenario.selectivity`：缺省**不存在**（不是一个填了 false 的字段），
照 `fading` 已经立的规矩（`src/model/scenario.ts` 第 1000–1012 行那段注释
把「默认在字段上，永不在小节上」讲得很清楚，这一刀照抄）。

小节里只有一个字段，因为别的都已经在标准或 `fading` 里了：

| 字段 | 取值 | 缺省 | 标 |
| --- | --- | --- | --- |
| `binsPer20Mhz` | 固定 9，**不可配** | — | `standard §9.4.1.75` |
| `on` | 布尔（小节在即为真） | — | — |

**一个可配的格数就是一个发明出来的数**，所以它不可配。小节存在即生效，
分布与 K 因子从既有的 `fading` 小节来——于是 `selectivity` 必须要求
`fading` 在场且 `smallScale !== 'none'`（§6）。

### 3.5 记录：Wi-Fi 的记录流里第一个电平字段 · `model`

多径规格 §4.1 查过：`src/model/records.ts` 的 `RX_OK` / `RX_FAIL` / `RX_MISS` /
`CCA_BUSY` / `TX_START` / `TX_END` **一个 dBm 字段都没有**，全引擎带电平的
只有 AMP 反向散射那两条。我核过，仍然如此。

所以新一条 `WIFI_SEL`：`node`、`from`、`meanSinrDb`、`effSinrDb`、`lossDb`、
`bins`、`worstBinDb`、`threshDb`。**只在 `selectivity` 在场时发。**

**它不是装饰。** 没有它，这一刀能被看见的只有「帧翻了」，
而 §4 的全部结论都是关于**翻了多少**的；而 `lossDb` 与 `worstBinDb` 两栏并排，
正是 §4.1 那个反向结论在一行里的样子。

## 4. 读者会看到什么——以及 `width` 那条 limits 的预告是反的

### 4.1 量出来的两张表，方向相反

链路停在自己那一级的边上（`mcsForRssi` 留的 `RATE_MARGIN_DB = 3` dB 余量恰好用尽
就失败），均值信噪比 20 dB，40 000 次抽取，格数按 §3.1 由带宽算出：

| 带宽 | 格数 | 最深那一格（瑞利） | **掉帧率**（瑞利） | 掉帧率（莱斯 K=6） |
| --- | --- | --- | --- | --- |
| 20 MHz | 9 | 12.05 dB | **34.43 %** | 3.60 % |
| 40 MHz | 18 | 15.12 dB | **29.22 %** | 0.58 % |
| 80 MHz | 36 | 18.03 dB | **22.86 %** | 0.01 % |
| 160 MHz | 72 | 21.09 dB | **15.36 %** | 0.00 % |
| 320 MHz | 144 | 24.09 dB | **7.14 %** | 0.00 % |

**坑越来越深，而帧越来越收得到。** 两列单调，方向相反。

`width` 那条 limits 现在的预告是：

> 「真实的宽带室内信道不是这样：同一时刻信道的一部分深衰、另一部分完好，
> **而信道越宽，踩到这种坑的机会越多。**」

**前半句对，后半句作为一句关于后果的话是反的。** 踩到坑的机会确实越多
（第三列），但**掉帧的机会越少**（第四列），因为 OFDM 的编码跨整条信道，
坑越多越摊得开——这就是频率分集。损失的**中位数**几乎不随带宽动
（瑞利 2.29 → 2.36 dB，莱斯 0.86 → 0.92 dB），动的只有它的**分散度**：
90 分位从 4.62 降到 2.92 dB。

**宽信道真正的代价不是频率选择性，是噪声地板，而那一项引擎早就有了：**
`noiseDbm(20) = −93.99`、`noiseDbm(320) = −81.95`，整整 **12.04 dB**，
而 `width` 那一课的「倒挂」正是这 12 dB 的产物。
**频率选择性是往回赚的那一边，不是再往下压的那一边。**

### 4.2 所以读者看的是什么

**是掉帧率，而且它在时间线上成段地变。** 不是一个内部数字：

- `RX_FAIL`（`reason: 'lowSinr'`）的条数随带宽**单调下降**，这是可以在同一场景
  的五个带宽变体上并排数出来的。
- 掉帧之后 `RateControl` 会走（`FAILURES_TO_STEP_DOWN = 2`），
  于是**选中的 MCS 会在时间线上一级一级往下挪再爬回来**——
  这是 `rate-fallback` 那一课已经教过的机制，这一刀第一次给了它
  **真正的那个触发源**（那一课自己的 `out-of-scope` 逐字写着它缺这个触发源：
  「这里 337 次失败没有一次来自链路变差」）。
- `WIFI_SEL` 一行把 `lossDb` 与 `worstBinDb` 并排放着，于是 §4.1 那个反向结论
  **在一帧上就看得见**：坑 −21 dB，这一帧的损失 2.4 dB。

**这是「可见地改变哪些帧解得出」，不是「只动一个内部数字」。**

### 4.3 一处要诚实的限制：选级那一步仍然读均值

`simulation.ts#mcsForPeer`（261 行）**直接读 `linkTable`**，连 `fading` 都不读
（那里的注释把理由写得很对：发送端选级时那一帧还不存在）。这一刀不碰它。
后果有两条，都要进 `limits`：

1. 发送端**看不见**频率选择性，只能靠失败计数去反应——这恰好是真实设备
   要 CSI/CQI 反馈的理由，而 §1.2 的那两个字段就是那个反馈。
   **课文在这里引 §9.4.1.65 / §9.4.1.75，比任何比喻都省事。**
2. `rate-fallback` 那条「真实设备提前避开一段深衰」仍然为真，**不解除**。

## 4.4 更正（2026-10-03，Task 4 从真实的轮里量）：是「掉帧率」而且要「余量相同」

**§4.1 那两列的方向成立，而它的数字不是一轮仿真会产出的数字。**
Task 4 按计划的字面判据去量——`widthScenario` 原样、五个带宽、数 `RX_FAIL(lowSinr)`——
得到 **0、0、0、36、5**：既不单调，而且大半是零。它没有调场景去凑，而是找出了两个原因，
两个都不推翻物理：

1. **书桌那条链路在每个带宽上都高出自己那一级约 6 dB**，而这个特性产生的损失
   中位数只有 2.0–2.4 dB。§4.1 是在**固定 20 dB 平均信噪比、余量恰好用尽**时量的，
   而一轮真实仿真两个条件都不满足。
2. **随带宽一起动的不止格数**：噪声地板动了 12.04 dB（§4.1 自己说那才是宽信道真正的代价），
   而**速率控制是一个闭环**——它对失败的回答是降一级，于是给自己换来了更宽的余量。
   **一个选择性更重的带宽，可以改用速率去付，而不是用掉帧去付。**

**把平均信噪比按带宽补平之后（两端发射功率各抬 `noiseDbm(w) − noiseDbm(20)`，算出来的，
不是字面量），在 `width` 自己 `tryThis` 指定的那个客厅位置上量，每个带宽 200 ms：**

| 带宽 | 格数 | 最深格（中位） | 损失 p90 | 余量 | 掉帧 | PPDU | **掉帧率** |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 20 | 9 | −10.08 dB | 4.68 dB | 6.62 dB | 14 | 252 | **5.56 %** |
| 40 | 18 | −13.58 dB | 3.88 dB | 3.62 dB | 44 | 458 | **9.61 %** |
| 80 | 36 | −16.72 dB | 3.56 dB | 3.62 dB | 47 | 643 | **7.31 %** |
| 160 | 72 | −19.86 dB | 3.21 dB | 3.62 dB | 23 | 774 | **2.97 %** |
| 320 | 144 | −23.16 dB | 2.93 dB | 3.62 dB | 4 | 871 | **0.46 %** |

**坑每翻一倍深约 3.3 dB，而损失的尾巴同时收紧**（4.68 → 2.93 dB），两者都严格单调。
**§3.3 与 §4.1 的两列在真实的轮里复现了。**

**而结论的措辞要改两处，两处都是真实的轮逼出来的：**

- **是掉帧「率」，不是掉帧「数」。** 320 MHz 在同样的时间里发出 871 个 PPDU，
  而 20 MHz 只发 252 个。**数个数会把空口时间和解调能力混在一起**——
  按个数是 14、44、47、23、4，不单调。
- **而且要「余量相同」才比得了。** 20 MHz 已经先用「降一级」付过账了，
  于是它多出 3 dB 余量，掉帧比 40 MHz 还少——**而它其实是更差的那条信道。**
  测试**按余量本身**挑出可比的那一组，所以这个分组不能靠挑带宽来凑。

**§4.1 的 34.43 % → 7.14 % 是开环抽样、固定 20 dB 余量下的数，一门课跑不出它们。**
课文与 `limits` 可以说「坑每翻一倍深约 3 dB，而掉帧率降了一个数量级」，
**但必须说「余量可比时的掉帧率」**，而且不能把那两个开环数字说成一轮仿真的产物。

## 3.6 更正（同上）：逐格的只有信号，干扰与噪声仍然是一个数

§2.3 原来设想连 `lock.maxInterfMw` 一起逐格。**Task 4 只把信号做成逐格的**，
干扰与噪声在每一格里都是同一个数。

- **对热噪声这是精确的**：噪声是平的，于是「逐格信噪比 = 平均信噪比 + 该格衰落」恰好成立。
- **对一个干扰者这是一处简化**：真实的干扰者和信号一样有频率选择性，
  于是本模型让一次碰撞比实际更均匀一点。**这一条要进 `limits`。**

附带结果：§2.3 预算的 O(在飞帧数 × 格数) 的算力从来没有发生。

**另外一处要进 `limits` 的不对称**：开着选择性之后，前导检测与捕获仍然读那个平的快衰落抽样，
而解调判决已经不读它了——**于是「均值」在同一帧的一生里指着两个不同的数。**

## 5. 五条 limits，逐条点名，以及每一条之后该说什么

全部五条，`kind` 全是 `unmodelled`，由 §4 的数据支撑。

### 5.1 `radio-primer`（`src/course/tier1/radio-primer.ts:134`）

现在：「即便打开了衰落，也没有时延扩展与频率选择性：多径只以它对幅度的净效果出现，
整个信道带宽共用同一个衰落值，所有子载波同起同落。」

之后有资格说的：

> 打开频率选择性之后，衰落不再是整条信道一个值：信道按 2.03125 MHz 一格
> （标准自己给 CQI 用的那个 26 音调资源单元）各抽一次，于是同一瞬间
> 一部分格深衰、一部分完好。仍然没有的是时延扩展本身与多普勒——
> 格与格之间在这里是独立的，没有一条时延参数把它们系起来。

### 5.2 `decode-thresholds`（`tier1/decode-thresholds.ts:84`）

现在：「衰落打开时也是整个信道带宽同一个值……不会出现『信道的一部分废了、
另一部分还好』。」

之后：

> 打开频率选择性之后会出现，而这一课的硬门限就落在**合成之后**那个数上：
> 格内各自的信噪比按容量折成一个有效信噪比，再与该级的要求比一次。
> 所以「一部分废了」不等于「这一帧废了」——320 MHz 上最深那一格平均深
> 24.09 dB，整帧的有效信噪比却只掉 2.36 dB。

### 5.3 `mcs-ladder`（`tier1/mcs-ladder.ts:97`）

现在：「不建模时延扩展与频率选择性，因此没有『只有一部分子载波坏掉』这种情形，
而真实设备正是靠它才会去选择带宽、空间流与信道。」

之后：

> 现在有了，但「靠它去选择」这一半仍然没有：选级那一步读的是链路表的均值
> （`simulation.ts` 的 `mcsForPeer`），频率选择性一个字都不进去。
> 真实设备靠的正是标准为此定下的那两个反馈——逐 26 音调资源单元的平均信噪比
> （§9.4.1.65 / §9.4.1.75）与逐子载波的信噪比偏差（§9.4.1.49，4 比特、−8…+7 dB）。

### 5.4 `noise-floor`（`tier1/noise-floor.ts:86`）

现在：「而且那份衰落对整个信道带宽是同一个值——不建模时延扩展、频率选择性与多普勒。」

之后：

> 分母（地板）仍然只跟带宽走，一格一格都一样；变成逐格的是分子。
> 于是这一课那个比值在打开频率选择性之后有了格数这么多个，
> 而判决用的是它们按容量合成的那一个。多普勒仍然没有。

### 5.5 `width`（`tier2/width.ts:149`）—— **这一条是这一刀的题目，而且它要改方向**

现在：「……而信道越宽，踩到这种坑的机会越多。即便在编辑器里打开衰落也补不上这一条。」

之后：

> 打开频率选择性之后补上了，而跑出来的结果与这句预告相反：
> 坑确实越宽越深（最深那一格从 20 MHz 的 12.05 dB 到 320 MHz 的 24.09 dB，
> 每翻一倍深约 3 dB），**掉帧率却从 34.43 % 降到 7.14 %**——
> 编码跨整条信道，坑越多越摊得开。宽信道的代价是那 12.04 dB 的噪声地板，
> 而频率分集往回赚一点。仍然没有的是格间相关：真实信道的相邻格并不独立，
> 相关会把这份分集吃掉一部分。

**第六条（`frame-anatomy-bytes` 的 GI）这一刀不动**，理由见 §7.1。

## 6. 拒绝计划：每一个被允许的组合，都要能证明它不是空的

本分支已经发出过三个「被允许却可证明什么也不做」的配置（切片 3 的
`contention` + `rmnr`、切片 3.5 的 SRRR `RRTT` 位、以及 SSBD 规格 §5 点出的那一批）。
这一刀的开关逐条过。

**schema 拒绝（`superRefine`，中文消息，照既有几条的写法）：**

| 组合 | 为什么拒 |
| --- | --- |
| `selectivity` 在场 + 没有 `fading` 小节 | 逐格偏差的分布就是 `fading.smallScale`。没有它，格格相同，与关掉**逐字节相同** |
| `selectivity` + `fading.smallScale: 'none'` | 同上，而且这一条是最容易写出来的空配置：`smallScale: 'none'` 时 `smallScaleDb` 直接返回 0 |
| `selectivity` + 场景里没有任何 `eht`/`he`/`vht` 链路 | 26 音调资源单元是 OFDM 的分格；纯非 HT 链路上格数仍是 9，但课文的每一个数都按 EHT 间隔算。拒了比悄悄给出一个按错间隔算的格宽好 |

**schema 拒不掉、必须由测试证明不空的四个：**

1. **反向散射与 AMP 上行帧。** `resolveLock` 同时服务 `ampBsReply`
   （`decodeThreshDb` 第 324 行就是它）与 `frame.amp?.dir === 'ul'` 的 OOK 帧。
   **这两类帧不是 OFDM，26 音调资源单元在它们身上没有意义**，而反向散射的
   地板是读写器自己的泄漏（`bsFloorDbm`），不是热噪声。
   **决定：逐格那一路只对 OFDM Wi-Fi PPDU 走，AMP 两类走原路。**
   **测试怎么证**：在一个同时有反向散射标签与 `selectivity` 的场景里跑两轮
   （开/关），断言 `AMP_BS_REPLY` 与 `AMP_BS_BOOT` **逐字段相同**、
   `WIFI_SEL` 里没有一条的 `from` 是标签。**这一条分不开，AMP 那一层的
   两份 fixture 就会无声地动。**
2. **链路余量够大的场景。** 一条离 AP 两米的链路，选中那一级之上还有
   好几分贝的台阶（EHT 灵敏度阶梯最大一步 5 dB，加 3 dB 余量），
   于是 2.4 dB 的损失一帧都翻不动。schema 拒不掉——几何本来就可以是这样。
   **测试怎么证**：在那个场景上断言 `WIFI_SEL` **有记录**且 `lossDb > 0`，
   同时断言 `RX_FAIL` 条数与关着时相同，**并在课文里写明这是哪一种情形**。
   「有量、无后果」要被明示地钉住，而不是让它看起来生效了。
3. **`widthMhz: 20` 的单格近似。** 9 格是最少的一档，掉帧率 34.43 %（瑞利）
   是全表最高的一档。**这不是无效果，而是效果最大的那一档**——
   但它容易被误读成「这一刀对窄信道没用」。
   **测试怎么证**：五个带宽各跑一轮，断言 `RX_FAIL` 条数随带宽**严格单调下降**。
   **这一条断言就是 §4.1 那张表，也是 `width` 那条 limits 改方向的全部依据；
   它要是不单调，这一刀的结论是错的，不许发。**
4. **`selectivity` + 多用户帧（`muParts` / `ruFraction`）。** 一个占半条信道的
   成员在物理上只拿到一半的格，占一个 26 音调资源单元的成员只拿到**一格**。
   **本刀不建这一半**（见 §7.1 的切片 4b），于是一个 OFDMA 成员会拿到
   **整条信道的格数**，分集被高估。
   **测试怎么证**：在一个 OFDMA 场景上断言 `WIFI_SEL.bins` 等于**整条信道**
   的格数而不是该成员那一份，并在 `ofdma-dl` / `ofdma-ul` 各加一条
   `out-of-scope` 说明它。**一个被高估的量要被断言成它现在的样子，
   而不是被当成对的。**

**另外一个要证明两边都还在动的：** `selectivity` + `fading.shadowSigmaDb > 0`。
两者作用在不同的维度上（阴影按时间、选择性按频率），不该互相吃掉。
断言一次运行里 `WIFI_SEL.meanSinrDb` 在相干区间之间**跳变**（阴影在动）、
而 `lossDb` 的分布在区间内外**一致**（选择性与阴影无关）。

## 7. 明确不做：范围 / 举证，两类分开

### 7.1 范围决定（「一刀的量，和之后那一刀」）

- **资源单元粒度的频率分集 → 切片 4b。** §6 第 4 条量出来的那件事：
  整条信道 144 格时掉帧率 7.14 %，半条（72 格）15.36 %，
  而一个 26 音调资源单元是**一格**，掉帧率 39.48 %。
  **「把信道切开，切掉的是频率分集」是一门独立的课**，而且它正是
  `ofdma-dl` 那一课「每个成员只拿到速率的一部分」缺的那后半句。
  不并进这一刀的理由是它要动 `muParts` 的每一份与 `ruFraction`，
  而那是 MU 判决那一路（`decodeThreshDb` 第 329–335 行），不是 `resolveLock` 本身。
  **它该在 backlog 里单独有一行。**
- **保护间隔的选择 → 切片 4c，而且它不需要 σ_τ。**
  取值查到了（802.11be-2024 Table 36-18：0.8 / 1.6 / 3.2 µs；
  `GI_TYPE` 由 TXVECTOR 指定，§27.3.23 / §36.3.x）。
  **把 GI 当成一个场景选择**而不是从信道推出来的量，
  它就只是 `PHY_MODES[*].symNs` 从常数变成「DFT 周期 + 选中的 GI」，
  空口时间跟着变一两成——**可跑、可读、一个新常数都不要**。
  要从时延扩展**推**出该选哪一档才需要 σ_τ，而那一步不做（§7.2）。
  它解除的是 `frame-anatomy-bytes` 那条（§2.1 的第六条）。
- **信道矩阵与天线相关性（`streams`、`mumimo` 那两条）。** 要的是天线维度，
  而式 (19-62) 的 H_k 是一个矩阵——这一刀只建那个矩阵的**一个标量摘要**
  （每格一个信噪比）。秩、相关性、MU 组内残余泄漏都在这之外。
- **真正的逐子载波波形与均衡。** 引擎不建调制与波形，一格是一个信噪比，
  不是 26 个音调。均衡器的噪声增强因此也不建。
- **载波侦听、前导检测、捕获效应吃频率选择性。** §2.3 的表里那三行。
  真实接收机的前导检测同样落在选择性信道上；本刀让它们继续走均值，
  理由是这三件事都发生在**一帧之内的一个瞬间**，而逐格的那笔算力账
  （§2.3）要是乘到 `updateAllCca` 上就会落在每一次 `applyPendingStarts` 里。
- **CSI / CQI 反馈那个交换本身**（NDP 公告、NDP、压缩波束成形/CQI 报告帧
  各占多少空口时间）。那是一刀 MAC 空口时间的活，里面一个格都没有。
  记在这里是因为它看起来是这一刀的续集，**而它跟 `selectivity` 共用的只有条号**。
- **802.11bf-2025 的感知。** 多径规格 §6.4 已经查完，结论不变，
  但有一条要补：**11bf 的 sub-7 GHz 那一半送回的 CSI 用的正是 Ng = 16 的
  子载波分组**（查过，228 页里 `subcarrier grouping` 5 页、`Ng = 16` 6 页）。
  所以这一刀建完之后，11bf 那一半的前提**第一次成立了一半**——
  引擎有了逐格的信道摘要。**但它要的是 H_k，不是 |H_k|²/N 的一个标量**，
  所以仍然接不上。这一句写下来，是为了下一个人不要以为 4a 打开了 11bf 的门。

### 7.2 举证不足（「正文没说」）

**只有两条，而且都不拦这一刀：**

- **时延扩展 σ_τ 的任何取值，以及任何一张信道模型表。** §1.4 那张表就是搜索记录：
  四份已发布文件、`frequency selectiv` / `coherence bandwidth` / `power delay profile` /
  `rms delay` / `tapped delay` / `Rayleigh` / `Rician` / `TGn` 全部 **0 命中**，
  `delay spread` 只有 GI 那一句。**而这一刀不需要它**——
  标准给的参数化是分组与逐资源单元平均信噪比（§1.2、§1.3），不是 σ_τ。
  **backlog 的第二条判据因此是过的，而这正是多径规格把题目留在这儿时没有看到的那一半。**
  要写进 `limits` 的是另一句：格与格之间的**相关长度**没有取值，
  所以本刀取独立，而独立是分集**偏多**的那一边。
- **EESM 的 β，以及真实接收机与容量之间那个差值。** 两者在四份文件里都没有。
  于是合成用容量（§3.3），而那意味着本模型给出的是频率选择性损失的**下界**。
  **这一条要与上一条分开记，因为它是「有机理、缺一个数」，
  而上一条是「不需要那个数」。混成一句是多径规格在 UWB 那半犯过的错。**

## 10. 这一刀收在哪一课

**id `selectivity`，Wi-Fi Tier 2 M4，接在 `width` 之后**
（`src/course/curriculum.ts` 第 186 行那一行里 `'width'` 与 `'streams'` 之间）。
放在那儿而不是放在 `rate-fallback` 之后，理由是 `width` 那条 limits 就是它的题目，
而它要改的正是那条 limits 的方向——**一门课最好紧跟着它推翻的那句话。**

**工作标题：《一部分死掉，和这一帧死掉，是两回事》。**

**一句话结论：给整条信道一个电平，演不出「一部分深衰」；
按标准自己的 26 音调资源单元分格建出来之后，跑出来的结果与预告相反——
最深的那个坑随带宽每翻一倍深约 3 dB（20 MHz 的 12.05 dB 到 320 MHz 的 24.09 dB），
而掉帧率随带宽单调下降（34.43 % → 7.14 %），因为编码跨整条信道，坑越多越摊得开；
宽信道真正的代价是那 12.04 dB 的噪声地板，频率选择性是往回赚的那一边。**

这句话读者会觉得值得知道，而且它不是我推的，是 §4.1 那两列量出来的。
它还顺手解释了三件别的事：为什么标准要为每一个资源单元回报一个信噪比
（§9.4.1.65 / §9.4.1.75）而不是为整条信道回报一个；为什么那个逐子载波偏差字段
只给 4 比特就够（§9.4.1.49，−8…+7 dB，而一个莱斯 K = 6 的信道有 96.7 % 落在里面）；
以及为什么把信道切成资源单元要付一笔课文至今没算过的账（切片 4b，§7.1）。

配一条 `model-value`（逐格偏差的分布与 K 因子来自既有的 `fading` 小节，
不是标准取值）、一条 `unmodelled`（格间相关长度没有取值，本刀取独立，
而独立是分集偏多的那一边）、一条 `threshold`（合成用容量，真实接收机达不到，
于是这里给出的是频率选择性损失的下界，而那个差值就是我们拒绝发明的 EESM 的 β）、
一条 `out-of-scope`（载波侦听、前导检测、捕获效应仍然走均值；
多用户成员拿到的是整条信道的格数，分集被高估——指向切片 4b）。

## 11. 判断：这一刀该不该按这个样子做

**该做，但该拆成三刀，而且顺序与 backlog 现在那一行不同。**

| 刀 | 内容 | 为什么单独 |
| --- | --- | --- |
| **4a**（本规格） | 单用户、占满整条信道的逐格信噪比；五条 limits；新课 `selectivity` | 一个结构体字段加两个纯函数，爆炸半径是 `resolveLock` 这 15 行（§2.3） |
| **4b** | 资源单元粒度的频率分集 | 动的是 MU 判决那一路，不是 `resolveLock`；而它自己有一门课（§7.1） |
| **4c** | 保护间隔的选择 | 与频率选择性无关，取值已查到，**一个新常数都不要**；解除第六条 limits |

**而要说清的一点是：backlog 把这一行写成「它比原来的切片 4 大」时，
大的那部分恰好是不必做的那部分。** 「给 `linkTable` 加一个频率维度」不必做
（§2.3），「σ_τ 只能标 `model`」不必面对（§7.2）。
剩下的 4a 比 backlog 估的小，而 4b 是 backlog 完全没有估到的那一门课。

**三刀连着的前三次更正都来自有人去核而不是去继承，这一次也是：**
多径那份规格把题目留在这儿是对的，它只是在最后一步问了 σ_τ 而没有问
「标准自己用什么参数化这件事」。那两个问题的答案不一样。
