# 允许但空转：拒绝，还是钉住现状

2026-10-05。一个 **schema 收得下、而打开它之后记录流一个字节都不变**的配置，
在这个仓库里是反复出现的失效形状之一——它让一个特性看起来做完了。
先例：切片 3 的 `contention` + `rmnr`、切片 3.5 的 SRRR `RRTT` 位、SSBD 第 5 节那一批名字、
平信道上的 `selectivity`（八种合法世代配对亮着灯什么都不做）。

这类配置有**两种**正当结局：

- **在 schema 里拒掉**（`superRefine` + 一个导出的 `…Refusals` 函数）；
- **用测试把它现在的样子钉住**（`tests/engine/*-inert.test.ts`）。

两种都比什么都不做强。**但它们不是口味问题**，而在 2026-10-05 之前仓库里没有判据说什么时候选哪一种，
于是每次都是现场判断。这份文件就是那条判据。

> **这是一份约定，不是建议。** 要加一条拒绝，按下面六步走；
> 判定结果（拒还是钉）要写进那一刀的规格或提交信息里。

---

## 1. 六步

### 第一步 · 拒之前先问「有没有一门课正在演示这个配置」

**这是前置检查，不是事后发现。**

查法写明，因为这一条栽过：**扫全部课程场景与变体** —— `LESSONS` 的 `scenario()` 与
`variants[*].scenario()`，再加 `HOUSEHOLDS` 与 `defaultScenario()` ——
**不是读代码猜，也不是看任务给的文件清单。**

2026-10-05 这一刀没先查。三条拒绝落地之后 `tests/engine/tamper-inert.test.ts` 当场红了三条，
原因是 **`Simulation` 的构造函数先 `ScenarioSchema.parse` 再建任何东西**
（`src/engine/simulation.ts`）：**被拒的方案从「空转」变成了不可达**，
而那三格正是 `edca-tamper` 那一课在教的东西。

现成的探针形状见 `tests/model/driver-scenario.test.ts` 末尾那个 census：
它把 255 个方案 / 1 080 个节点逐个送进规则，并配一个「种一个违规必须抓到」的反面断言——
**一个数不出东西的普查会报出同一个零。**

### 第二步 · 只能钉住现状的两种情形

1. 这个配置是**某门课的教具**（课文让读者去点它）；
2. 它的「什么都不做」**本身就是那门课要教的事实**。

两者有一个成立，拒绝就会删掉教学内容，而不是删掉一个空配置。

### 第三步 · 拒绝的门槛是「读不到」，不是「效果小」

拒的判据是：这个字段在这条路径上**一个都读不到**——那是**接线**问题。
**效果小是物理**，不该拒；拒了就是用 schema 去表达一个本该由课文表达的判断。

实例：传统 DCF 链路上 `aifsn` / `allAsAc` / `txopLimitUs` 三个字段**一个字都读不到**（拒），
而 `cwMin`/`cwMax`、`noDoubling`、`navInflateUs` 在同一条链路上照样有效（不拒）。
**所以规则不能写成「没有 EDCA 就不许 tamper」——那会删掉真东西。**

**而且要问链路，不要问设备。** 一个特性是否可用是**两端取与**
（`negotiated`，`src/model/caps.ts`；`simulation.ts` 算 `cfg.edca` 用的就是它），
所以「旧路由器 + 新笔记本」这样的配对跑出来没有 EDCA，而站点自己的 `caps.features.edca` 是 `true`。
问节点会正好漏掉这一整类——`hasBinnableLink` 就是为这件事重写的，
当时**十六种配对里有八种**被 schema 收下且逐字节空转。

### 第四步 · 拒绝之后，物理的证据要从还合法的那一侧量得出来；量不出来就不该拒

拒掉之后那个配置再也跑不起来，于是「它确实什么都不做」这件事**失去了它原来的证据**。
**必须另有一个 schema 仍然接受的配置，能量出同一份物理。**

2026-10-05 那一次有：`greedy`（五个字段）与 `cw`（一个字段）在同一条传统链路上**逐字节相同**，
而 `greedy` 照收——这就证明了那三个字段在那里读不到。
**没有这样一侧的时候，就该钉住现状而不是拒绝**，否则是拿一条注释换掉一条测量。

### 第五步 · 拒绝必须说出该改哪里，而且 schema 与编辑器读同一份措辞

照 `selectivityRefusals` 立下的形状：**规则与它的措辞住在一个导出函数里**，
`ScenarioSchema` 的 `superRefine` 与编辑器的面板都读它。
两份措辞一定会漂，而漂的那一份一定是用户读到的那一份。

消息里要有三样：**哪个节点/哪个字段**、**为什么它在这里是死的**、**该改成什么**。
编辑器那一侧要把它渲染在控件旁边，**红字、在屏幕上，不是 title 提示**——触摸屏没有悬停。

### 第六步 · 让句子变长的那一刀，要负责渲染

2026-10-05：拒绝消息比旧的 schema 消息长了一个数量级（最长一条 150 字以上），
而载入失败那段渲染原样打印 `String(err)`，也就是 `ZodError` 的 JSON。
它是既有代码、对所有规则一视同仁——**但是这一刀让它变得难读的，所以归这一刀修**。
**「既有的」不是「不归我」。**

## 2. 2026-10-05 那一刀的分法，当例子

| 配置 | 结局 | 为什么 |
| --- | --- | --- |
| `gameAccel` 贴在非接入点上 | **拒** | 引擎只读 `ap.gameAccel`；没有课在演示它；UI 本来就不给点 |
| `tamper` 贴在非站点上 | **拒** | `simulation.ts` 显式丢掉；没有课在演示它 |
| `tamper` 的每个字段在这条链路上都读不到 | **拒** | 接线问题；而证据从 `greedy ≡ cw` 那一侧仍然量得出来 |
| `gameAccel` 打开而房间里没有游戏流 | **钉住** | 编辑器里的合理中间状态（先勾路由器、再给手机加流），拒了会让编辑器难用 |
| `noDouble` 在不会碰撞的场景上 | **钉住** | 场景会不会碰撞，schema 看不见 |
| `txopHog` 在队列只有一帧的场景上 | **钉住** | 同上，**而且它是 `edca-tamper` 的一个变体** |
| 零时延服务器 ≠ 没有服务器 | **钉住** | 它是「反向」那一条：证明开关真的接上了 |
| 无人可达的服务器列表 | **钉住** | 场景自己不写它就行；拒它要看业务档位，是另一类判断 |

## 3. 渲染那一侧的一个已知坑：zod 会短路

`scenarioLoadIssues`（`src/editor/planOps.ts`）把失败渲染成一行一条的句子：
`custom` 的 issue 只印 `message`（本仓库自己写的整句中文，`path` 只是路由标签），
其余印 `path：message`（zod 自己生成的文本离了位置没用）。

**但有一件事它修不掉，写在这里免得下一个人去绕：zod 在节点级类型错误时会短路。**
`superRefine` 只在基础解析成功之后才跑，所以一个方案**同时**有「某个枚举写错」
和三条自定义拒绝时，**只印得出前者**——而用户会以为自己只有一个毛病，
改完再载入又看到三条新的。

这是 zod 的行为，不是渲染的缺陷。**不要为了一次全印出来去拆 schema 的分层**：
那会把类型保证让出去，换一个更差的交易。

## 4. 这份文件在代码里的三处入口

这条判据是给**写下一条拒绝的人**看的，所以它在那个人的必经之路上各留了一行：

- `src/model/scenario.ts` · `ScenarioSchema` 的 `superRefine`；
- `src/model/scenario.ts` · `selectivityRefusals` 的 docblock；
- `src/model/scenario.ts` · `driverRefusalsFor` 的 docblock；
- `src/model/scenario.ts` · `ancillaryRequestRefusals` 的 docblock（2026-10-05 切片 3d 加的第三个导出函数）。

入口数跟着**导出函数**长，不跟着规则条数长：`superRefine` 里每读一条规则就再写一次这个路径，
会把那个计数变成一个没有意义的数（`tests/model/driver-scenario.test.ts` 把这一条钉住了）。

`.superpowers/sdd/LESSONS.md` 里只留一行指过来，**不留第二份正文**：
两份正文会分叉，而分叉的那一天没人知道哪份是真的。
