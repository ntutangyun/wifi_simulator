# 课文里印出来的每一个数，有没有人管

这份文件只回答一个问题：**一门课印在读者眼前的某个数被改掉一位，整套测试会不会变红。**

它不是一条检查，而是一笔账。检查的那一半在 `tests/course/prose-readback.test.ts`——它钉的是
「每门课的测试至少**看过**它自己印出来的字」，而那条规则在自己的注释里就写明了它弱在哪里：
没有任何语法检查能分清「核过」和「提到过」。充分的那一半只能靠量：**栽一桩，看它红不红。**

量具是 `scripts/figure-planting.ts`。

```
npx tsx scripts/figure-planting.ts --census          # 全课按暴露面排序
npx tsx scripts/figure-planting.ts cca               # 扫一门（连它自己声明的邻居一起跑）
npx tsx scripts/figure-planting.ts cca --own         # 只跑这门课自己的测试，快得多
npx tsx scripts/figure-planting.ts cca --own --sample=6   # 抽六个数估个比例
```

## 什么算「印出来的数」

字符串取自 `lessonTexts`——课程自己那套「读者读到的字」的遍历——所以节点 id、泳道键、枚举值
永远不算：那是代码，不是课文。偏移量靠在课文模块文件里找到那个字符串拿到，于是三类数自动
落选，而这三类恰好是 2026-10-12 第一次全课普查撞到的三类假阳性：

1. **插值出来的**（模板字符串里由常数算出来的）：它不可能漂，也不在文件里以文本形式存在。
2. **条款号、章号、文档号**：本仓库没有标准正文可核，栽了绿也说明不了任何事；单独计数。
3. **名字里的数字**：「Wi-Fi 6」「4096-QAM」「802.11-2024」「4× LTF」「SP0」。它们不会差一，只会写错
   名字，而那是用词规则（`docs/course-wording-contract.md`）的事。这一条是量出来的：`@nav`
   起初报的两个「未钉」都是 Wi-Fi 6 的那个 6，而输出里只要有一行需要读者跳过，这份输出就
   没人会读。**这一类的代价可以很大**：`@uwb-uwbd` 报 175 个数，其中 **42 个是 4ab 草案那种包
   的名字「SP0」里的 0**——占这门课四分之一，而它们每一个都要花一次 3 秒的运行去栽。补一条
   `SP`／`sp` 规则就都没了。所以这条规则该在**扫之前**补，而发现它的办法是扫到一半去看一眼
   名单：栽桩的顺序就是课文的顺序，于是同一类假阳性会挤在一起出现。

## 五类豁免，而理由必须是论点，不是日期

* **标准给电台的界**，本仓库无从核起。例：`@ifs` 与 `@cca` 都引的「最多 4 µs 内报告」。
* **只对读者界面成立、引擎里没有对应量的数**。例：`@ifs` 的「把时间轴缩放到约 200 µs 的跨
  度」——「约」是一位有效数字，而这台仿真器里没有任何量等于 200 µs；能钉的是「时间轴真能显示
  这个跨度、它比要量的那段间隙宽、比整个回合窄」，三条都钉着。

* **内容是一个不等式的数**。例：`@txop-protect` 的 `deeper` 说「把它调到 3000、高过这里的每
  一帧」——3001 建出完全相同的场景，因为**任何高过每一帧的门限都在说同一句话**。能钉的是那
  个不等式（这个数必须大于本轮最大的帧），而那正是断言里写的；栽桩仍然会报它绿，而且应该。

* **prose 里的频段名**。例：`@link-2g` 的「这门课量到现在的每一个数，都是在 5 GHz 上量的」
  ——把 5 改成 6 会让句子变错，却不会让任何测量变错：引擎里没有哪个量必须等于它，它说的是
  「这句话在讲哪个频段」，而那是语义。可核的只是**它在引擎真有的频段集合里**（
  `LINK_EXTRA_LOSS_DB` 的键），这一门有十一处这样的位置。注意这一条**不**覆盖「6 GHz 先数到
  零」那种句子——那是一句关于某次运行的话，`@mlo` 有十处，而它们都钉着。

* **集合里任何一个成员都成立的数**。例：`@amp-slots` 的 `observe` 说「选中 Tag 3，单步走过五
  轮……三十轮里四个取值它都抽到过」。这个 3 可核为「它是本场景真有的一个标签」，但那是个六元
  集合，而**那句话对六个标签里的每一个都成立**，所以它承载的信息不超过「某个标签」。这一类与
  第二类不同：引擎里有这个量，只是这句话没有挑出它。**而豁免的纪律是把这件事量出来**——断言
  读出课文点的那个标签，再对全部六个逐个核那句话成立，于是「随便哪个都行」从一句借口变成一条
  结果。

五类都要把论点写在断言旁边。扫描会一直把它们报成「未钉」，这是对的：**账上留着，比从账上
消失好。**

## 这一程找出来的假话

每一条都是**课文说了一个数，而仿真器说的是另一个**。它们之所以能活到现在，是因为断言钉的是
那句话存在的理由，而不是那个数。

| 课 | 课文写的 | 仿真器给的 | 为什么没人发现 |
| --- | --- | --- | --- |
| `@ampdu` | 36 个子帧 | 34 | 断言核的是「比 1 个多」 |
| `@airtime` | 本轮 254 个回答 | 116（254 是 `@ifs` 那台站点的数） | 扫描把它标成「maybe」，因为 254 确实出现在 `tests/` 里——是另一课的另一个量 |
| `@rts-cts` | 保护帧「恒为 24 Mb/s」 | 本轮 24／12／6 三档都有 | 只核了第一帧 |
| `@rts-cts` | 两个 RTS「相隔不到四个时隙」 | 最宽的一对正好四个 | 「不到」与「不超过」之差 |
| `@nav` | TXOP 保护那一句 | 与引擎相反 | 见该课测试的 docblock |
| `@uwb-acquisition` | 路由器「距锚点 1.1 m」 | 3.04 m（1.1 m 是它被挪走之前的位置） | 断言核的是「离锚点比离标签近」，那句话仍然成立 |
| `@uwb-acquisition` | 32 那一行「−2.858 dBm」 | −2.857 | 那个数是 −2.490 − 0.368 算出来的：**两个已经四舍五入的数相减** |
| `@uwb-acquisition` | 步骤表「带 SFD，余量 26.7 dB」 | 26.5 | 同一课的 `tryThis` 三段之后写的是对的 26.5；上一次修 `tryThis` 的时候只读了 `tryThis` |
| `@fading` | 掉帧率「是瑞利的 2.5 到 4 倍」 | 五个种子逐个是 2.539／2.553／2.934／3.802／**9.488** 倍 | 断言核的是**方向**（每个种子上莱斯都高于瑞利），而那正是这一课写在测试开头的验收闸门，所以它一直是绿的；那个倍数区间从来没人核过——而它紧挨着「五个种子逐个成立」，读者会把它当成逐个成立的那件事 |
| `@selectivity` | `margin` 那条词条「本课五档各 3.62 dB」 | 本课自己五轮是 6.617／3.617／3.617／3.617／3.617 ——最窄那一档高出整整一级 | 那个 3.62 确实是课文印的那张掉帧率表的余量（四十五次运行按余量池化出来的），而词条把它说成了「本课五档」。同一门课两屏之后自己写着「这一课的场景只有五轮，余量并不这样齐」，测验的解释也靠这句话——于是一门课的词条与它自己的测验互相矛盾。看守它的断言读的是「词条里的那些 dB 与表头里的那些 dB 相等」，两边都是 3.62，所以它永远绿 |

| `@uwb-slot-budget` | `tryThis`「两个都是 3 的整数倍，也都宽过容量规则」 | 282 RSTU 是 235 000 ns，而容量规则要 236 803——它差 1.8 µs，根本没过 | 这一课自己的测试**早就知道**：它断言 282 会被 schema 挑出**两条**毛病（下限那一条，加上「235.0 µs 装不下 236.8 µs」那一条），而 285 只有一条。那条断言钉的是 schema 的行为，没人拿它去读 `tryThis` 那句话；而那句话的上一句（步骤四「285 与 282 都过得了」）说的是**另一条规则**——3 RSTU 的整数倍——两句话紧挨着，读起来像在说同一件事 |

| `@uwb-contention` | 测验一的解释「把实测的 5.23 代回去得到 1.54」 | 把 5.23 代进那条公式得到的是 1.55；1.54 是**逐轮代回再平均** | 两者只差 0.01，而差的那一点正是公式的曲率（Jensen）。课文那张表自己的那一列也叫「按这个人数的期望」，而这一课的测试早就是按**逐轮**算的——于是数是对的，错的是那句话描述的运算。改成「按每一轮实测的竞争者数逐轮代回去，平均是 1.54」 |

这张表里有三条是**同一门课自己反驳自己**（`@uwb-acquisition` 的 `tryThis` 三段之后写的是对的
26.5；`@selectivity` 的词条与它自己的测验互相矛盾；`@uwb-slot-budget` 那一句的隔壁就是它自己的
测试断言的「282 会被挑出两条毛病」），而这是这一程最值得记住的形状：一个数在课文里出现两次
而只有一次被读，于是另一次可以长年是错的。所以每一门课的收尾动作都是同一个——把每个数在
**全课所有文字里的每一次出现**都读一遍。

**2026-10-13 扫了十七门课，而这张表只加了最后那一行。** 前十六门（`@uwb-dl-tdoa`、
`@link-2g`、`@uhr-rate-ladder`、`@amp-slots`、`@uwb-uwbd`、`@amp-backscatter`、
`@uwb-mms-numbers`、`@amp-coexist`、`@uwb-coexist`、`@uwb-sstwr`、`@uwb-dstwr`、`@width`、
`@uwb-nba-coexist`、`@uwb-geometry`、`@uwb-aoa`、`@uwb-ssbd`，合起来两千多个数）一处假话也
没找到——找到的二十几处全在**断言**里（见下一节）。读回写到第二轮之后，缺陷就从课文搬到了
测试里。

而 `@fading` 那一行值得单独说一句，因为**它不是器具找出来的**。器具只能发现「没人看着的
数」；这个数是**有人看着的，而看它的那个断言读的是另一件事**（方向，不是倍数）。把它逼出来
的是写读回的那一步本身：要读「2.5 到 4 倍」，就得先量出那五个比值，而一量就对不上了。
**所以读回不只是把缺陷从课文搬到测试，它本身也是一次测量。**

## 容差、以及一个成员测试有多窄

上面那张表里的每一条都是课文错了。下面三条是**断言错了**——它们读的是对的那个数，却用了一
种任何一位改动都能通过的方式去读。三条形状不同，但都是同一句话：**一个成员测试的强度等于它
那个集合的窄度，而一个容差的强度等于它和印出来的位数的差。**

* **容差比印出来的位数粗。** 器具栽桩的办法是**把最后一位加一**。所以 `toBeCloseTo(x, 1)` 去
  核一个印到两位小数的数，是按构造必绿的：`+8.18 %` 改成 `+8.19 %` 还在容差里。
  `@uhr-rate-ladder` 起伏表那两列六格里有五格是这样绿的——而它们本来是这个文件里最贵的测
  量（每格四十次三百毫秒的仿真）。改法是从印出来的那个字符串数出小数位数，拿
  `toFixed(dp)` 去比；这六格一次就对上了，也就是说那张表本来就是准的，只是没人真的在核它。
* **成员测试用了更宽的那个集合。** `@uhr-rate-ladder` 的 `sources` 说那张草案表里「7 行是本
  仿真器已有的档（−79 / −77 / −74 / −70 / −66 / −64 / −59 dBm）」，而断言拿它们去对**十八档
  那条阶梯**的灵敏度。四个新档的灵敏度也在那条阶梯里，于是栽出来的数常常正好落进集合。
  「本仿真器已有的档」指的是**十四档那条**，换过去之后还多出一件事：十四个值**两两不同**，
  所以点了七个就等于点了另外七个——「MCS 0、6、9–13 不在那张表里」从一句只能核个数的话，变
  成了可以逐个核的话（留下来的七行的灵敏度多重集必须正好是印出来的那七个数）。而我上一轮写
  在注释里的「MCS 6 与那七行里的一档都在 −70 dBm」本身就是用错尺子量出来的：−70 在十八档里
  是索引 6，在十四档里是索引 4。
* **成员测试的那个映射不是单射。** 同一课十余处「调制＋码率」原来核的是
  `234 × 每子载波比特数 × 码率` 落在两条阶梯的 N_DBPS 里。可这个映射会撞：把「256-QAM 2/3」
  改成「256-QAM 2/4」得 936，而 936 就是粗阶梯的 64-QAM 2/3——**一个真的档**。十六处这样绿
  的。改法是不核算术而核**字符串**，集合是课文自己把「调制＋码率」和「它是哪一档」印在一起
  的那三处（表的那一列、「同一个数字 7」那一句、两条阶梯顶上的 4096-QAM 5/6），每一处都在断
  言里对着引擎重新验过一遍。
* **`same()` 这类「按印出来的位数比」的辅助函数，只能喂给它从课文里读出来的字符串。**
  `@uwb-coexist` 的 `sources` 说「一米处 46.7 dB……6 GHz 再加 1.2 dB」，而断言把两项加起来再交
  给 `same()`——可 `String(46.8 + 1.2)` 是 `'48'`，于是比较降到了整分贝，被栽的 46.7 → 46.8 照
  旧绿。**算出来的和没有「印出来的位数」这回事**；要按两个加数自己印到的位数去比。这是上一条
  （除法加四舍五入）的同一个病根：精度是从哪里来的。
* **`dB` 是 `dBm` 的前缀。** 读「N dB」的模式会把「−62 dBm」也收进来，于是一条 SIR 门限的断言
  拿到了能量检测门限的值。写 `dB(?!m)`。同一类还有 `ms`／`µs`、`m`／`MHz`——**单位要把它后面那
  一个字符也管住**。
* **用一个占比（或任何别的商）去读一个时长，会在四舍五入处失明。** `@amp-coexist` 的「同样
  4190 µs 的轮就要预留信道的 20.95 %」只通过那个占比读了 4190——可 4191 µs 除以 20 ms 是
  20.955 %，而 JavaScript 里 `(20.955).toFixed(2)` 正好是 `'20.95'`，于是被栽的那个数又
  round 回了印出来的那个。**一个数除以另一个数再四舍五入，会把最后一位的改动吃掉**；时长要对
  引擎直接读，占比另算。
* **断言是一条对任何取值都成立的恒等式，就什么也没钉住。** `@amp-backscatter` 的「把激励抬高
  10 dB，它要在上面分辨回应的那个底也抬高 10 dB」被读成了「底抬高的量等于激励抬高的量」——而
  这对**任何**一个抬升都成立，于是 10 改成 11 照旧绿。这一条比「内容是不等式」更隐蔽：不等式
  至少排除一半取值，恒等式一个也不排除。让那个 10 成为一个数的是**那个变体真的抬起来的量**。
  同一门里还有一个较弱的版本：「0 到 2^Q − 1」原来只核上界（3^Q − 1 = 8 也容得下真实最大值），
  改成等式——一秒钟里计数真的取遍 0…3，所以可核的是「最大值正好是 2^Q − 1、中间每个值都抽到
  过」。
* **点名一个运行，不等于核了它。** `@amp-slots` 的「ACWE 1 与 2 下公式给出 p = 1」把 1 改成 2
  照旧绿：句子变成「ACWE 2 与 2」，而 ACWE 2 的 p 确实也是 1——对三个运行做成员测试，集合里有
  两个都满足这句话。可核的形式是**它声称的那条性质、外加没有别的运行有这条性质**：「p = 1 的
  恰好就是这两个」、「只有一个运行的可达时隙少于它开出的时隙」。这是「成员测试只有它那个集合
  那么窄」的又一种形状，而窄到底就是**唯一性**。
* **一张表的读回必须连「标签」那一列一起读。** `@uwb-aoa` 的两张表上一程都是读回：日志那张
  的每一格是 `fmtRecord(记录)`，工作表那张是从第 0 轮现算出来的——而两张都只核了第 1 列。
  第 0 列里住着四个数：两个方位角的时刻、从斜距里扣掉的高度、锚点自己的朝向，一个都没人看着。
  一张表的「步骤／行」那一列看起来像散文，可它照样印数。**表的 `heading` 同样是一个窝**：`@uwb-ssbd` 的「四种设置，同一个场景，1.3 秒」就栽在那里，而那个 1.3 在课文别处读过两遍。
* **家族读法必须按「形状」匹配，不能按「值」匹配。** `@width` 把「每一个 48 µs 都是前导码」写成
  了 `/(48) µs/g` 再逐个核——可被栽成 49 的那一处**直接从匹配集合里掉出去了**，剩下几处照旧满足
  计数与断言，于是四处全绿。一个把值写进模式里的家族读法，只能看见没被改过的那些。按句子周围的
  字去读（「四条道上的前导码是同一段 (…) µs」），或者按 `(\d+)` 匹配再要求它落在一个窄集合里。
* **正则里有一个没被捕获的 `\d+`，就是一个洞。** `@amp-slots` 的
  「占每 20 ms 的 20.95 %，而不是每 100 ms 的 4.19 %」 读的是那两个百分数，而两个间隔写成
  `占每 \d+ ms 的`——**匹配上了，却从没被比较**，于是 20 改成 21 照旧绿。同一门的
  「整整 600 ms 只送达 7 个读数」 一样。这一类最骗人，因为那个数就明明白白写在正则里，看起来
  正在被读。筛它只要一分钱：**把每个正则的捕获组去掉，看还剩不剩 `\d`**（这一程写了个十行的
  脚本，对四个已读回的文件报 8 处，其中 2 处是真漏、6 处是辅助函数与另一处已读的同一个数——
  所以它是个提示，不是一次测量）。还有一条连带的：**同一个数第二次印出来就是另一处**，所以
  「这个数在别处读过了」不算读过它。
* **注释夹在名字和数之间。** 上一条改完复扫，那四个数里还有四个绿的，而它们都在 `picture`
  里：课文按用词规则在**第一次出现**那里给术语注英文——「QPSK（quadrature phase-shift
  keying）2/3」——于是英文夹在调制与码率之间，一个要求两者相邻的模式刚好跳过了最该读的那两
  对。这一条**对全课都成立**：凡是按「名字紧跟着数」去读的断言，都会在每个术语的第一次出现
  那里漏一次，而第一次出现往往正是课文最用力的那一处。摘注释的时候还有一个坑——把
  「（…）」换成空串会留下「QPSK2/3」，它得换成一个空格，因为括号本来就站在那个空格的位置上。

* **用解析出来的数拼回去的针，对任何数都成立。** 没有语料的引用只剩一条可核的事实——「这个串
  在课文里出现的次数正好是它该出现的次数」——而 `@uwb-subrounds` 那条会议纪要的表决
  「以 12/13/1 被否决」我是这么写的：先把三个数解析出来，再用 `${yes}/${no}/${abstain} 被否决`
  去数出现次数。那个针是**从课文自己印的数拼回去的**，于是无论课文印什么它都成立；栽第二位与
  第三位都没有红。针必须写死在测试这一侧，而写死一个针与「用一个字面量去核一个可测的数」不是
  同一件事：前者是这类引用**唯一**的器具，后者是在偷懒。顺带还留一条语义的：否决意味着反对多于
  赞成，这一条钉得住第一位，而且与那个串无关。
* **`every(..., n)` 那个 `n` 只证明模式自己数得全，不证明那个数印了几次。** `@wan-rtt` 的
  「单向 12.5 毫秒」印了三处：`picture` 的「建成单向」、步骤里的「走单向」、以及「答复再走一次」。
  我的模式写了前后两种说法，于是它匹配到两处，而 `every(..., 2)` 拿到的正是 2 —— 断言通过，第三
  处一个人也没读，栽进去就是绿的。**这个数的断言强度等于模式的覆盖面，而计数断言量的是模式，
  不是课文。** 办法只有两个：模式按「这个数后面的单位」而不是按前面的说法去写（`([\d.]+) 毫秒`
  再按上下文分流），或者扫完之后拿器具报的那一处回来补——而扫描正是这一条唯一的证人。

**写完一段读回，扫之前先过这七问。** 每一问都是上面某一条的反面，而它们合起来能省掉一整轮
扫描（一轮是几分钟到两小时）：

1. **容差有没有比印出来的位数粗？** 两位小数的数不能用 `toBeCloseTo(x, 1)` 去核。
2. **成员测试用的是最窄的那个集合吗？** 能不能核唯一性（「有这条性质的只有它一个」）？
3. **正则里有没有匹配上却没被捕获的 `\d`？** 把捕获组去掉，看还剩不剩数字。
4. **这个数在课文里印了几次？每一次都读了吗？** 第二次印出来就是另一处；注释可能夹在名字和数
   之间（「QPSK（quadrature phase-shift keying）2/3」）；同一句话里也可能印两遍
   （「脉冲多 4.3 倍，10·log10(4.3) = 6.33 dB」）。
5. **它能不能被某个集合里任何一个成员替掉？** 如果能，那就是第五类豁免，而豁免要把「随便哪个
   都成立」对全集核一遍。
6. **这条读法的针，是不是从课文自己印的数拼出来的？** 如果是，它对任何数都成立。
7. **`every(..., n)` 里的 `n` 是从哪里来的？** 如果是「模式匹配到几处」，那它什么也没证明；要
   先独立数一遍这个数在课文里印了几次（`--list` 的输出就是这个），再把 `n` 写成那个数。

## 最后一列不是证据

扫描会给每个「未钉」的数标一列：这个数值在 `tests/` 里有没有数值相等的字面量（按单位换算的
几种标度都试过）。**一个在整个 `tests/` 里都找不到相等字面量的数，确实没有任何东西钉着它。**
反过来不成立——相等可能只是巧合，而**这个器具找出的第一个真缺陷就在「maybe」那一列**：
`@airtime` 的 `limits` 写「本轮 254 个回答一个不差」，而那个场景在这一课统计一切的窗口里只
回答 116 次，254 是 `@ifs` 那台饱和上传站点的数。扫描之所以标它「maybe」，是因为 254 的确
出现在 `tests/` 里——作为 `@rate-fallback` 的 ACK 超时次数，另一课的另一个量。

## 要做的事，按什么顺序

按**读者暴露面**排，不按未钉数：一门课印 300 个数而读者只看三张表，和一门课印 30 个数而每一
个都在正文里，不是同一笔债。暴露面的近似值就是 `--census` 的第一列（印出来的数），而第二、
第三列（条款号、算出来的）是提醒：那两类不用栽。

器具这一程长了两样东西，都是被一门课逼出来的：

* `--list`：只列出这门课印了哪些数、不栽桩。写一门课的读回要先把整张单子摊开，而一次全扫要
  十几分钟——在它存在之前，已经三次为此临时写脚本了。
* 两条新的「这不是一个可核的数」规则，都是扫描把一条引用报成未钉之后加的：`JSAC` 与
  `INFOCOM` 跟 `IEEE`／`Std` 并列（`@bianchi` 印着「IEEE JSAC 18(3):535–547，2000」与
  「Wu 等人（INFOCOM 2002）」，本仓库对它们都没有语料）；以及**紧跟 `-NN` 的数是条款号或式
  号**（「按式 17-29」）——这一条判的是它后面，不是前面那个「式」，因为「路径损耗公式 46.7」
  在左边读起来一模一样，而那是个模型取值。
* **同一处字面量被读者读到两次**时只算一处。`@radio-primer` 把 67.7 既印在表里也印在那张由表
  生成的图里，而文件里只有一个 `'67.7'`——于是「整套一起栽」那一次探测抛了
  `offset drifted at 5978: found 67.8`：前一次替换已经把这一位挪走了。它在写文件之前就抛了，
  所以没有留下栽桩，但在修好之前这门课根本扫不动。

**第一遍总是差 15–25%，而补的那一遍每次都是同一个动作。** 这一批七门课的第一遍分别留下
36／181、0／143、18／129、18／107、6／99、38／83、25／71 处未钉，而补读的内容几乎全是同一类：
**同一个数在课文里印了四五遍，而第一遍只读了它被推导出来的那一处。** `@streams` 的「88.8 µs」
印四遍、「2 条流」六遍、「20 MHz」五遍；`@small-frames` 的「21 502 B」印六遍，而且这四处在整个
`tests/` 里连一个相等的字面量都没有（这个测试文件 import 了 `BURST_BYTES`，从不打出那个数）。
所以这一程得出的做法是：**先写「每一次出现都读」，再回头处理那些需要单独论点的数**。

**而第一遍差得最多的那一次（`@uhr-rate-ladder`，59／175）差的不是这个。** 那门课的补读照上面
这条做法写了，可它第一遍仍然留下三分之一——因为留下的不是「印了四遍读了一遍」，而是**三种一
眼像钉住的断言形状**（容差比印出来的位数粗、成员测试的集合太宽、成员测试的映射不是单射，见上
「容差、以及一个成员测试有多窄」）。所以这一条要补一句：**写完「每一次出现都读」之后，还要回
头看自己写的每一个断言能不能被改掉一位的数满足**——而这件事只有器具答得了，不是读一遍能看
出来的。那门课四遍复扫 175 → 59 → 9 → 4，合起来 255 次运行，比一次全扫（244 次）只多一点。

每门课的成本，实测：扫描是「这门课自己的测试跑一遍」乘以「可栽的数」，而**第一个因子在课与课
之间差十倍**——所以排下一门的时候要连它一起看：

| 25 秒（`@uhr-rate-ladder`，二十个种子乘两条阶梯） | 244 | 约 1 小时 50 分 |
| 39 秒（`@claim-to-contribution`） | 223 | 约 2 小时 30 分 |

**试过一个不用扫的筛子，不值得。** `@amp-slots` 的那个形状（课文抄在注释里、断言对着自己这一
侧的字面量）看起来应该能不扫就看出来：把测试的注释与字符串剥掉，数一数课文印出来的数有多少个
在**代码**里又被打了一遍。写出来一量就知道这个筛子不能用——已经整门读回完的 `@uhr-rate-ladder`
（真实成绩 4／244）照样报 35 %，`@queues`（真实成绩 0）报 69 %，因为一条读回的断言旁边照样会有
常量、容差和脚手架里的数。**它只能排个大概的先后，不能当成一次测量**；真正的判据仍然只有栽桩。
这一条记在这里，是为了别人不必再写一遍。

所以慢课要换个走法：**先扫一遍拿到名单，再用 `--saved` 只复扫名单上的那些**（`@bianchi` 是
14 次而不是 129 次），而真正的成本仍然是写那一段逐处读回的断言，它和课文一样长。

**而「这门课的测试跑一遍」要连它 declared 的那几个文件一起算，那一项可以反过来压倒它自己。**
器具扫的是 `own` 加上**这门课的测试文件里提到的每一个测试路径**，而那里面可能坐着一门很贵的
课：`@fading` 自己的测试跑一遍 13 秒，而它 declared 了 `tests/engine/lesson-hashes.test.ts`
与 `tests/course/claim-to-contribution.test.ts`（后者单独就要 39 秒），于是一次全扫是 145 乘
约 70 秒——将近三个小时。做法是器具自己的文档里早就写着的那一条，只是我第一次没照着做：
**先 `--own` 只对自己那一个文件扫一遍（31 分钟），拿到名单，再用 `--saved` 带上全部 declared**
文件复扫名单上的那几个。`--own` 给出的是未钉数的**上界**（文件少了，更多数看起来没人管），
`--saved` 再把它收到真值，两步都是可复现的。

**改一句课文要付三处契约。** 2026-10-13 那五处假话改完，全课跑下来三个文件七处红，而七处全是
课程自己的契约在说话：**分钟数**（`@selectivity` 那条词条我改长了五十个字，它的 raw 分钟就从
29.9x 变成 30.05，而「超过 `MAX_MINUTES` 的课」这个集合是被断言钉死的——按 `curriculum.ts` 自己的
规矩，过了三十分钟就是在讲两个题目，答案是拆课；所以改文要写短）；**术语的英文注**（重写一段时
把「退避（backoff）」整个删掉了，而官方术语必须在**首次中文出现处**带英文名——新写的句子第一次
用上「时隙」，也得带「（slot time）」）；以及**覆盖表里那几个「量出来的」数**（全课程主路径汉字、
它除以 91 的均值、以及那一门自己的字数）。还有一处是这份文件自己的：`doc-citations.test.ts` 要求
契约文档引的路径指得到东西，而我写的 `probes.local/...` 是器具的本地目录。**所以每修一处假话，
`readability`、`wifi-coverage` 与 `doc-citations` 这三个文件都要跟着跑一遍**——它们在全课层面
互相咬着，而一处改文看起来只动了一句话。

**两个扫描不能同时跑，哪怕它们栽的是两门不同的课。** 2026-10-13 夜里试过一次：`@uwb-sts` 的扫描
正在栽它自己那一课，而我同时让 `@ofdma-ul` 的 `--saved` 跑起来——后者在基线那一步就抛了「the tests
are already red」。原因是每个扫描跑的那一组测试里有走遍**全部课程**的那几个（`lessons.test.ts`、
`prose-readback.test.ts` 之类），于是另一门课此刻被栽着的那一位数把它们读红了。更坏的是它留下的
后果：那一次失败把器具保存的那份未钉清单清掉了，于是 `--saved` 从此无从重跑，
只能重新全扫一遍（七分钟）。**一次只跑一个扫描；要并行就等它报完。**

**半路掐掉一次扫描，会把当前那一处栽桩留在课文里——而且掐掉外壳并不等于掐掉扫描。** 器具每一
步都是「栽 → 跑 → 还原」，所以它跑完会自己打一行 `restored; final check green`；而把进程杀掉
的那一刻，正在栽着的那一处就留在了文件里。这一条本来就记着，而 `@fading` 这一程教了它后半句：
把后台 Bash 任务停掉只杀了外壳，`tsx` 那个子进程照旧一个数一个数地往下栽。于是我**连着改回去
三次，每一次改的都是它早就走过的那一处**，直到发现 `git diff` 一直在动。所以规矩是：掐掉扫描
之后反复 `git diff src/`，直到它不再变；要么干脆让它自己跑完（它会自己还原）。要是真得杀，就
按**启动时刻**认出它那几个 `node` 进程来杀，别按名字杀——这台机器上还坐着别人的 vite。一条便
宜的出路是挂一个看门的：

```
until [ "$(git diff --numstat <课文> | awk '{print $1" "$2}')" = "0 0" ]; do sleep 20; done
```

放到后台，等它通知。而不论哪条路，收尾动作都要能一眼分清哪一行是栽桩、哪一行是自己有意的改
动——这也是「课文的改动与读回分两次提交」值得坚持的理由之一。

## 这份文件自己的纪律

* 表里的数都要是量出来的，而且量法要写明（抽样还是全扫，跑了哪些测试文件）。
* 一门课修完要复扫，并把两个数都留在表里（修前／修后）——`@airtime` 的「74 → 0」是这张表最
  有用的一行。
* 扫描中途被杀会在课文里留下一处栽桩（器具就是这么设计的：崩在半路要留下看得见的桩）。
  **长扫描一律写日志文件，不要把输出接到管道上**，并且结束后 `git status` 看一眼。
* **扫描在跑的时候不要读那门课的课文。** 扫描开头有一次「整套一起栽」的探测，那一刻**课文里
  每一个数都比真值大一**，而这正好是一个细心的读者能在每句话里都「发现一处假话」的状态：
  2026-10-13 读 `@amp-backscatter` 时就这样读出了六处不存在的矛盾（「四张在 16 cm」对表里的
  15、「RN17」对别处的 RN16、「21 + 51 − 7 = 65 − 3 × 路损」对公式自己的 20 + 50 − 6 = 64 −
  2 ×）。要在扫描进行中读课文，就读 `git show HEAD:<课文路径>`。
