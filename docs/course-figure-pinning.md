# 课文里印出来的每一个数，有没有人管

这份文件只回答一个问题：**一门课印在读者眼前的某个数被改掉一位，整套测试会不会变红。**

它不是一条检查，而是一笔账。检查的那一半在 `tests/course/prose-readback.test.ts`——它钉的是
「每门课的测试至少**看过**它自己印出来的字」，而那条规则在自己的注释里就写明了它弱在哪里：
没有任何语法检查能分清「核过」和「提到过」。充分的那一半只能靠量：**栽一桩，看它红不红。**

量具是 `scripts/figure-planting.ts`。

```
npx tsx scripts/figure-planting.ts --census          # 全课按暴露面排序
npx tsx scripts/figure-planting.ts cca               # 扫一门（连它自己声明的邻居一起跑）
npx tsx scripts/figure-planting.ts cca --own         # 只跑这门课自己的测试，快得多
npx tsx scripts/figure-planting.ts cca --own --sample=6   # 抽六个数估个比例
```

## 什么算「印出来的数」

字符串取自 `lessonTexts`——课程自己那套「读者读到的字」的遍历——所以节点 id、泳道键、枚举值
永远不算：那是代码，不是课文。偏移量靠在课文模块文件里找到那个字符串拿到，于是三类数自动
落选，而这三类恰好是 2026-10-12 第一次全课普查撞到的三类假阳性：

1. **插值出来的**（模板字符串里由常数算出来的）：它不可能漂，也不在文件里以文本形式存在。
2. **条款号、章号、文档号**：本仓库没有标准正文可核，栽了绿也说明不了任何事；单独计数。
3. **名字里的数字**：「Wi-Fi 6」「4096-QAM」「802.11-2024」「4× LTF」。它们不会差一，只会写错
   名字，而那是用词规则（`docs/course-wording-contract.md`）的事。这一条是量出来的：`@nav`
   起初报的两个「未钉」都是 Wi-Fi 6 的那个 6，而输出里只要有一行需要读者跳过，这份输出就
   没人会读。

## 三类豁免，而理由必须是论点，不是日期

* **标准给电台的界**，本仓库无从核起。例：`@ifs` 与 `@cca` 都引的「最多 4 µs 内报告」。
* **只对读者界面成立、引擎里没有对应量的数**。例：`@ifs` 的「把时间轴缩放到约 200 µs 的跨
  度」——「约」是一位有效数字，而这台仿真器里没有任何量等于 200 µs；能钉的是「时间轴真能显示
  这个跨度、它比要量的那段间隙宽、比整个回合窄」，三条都钉着。

* **内容是一个不等式的数**。例：`@txop-protect` 的 `deeper` 说「把它调到 3000、高过这里的每
  一帧」——3001 建出完全相同的场景，因为**任何高过每一帧的门限都在说同一句话**。能钉的是那
  个不等式（这个数必须大于本轮最大的帧），而那正是断言里写的；栽桩仍然会报它绿，而且应该。

三类都要把论点写在断言旁边。扫描会一直把它们报成「未钉」，这是对的：**账上留着，比从账上
消失好。**

## 这一程找出来的假话

每一条都是**课文说了一个数，而仿真器说的是另一个**。它们之所以能活到现在，是因为断言钉的是
那句话存在的理由，而不是那个数。

| 课 | 课文写的 | 仿真器给的 | 为什么没人发现 |
| --- | --- | --- | --- |
| `@ampdu` | 36 个子帧 | 34 | 断言核的是「比 1 个多」 |
| `@airtime` | 本轮 254 个回答 | 116（254 是 `@ifs` 那台站点的数） | 扫描把它标成「maybe」，因为 254 确实出现在 `tests/` 里——是另一课的另一个量 |

| `@rts-cts` | 两个 RTS「相隔不到四个时隙」 | 最宽的一对正好四个 | 「不到」与「不超过」之差 |
| `@nav` | TXOP 保护那一句 | 与引擎相反 | 见该课测试的 docblock |
| `@uwb-acquisition` | 路由器「距锚点 1.1 m」 | 3.04 m（1.1 m 是它被挪走之前的位置） | 断言核的是「离锚点比离标签近」，那句话仍然成立 |

现两次而只有一次被读，于是另一次可以长年是错的。所以每一门课的收尾动作都是同一个——把每个
数在**全课所有文字里的每一次出现**都读一遍。

## 最后一列不是证据

扫描会给每个「未钉」的数标一列：这个数值在 `tests/` 里有没有数值相等的字面量（按单位换算的
几种标度都试过）。**一个在整个 `tests/` 里都找不到相等字面量的数，确实没有任何东西钉着它。**
反过来不成立——相等可能只是巧合，而**这个器具找出的第一个真缺陷就在「maybe」那一列**：
`@airtime` 的 `limits` 写「本轮 254 个回答一个不差」，而那个场景在这一课统计一切的窗口里只
回答 116 次，254 是 `@ifs` 那台饱和上传站点的数。扫描之所以标它「maybe」，是因为 254 的确
出现在 `tests/` 里——作为 `@rate-fallback` 的 ACK 超时次数，另一课的另一个量。

## 账

全课 **8 031 个可栽的数**（另有 1 886 个条款号与名字，1 752 个字符串是算出来而非打出来的），
分布在 91 门课上。

这个总数一路在降，降的是器具而不是课文：每发现一类「它根本不是一个可核的数」，分类器就收紧一
条，那一批就从「可栽的数」移到「条款号与名字」里去。最早一次普查报 8 512，2026-10-12 与 13 的五条新
规则（成组的千位分隔符算一个数；`802.11` 与 `802.15.4` 整体是标准的名字，哪怕它就是整个数；
`TG4ab` 里的 4 是工作组的名字；`JSAC` 与 `INFOCOM` 跟 `IEEE` 并列；紧跟 `-NN` 的数是条款号或
式号）把它压到 8 031。
所以**跨日期的总数不可比，同一天的两次才可比**；下面两张表里的「可栽的数」都标着它是哪一次量的。

## 要做的事，按什么顺序

按**读者暴露面**排，不按未钉数：一门课印 300 个数而读者只看三张表，和一门课印 30 个数而每一
个都在正文里，不是同一笔债。暴露面的近似值就是 `--census` 的第一列（印出来的数），而第二、
第三列（条款号、算出来的）是提醒：那两类不用栽。

器具这一程长了两样东西，都是被一门课逼出来的：

* `--list`：只列出这门课印了哪些数、不栽桩。写一门课的读回要先把整张单子摊开，而一次全扫要
  十几分钟——在它存在之前，已经三次为此临时写脚本了。
* 两条新的「这不是一个可核的数」规则，都是扫描把一条引用报成未钉之后加的：`JSAC` 与
  `INFOCOM` 跟 `IEEE`／`Std` 并列（`@bianchi` 印着「IEEE JSAC 18(3):535–547，2000」与
  「Wu 等人（INFOCOM 2002）」，本仓库对它们都没有语料）；以及**紧跟 `-NN` 的数是条款号或式
  号**（「按式 17-29」）——这一条判的是它后面，不是前面那个「式」，因为「路径损耗公式 46.7」
  在左边读起来一模一样，而那是个模型取值。
* **同一处字面量被读者读到两次**时只算一处。`@radio-primer` 把 67.7 既印在表里也印在那张由表
  生成的图里，而文件里只有一个 `'67.7'`——于是「整套一起栽」那一次探测抛了
  `offset drifted at 5978: found 67.8`：前一次替换已经把这一位挪走了。它在写文件之前就抛了，
  所以没有留下栽桩，但在修好之前这门课根本扫不动。

**第一遍总是差 15–25%，而补的那一遍每次都是同一个动作。** 这一批七门课的第一遍分别留下
36／181、0／143、18／129、18／107、6／99、38／83、25／71 处未钉，而补读的内容几乎全是同一类：
**同一个数在课文里印了四五遍，而第一遍只读了它被推导出来的那一处。** `@streams` 的「88.8 µs」
印四遍、「2 条流」六遍、「20 MHz」五遍；`@small-frames` 的「21 502 B」印六遍，而且这四处在整个
`tests/` 里连一个相等的字面量都没有（这个测试文件 import 了 `BURST_BYTES`，从不打出那个数）。
所以这一程得出的做法是：**先写「每一次出现都读」，再回头处理那些需要单独论点的数**。

每门课的成本，实测：扫描约 3.5 秒一个数（只跑本课测试），所以 50 个数的课扫一遍约 3 分钟；
真正的成本是写那一段逐处读回的断言，而它和课文一样长。

## 这份文件自己的纪律

* 表里的数都要是量出来的，而且量法要写明（抽样还是全扫，跑了哪些测试文件）。
* 一门课修完要复扫，并把两个数都留在表里（修前／修后）——`@airtime` 的「74 → 0」是这张表最
  有用的一行。
* 扫描中途被杀会在课文里留下一处栽桩（器具就是这么设计的：崩在半路要留下看得见的桩）。
  **长扫描一律写日志文件，不要把输出接到管道上**，并且结束后 `git status` 看一眼。
