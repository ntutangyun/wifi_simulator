# Wi-Fi Airtime Simulator

A browser-based, microsecond-resolution simulator of **IEEE 802.11 (CSMA/CA)** channel access inside a 3D house you design yourself — and a learning tool for how Wi-Fi actually works. Draw rooms, place an access point and stations, pick each device's Wi-Fi generation (802.11a legacy / Wi-Fi 5 / 6 / 7) and toggle its features, then watch — and scrub through — every backoff slot, AIFS wait, NAV reservation, A-MPDU burst, OFDMA trigger exchange, collision and retransmission. Hover any block in the timeline for an explanation of what it is and why it happens; the 📖 Guide tab walks through the protocol from carrier sense to MLO.

Built as a static SPA (Vite + TypeScript + React + Three.js). No backend; deployable on GitHub Pages.

## Quick start

```bash
npm install
npm run dev      # local dev server
npm test         # engine conformance test suite (vitest)
npm run build    # static production build in dist/
```

## Using it

0. **📚 Course mode** — a built-in Chinese-language course on the Wi-Fi MAC (DCF foundations → EDCA/A-MPDU/TXOP → OFDMA/MLO → ambient power IoT). Each lesson loads a purpose-built deterministic scenario next to the text, with jump-to buttons that seek the playhead straight to the teachable moment (first collision, first Trigger frame, …), observation checklists, experiments and self-check quizzes. Progress is saved locally.

   Every lesson is built to one zero-to-hero shape, so a reader always knows where they are: **why** this matters in plain words, **what you will be able to do** afterwards, **which lessons you need first** (as buttons that take you there), **the new words** with a one-line explanation each, **the picture** — the mechanism in plain language, with call-outs that load the simulation at the right moment — and only then **the numbers**: the tables, formulas and exact values. After that come the observation checklist, the experiments and the quiz, with the professional depth and the provenance (**where these numbers come from**: clauses, contributions, which values are the simulator's own choice) collapsed at the end for whoever wants them. A test enforces the shape and pins every number the lesson states against the simulator; the length is the author’s, under a 30-minute-per-lesson ceiling. See `docs/superpowers/specs/2026-09-25-course-pace-and-diagrams.md`.
1. **✎ Edit mode** — draw rooms (▭), punch doors/windows into walls, set wall materials (drywall/brick/glass), drag the AP and STAs around, assign per-station traffic profiles (video, backup, browsing, IoT, saturated), place battery-free **AMP tags** on a Wi-Fi 7 AP's 2.4 GHz link and configure its polling (slots, ACWE, DL/UL rate, protection), place **UWB anchors and tags** and set the ranging session (SS-/DS-TWR, block and slot length, channel, timestamp noise), or 🎲 spawn random stations. Undo/redo (↶/↷, Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y) covers the last 100 edits, with a pointer drag folded into one step. Scenarios persist to localStorage and import/export as JSON.
2. **▶ Simulate mode** — the engine (in a Web Worker) simulates ahead and records *every* observable micro-event. The UI is a player over that recording:
   - **Transport bar**: play/pause, slowdown from ×10 to ×10 000, and stepping **±1 µs, ±1 slot (9 µs), ±1 event, ±1 frame exchange — forward and backward**.
   - **3D viewport**: expanding wavefronts per transmission (blue = AP data, green = STA data, white = ACK, orange = RTS/CTS), node state halos, live backoff counters.
   - **Timeline strip**: logic-analyzer-style per-node lanes (TX/RX/backoff/defer/NAV) with wheel-zoom down to single-slot scale; red ticks mark collisions; drag to scrub. AMP tags get their own lane: trigger/Ack reception, an armed "slot k" wait span, and their uplink response.
   - **Inspector**: full MAC state at the playhead — backoff, CW, SSRC/SLRC, NAV, IFS, queue contents, per-node stats (or, for a tag, ABOC/ACW and sent/acked/lost counts).
   - **UWB ranging**: a second radio measuring distance rather than carrying traffic. Each tag gets a lane showing its ranging round slot by slot; the floor of the 3D scene carries one range ring per (tag, anchor) pair, the solved position as a cross and its 1-σ error ellipse (drawn at 10× — the inspector quotes the true axes), all fading out over one ranging block.
   - **Event log**: chronological micro-events; click a TX row to decode the frame.

### IEEE P802.15.4ab (draft): multi-millisecond ranging (MMS)

**Draft status.** Everything in this section is **P802.15.4ab**, an unratified draft in SA-ballot recirculation (first recirculation, September 2026). The balloted text is members-only, so nothing here is copied from it: the model is built by paraphrase from the task group's own contributions — **15-22/0381r5** (the pairwise ranging cycle, its phases, slot/round/block defaults, the listen-before-talk rule, the narrowband channel lists and the compressed PSDU formats), **15-23/0100r2** (the RSF/RIF/MMRS definitions, the N_MSR set, the 1 ms fragment spacing and the narrowband PHY configurations), **15-23/0502r3** (the mandatory operating parameter sets, proposed as 16.2.11.4) and **15-22/0205r0** (the per-millisecond energy budget and why fragments exist at all), plus five 2025 contributions for the draft features below — **15-25/0194r0** (the two control-plane configurations, the SP0-versus-SYNC+SFD acquisition comparison and the zero-length control phase), **15-25/0066r1** (RSF with SFD, and the fragment-length field renames), **15-25/0292r1** and **15-25/0331r1** (non-interleaved sub-rounds and their control phase) and **15-25/0224r2** with **15-25/0556r2** (the fixed reply time and the reversed order). The balloted text may differ in numbering and in detail; the Guide's section 12 and both lessons say so up front. Rows tagged *4ab draft* cite the contribution, not a clause number; rows tagged *model* are this simulator's own choices.

**Last checked 2026-09-26** against the task group's 2025–2026 comment-resolution documents, which quote the draft text by page and clause and are the closest public proxy for it. Four things had drifted since the contributions above: the MMS ranging phase is now §10.39.5 (it was §10.35.5, §10.36.5, then §10.38.5); N_MSR and the STS segment length are carried by fields now named **RSF Fragment Length** and **RIF Fragment Length**; `macMmsRpDuration` is derived from the fragments rather than defaulted to 20 slots; and the draft has an interleaved mode with a 500 µs offset that this engine does not model. The fragment counts were confirmed unchanged. Those five draft features are now modelled rather than absent — the NBA-MMS/UWBD-MMS configuration split (with its zero-length control phase), RSF with SFD, non-interleaved sub-rounds, MMS Fixed Reply Time and reversed MMS order — each one off by default, so every plan stored before them replays as the session it was, and each with a row of its own below naming the contribution it came from. What is still absent rather than contradicted is the interleaved mode's 500 µs offset. See [the standard-basis note](docs/superpowers/specs/2026-09-26-uwb-standard-basis.md) for the method and the evidence.

### Known simplifications

- No beacons/association (pre-associated BSS), no power save, no MU-EDCA/BSR (the OFDMA scheduler reads STA queues directly as a BSR stand-in).
- 20 MHz channels only; PPDU decode is all-or-nothing per receiver (per-MU-part thresholds for OFDMA); receivers lock the first decodable preamble.
- OFDMA RUs modeled as 1/n rate scaling; MLO is STR with a simplified 6 GHz path-loss offset; wall openings are full-height gaps.
- TXOP NAV covers one exchange at a time rather than the full TXOP remainder.
- 2.4 GHz always uses the 9 µs short slot (no 802.11b stations are modelled); the 6 µs signal extension is modelled as occupied medium, so a PPDU overlapping only another PPDU's extension counts as interference.
- AMP models the Active Tx non-AP AMP STA and mono-static backscatter (an EPC Gen2 inventory tunnelled in AMP RFID frames); bistatic backscatter, the energizer, wireless power transfer and energy harvesting are not implemented yet.
- AMP is a draft (P802.11bp D0.5/D1.0): the tag's −72 dBm downlink sensitivity and the OOK SINR thresholds (decoding requirements the draft does not publish) are model choices, not standard values.
- A tag finds its slot by counting AMP Acks in arrival order rather than reading a slot number off them; the draft leaves ABOC retransmission behaviour TBD, so a lost response draws a fresh ABOC next round.
- Backscatter timing is nominal: the tag's ±10 % clock (100 000 ppm, SFD PM-28) is stated, not drawn as per-reply jitter, and T1 (16 µs) is fixed rather than resampled every reply.
- EPC Gen2's Q-adaptation (QueryAdjust) is not modelled: Q is a scenario knob the run holds fixed, not something the reader retunes from what it hears.
- Backscatter path loss below 1 m uses free-space (Friis), not the indoor Wi-Fi law, clamped at a 5 cm floor so a tag pressed against the reader does not divide by zero.
- A backscatter DL PPDU is transmitted at two powers in one frame — `chargeDbm` through AMP-Data, `bsDbm` during the BST-Excitation — a model reading of 11-25/0307r0's PEX_C/PEX_B split, not something the SFD's frame format spells out byte for byte.
- The reader's mono-static energy detector (deciding a collision from silence when no reply is acquired) reads the same leakage-floor threshold the demodulator uses; the draft does not specify how a real receiver tells the two apart.
- UWB ranging schedules are either time-scheduled — every slot assigned before the session starts, so two UWB devices never collide — or contention-based (schedule mode 0), a shared response window responders draw a slot from at random. Even the contention schedule has **no CCA**, no backoff and no NAV: the draw is uniform-random against a fixed window and retry budget, not carrier sensing.
- UWB reception is sensitivity-only against another UWB frame: a frame is received when it clears −93 dBm, and interference from another UWB transmission is a 6 dB capture margin — there is no UWB SINR curve or multipath channel model there. Wi-Fi 6E / UWB channel-5 coexistence is a separate, cruder model: flat spectral density inside each side's band, path loss from the *transmitter's* own table, and no adjacent-channel leakage (an emission is either inside a band or contributes nothing to it).
- Positions are solved in 2-D with the tag's z taken from the scenario. AoA is a single two-antenna pair on the horizontal plane only: no elevation (the antennas differ in azimuth, not height), no multipath phase (the model adds one Gaussian noise term straight to the true phase rather than simulating a channel), and no third antenna or second axis to resolve the front/back mirror — pointing the anchor's yaw at the room is the only defence.
- NLOS is one excess delay per wall crossed, not a delay spread: no first-path/strongest-path split, no leading-edge detection and no ranging bias calibration. The FoM is a two-valued model mapping (LOS / through-a-wall) and is reported, never used by the solver.
- DL-TDoA's per-message RX/TX counter content and UL-TDoA's "wired sync" are model, FiRa-style choices, not something the standard's §10.29.1.2.5 spells out byte for byte; the overlay draws only the fix and its 1-σ ellipse, never the hyperbolae themselves; and a UL-TDoA anchor's `syncErrorNs` is a fixed per-anchor bias, not white noise that repeated blinks average away.
- STS key management, round hopping, LRP UWB, DS-TWR under a contention schedule (its report would need a second contended window) and multi-node round scheduling beyond one round per tag are out of scope.
- Timestamp precision follows SNR only in shape (a Cramér-Rao-like √(SNR_ref/SNR) scale on `tsNoisePs`, floored at 1× and capped at 10×, model): a fragment train sharpens a stamp only through its combined SNR, and the draft's headline "ToF accuracy improvement" figures are not reproduced.
- The MMS cycle is pairwise by default and one-to-many with `mms.oneToMany` (one initiator, every anchor of the session, one round per tag). What is still not modelled: the initialization handshake (ADV-POLL / ADV-RESP / SOR), public advertising, acquisition packets and short-term parameter negotiation — the session is configured by the scenario, as every session here is — and the draft's other one-to-many POLL variants (explicit per-responder slot ranges, access slots, the switched Poll/Response order). A one-to-many round's responder list is the session's anchors in scenario order, never negotiated.
- The narrowband radio's path loss is free space at the channel centre plus the same wall attenuation UWB uses; its listen-before-talk is one instantaneous spectrum reading standing for the 9 µs window, not an integration; its channel-centre formula is reconstructed from the draft's band edges and counts rather than read off the draft's own numbering; and a string hash stands in for the draft's AES-128-CTR blockwise channel switching.
- NBA-sensing, the 4ab high-rate data modes (1.95–62.4 Mb/s) as data modes, streaming, and the UWB-only MMS parameter sets (SHR + one RIF, which are 4z SP3 in all but name) are out of scope. The one place a high rate appears is the Config 1 control plane: the SP0 packet's 1.95 Mbit/s PSDU is modelled as the duration of a control message and nothing else — no payload, and no rate a scenario can pick.
- A Wi-Fi radio receives a downlink AMP PPDU as an ordinary legacy-preamble reception: it defers for the L-SIG length and then uses AIFS, not EIFS. The coexistence numbers (lesson 3) rest on this — a real 802.11 receiver's behaviour on an OOK payload under a legacy preamble is not something the draft pins down.

## Architecture

```
engine  (pure TS, Web Worker) — deterministic discrete-event sim, ns clock,
        seeded per-STA RNG streams, emits timeline records + ViewState snapshots
player  — scrubs the recorded timeline; backward stepping is just a buffer read
scene   — Three.js house + node visuals driven by the reconstructed ViewState
editor  — 2D floor plan (SVG) → extruded 3D walls, wall-dedupe, openings
ui      — React panels: transport, timeline lanes, inspector, event log
```

The engine never runs in the UI thread and every run is reproducible from (scenario JSON, seed).
